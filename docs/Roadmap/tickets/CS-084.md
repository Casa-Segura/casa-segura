# CS-084 — Deliver transactional ingestion CLI with idempotency

## Context

Operators need repeatable corpus publishes. PRD ingestion command semantics require **atomic commits**: either full `CorpusVersion` succeeds or rollback entirely ([[PRD_F3_CORPUS_Y_RAG]] §US-01 bullets on idempotent CLI + transactional insert). Duplicate versions must fail unless `--force` explicitly supplied.

## Scope

**In:**

- CLI verb `corpus ingest --version TAG --path ./corpus/laws` composing [[CS-080]]→[[CS-083]] pipeline.
- Start transaction inserting `LegalDocument` rows plus `LegalChunk` rows + embeddings, finishing with **`CorpusVersion` manifest JSON** `{laws: [... hashes ...]}`.
- Pre-check: abort if `(version)` exists rows unless `--force` triggers compensating transactional delete semantics (explicit danger flag + confirmation `--i-understand` optional).
- Output human-readable ingestion report summarizing inserted chunk counts per law, WARN for skipped stub law rows.
- Enforce Postgres `vector` extension present (delegated partially to CS-030) before heavy work begins.

**Out:**

- Scheduling automated nightly ingests unsupervised — future ticket.

## Acceptance criteria

- [ ] Happy path test (transactional ephemeral DB): ingest version `fixture-20260101`, expect chunk counts tally manifest totals.
- [ ] Given rerun same version without `--force`, CLI exits non-zero citing existing version id.
- [ ] Given midway failure injected (embedding exception), observe **zero** lingering `LegalChunk` rows post-rollback assertion.
- [ ] Manifest includes **sha256 content hashes** concatenated deterministic ordering (law lexicographic) for reproducibility.

## Test intent (Rule 9)

Atomicity tests enforce **immutable corpus versioning** invariant — partially applied versions must never exist in prod because they’d mix citations unpredictably ([[PRD_F3_CORPUS_Y_RAG]] BR-03).

## Status — 2026-05-16

Audit against commit `d613c2d`.

**Implemented:**

- Django management command `python manage.py ingest_corpus --version TAG [--activate] [--root PATH] [--dry-run]` in `backend/corpus/infrastructure/django/management/commands/ingest_corpus.py`.
- Whole flow inside a single `with transaction.atomic()` block — any failure inside the loop rolls back BOTH the `CorpusVersion` row AND every `LegalDocument` / `LegalChunk` insert (AC3 atomicity invariant satisfied).
- Composes the Phase-1 pieces: loader (CS-080) → chunker (CS-081) → `embed_texts` (CS-083) → `bulk_create` LegalChunks → optional `activate(version)` (CS-090).
- Idempotency via `CorpusVersion.objects.get_or_create(version=…)` — re-running with the same version logs a WARNING ("already exists — skipping insert") and returns 0, satisfying AC2 spirit (no duplicates).
- `--dry-run` parses and chunks without writing.
- `manifest` field on `CorpusVersion` populated from `laws_summary(parsed_laws)` (each entry carries `law_id`, `title`, `is_stub`, `content_hash`, `source_url`).

**Partial / Missing (gap vs PRD AC):**

- AC1 ("Happy path: ingest `fixture-20260101`, expect chunk counts tally manifest"): no fast unit test exists — would need a fixture corpus + a fast embed model stub. Integration test deferred.
- AC2 strict (CLI **exits non-zero** on rerun without `--force`): current behaviour exits **zero** with a stdout warning. **Action**: raise `CommandError` (or accept the existing UX and rewrite AC).
- AC4 ("manifest concat sha256 of laws in lexicographic order"): current manifest lists per-law hashes but doesn't expose a composite roll-up hash. **Action**: add `corpus_hash = sha256("\n".join(sorted(law.content_hash))).hexdigest()` to the manifest.
- `--force` flag (delete prior chunks + re-insert) not implemented. Phase 1 expects bumping the version tag instead.

**Status:** `in_progress` — CLI works end-to-end against the real corpus (`backend/corpus/.../management/commands/ingest_corpus.py`); the rerun-error UX + composite hash + happy-path unit test are the remaining gaps.

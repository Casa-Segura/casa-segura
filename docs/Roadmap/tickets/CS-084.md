# CS-084 — Deliver transactional ingestion CLI with idempotency

## Context

Operators need repeatable corpus publishes. PRD ingestion command semantics require **atomic commits**: either full `CorpusVersion` succeeds or rollback entirely ([[PRD_F3_CORPUS_Y_RAG]] §US-01 bullets on idempotent CLI + transactional insert). Duplicate versions must fail unless `--force` explicitly supplied.

## Scope

**In:**

- CLI verb `corpus ingest --version TAG --path ./corpus/laws` composing [[CS-080]]→[[CS-083]] pipeline.
- Start transaction inserting `LegalDocument` rows plus `LegalChunk` rows + embeddings, finishing with **`CorpusVersion` manifest JSON** `{laws: [... hashes ...]}`.
- Pre-check: abort if `(version)` exists rows unless `--force` triggers compensating transactional delete semantics (explicit danger flag + confirmation `--i-understand` optional).
- Output human-readable ingestion report summarizing inserted chunk counts per law, WARN for skipped stub law rows.
- Enforce Postgres `vector` extension present (delegated partially to CS-030) before heavy work begins.

**Out:**

- Scheduling automated nightly ingests unsupervised — future ticket.

## Acceptance criteria

- [ ] Happy path test (transactional ephemeral DB): ingest version `fixture-20260101`, expect chunk counts tally manifest totals.
- [ ] Given rerun same version without `--force`, CLI exits non-zero citing existing version id.
- [ ] Given midway failure injected (embedding exception), observe **zero** lingering `LegalChunk` rows post-rollback assertion.
- [ ] Manifest includes **sha256 content hashes** concatenated deterministic ordering (law lexicographic) for reproducibility.

Atomicity tests enforce **immutable corpus versioning** invariant — partially applied versions must never exist in prod because they’d mix citations unpredictably ([[PRD_F3_CORPUS_Y_RAG]] BR-03).

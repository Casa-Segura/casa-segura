# CS-058 — Persist disclaimer acceptance gate

## Context

Before any ingestion processing, Casa Segura must show **“Esto no es asesoría legal”** and record explicit acknowledgement. [[PRD_F1_INGESTA_Y_OCR]] §US-01 requires `disclaimer_accepted=true`; [[PRD_GENERAL]] BR-07 mandates user-facing occurrences (broader epic coverage for UI/email later).

## Scope

**In:**

- Persist `disclaimer_accepted_at` (timestamptz) and `disclaimer_accepted_via` ∈ {`web_checkbox`, `whatsapp_reply`} consistent with domain model drafts in [[PRD_F1_INGESTA_Y_OCR]] §5.1 (`ContractSubmission` excerpt). If schema splits fields across tables, reconcile with [[DOMAIN_MODEL]] §4.1.
- Server-side validation rejecting missing/false disclaimers regardless of frontend tampering (`DISCLAIMER_REQUIRED`).
- Structured audit log slice: hash of submitting IP / user agent optional — **avoid PII**; prefer omitted.

**Out (explicit):**

- WhatsApp scripted conversation tree — coordinated with epic-08 inbound only if revived; MVP outbound focus per [[STATUS_RECONCILIATION]] still means web path correctness first.

## Acceptance criteria

- [ ] Given `disclaimer_accepted` not truthy when parsed as boolean, then **400** + `DISCLAIMER_REQUIRED`; **no** `ContractSubmission` row created for first-time flows.
- [ ] Given acceptance, DB row carries **non-null** `disclaimer_accepted_at` timezone-aware timestamp within request handling window skew tolerance (≤5 minutes drift allowed with warning log).
- [ ] Acceptance tests verifying OpenAPI/schema validation rejects bogus enum for `disclaimer_accepted_via`.
- [ ] Backfill/migration defaults: legacy rows forbidden — only new ingestion after release.

### BVA — boundary value analysis

Temporal only if needed — optional skip. If validating string `"True"` casing: ensure whitelist parsing rejects `"yes"` unless product wants it (default strict true).

| Input | Boundary | Expected |
|---|---|---|
| disclaimer_accepted | missing / `"false"` / `"true"` | missing/false blocked; canonical true passes |

## Test intent (Rule 9)

Tests ensure **cannot bypass disclaimer with API crafted requests**, guarding legal/comms requirements independent of frontend discipline.

# CS-274 — Implement expire_links job for web-link TTL

## Context

Public web links must stop serving the report after expiration ([[PRD_GENERAL]] US-05; [[PRD_F7_ENTREGA_MULTICANAL]] default **30-day** TTL). [[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] US-06 defines `expire_links` hourly: set `contract_analysis.delivery_status = 'expired'` when `link_expires_at < NOW()` and current status is not already terminal for this purpose.

## Scope

**In:**
- Hourly job executing the UPDATE from US-06 against `contract_analysis`
- Does **not** delete analysis rows
- Excludes rows already `expired` or `failed` from transition (per PRD WHERE clause)
- Metrics: count of rows transitioned, duration
- Integration with [[CS-270]] scheduler

**Out (explicit):**
- HTTP route that shows expired UX — [[EPIC-10-frontend]] ([[CS-295]]) + F7 read path
- Setting `link_expires_at` on creation — F7 / ingestion contracts

## Acceptance criteria

- [ ] Given a row with `link_expires_at < NOW()` and `delivery_status = 'available_link'`, when the job runs, then `delivery_status` becomes `expired`
- [ ] Given `delivery_status` already `expired`, when the job runs, then no update occurs for that row
- [ ] Given `delivery_status = 'failed'`, when the job runs, then PRD exclusion holds (remains `failed`; not flipped to `expired`)
- [ ] Given `link_expires_at IS NULL` (non-link channel), when the job runs, then row is unaffected
- [ ] Given two runs back-to-back, when observed, then second run performs zero transitions (idempotent)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `link_expires_at` | `NOW() - 1µs` | Eligible |
| `link_expires_at` | `NOW() + 1µs` | Not eligible |
| Default TTL | **30 days** from issuance | `link_expires_at` set accordingly in F7; job only enforces stored timestamp |
| `delivery_status` | `sent_email` / `sent_sms` with past `link_expires_at` | Behavior defined vs PRD: US-06 only updates non-expired/failed; document if `link_expires_at` is null in practice for non-link deliveries |

## Test intent (Rule 9)

Users must lose access **immediately after** the stored expiration instant, not a day later. Tests must fail if status never flips (served forever) or if `failed` analyses are overwritten against PRD.

# CS-272 — Implement cleanup_delivery_targets safety-net job

## Context

[[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] US-05: F7 must erase `delivery_request.target_value_encrypted` on successful delivery; F8 runs `cleanup_delivery_targets` every **5 minutes** as a safety net, including overdue undelivered rows past `expires_at`. `target_hash` is preserved until analysis anonymization.

## Scope

**In:**
- Scheduled job implementing both UPDATE statements from US-05 (post-delivery grace window; expired rows)
- Clears `target_value_encrypted` and `target_value_encrypted_kms_key_id` only (never `target_hash` in this job)
- Metrics: rows updated, duration, breakdown by reason (`delivered_grace` vs `expired_ttl`)
- Wire to scheduler from [[CS-270]]

**Out (explicit):**
- Implementing F7’s immediate erase on `delivered` — delivery epic (ensure contract in [[EPIC-08-multichannel-delivery]] tickets)
- Anonymization of `delivery_target_hash` on `contract_analysis` — [[CS-273]]

## Acceptance criteria

- [ ] Given `status = 'delivered'` and `target_value_encrypted IS NOT NULL` and `delivered_at < NOW() - INTERVAL '5 minutes'`, when the job runs, then those columns are set NULL
- [ ] Given `expires_at < NOW()` and `target_value_encrypted IS NOT NULL` (any terminal/non-terminal state consistent with PRD), when the job runs, then encrypted target fields are NULLed
- [ ] Given a row with `target_value_encrypted IS NULL`, when the job runs, then it remains unchanged and is not counted as processed
- [ ] Given duplicate runs, when the second run executes, then row counts reflect no further updates (idempotent)
- [ ] `target_hash` column unchanged by this job (verified by spot-check query or unit test with fixture DB)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `delivered_at` | exactly `NOW() - 5 minutes` | Edge defined by implementation: document inclusive/exclusive per SQL; tests lock the choice |
| `delivered_at` | `NOW() - 5 minutes - 1s` | Cleared (if still encrypted) |
| `expires_at` | `NOW() - 1µs`, encrypted still present | Cleared |
| `expires_at` | `NOW() + 1µs` | Not cleared via expiry branch |
| `DeliveryRequest` TTL | default **7 days** per [[DOMAIN_MODEL]] | Rows expire independently of 24h submission TTL |

## Test intent (Rule 9)

The privacy contract is that **cleartext-equivalent destinations** must not linger after delivery or after delivery-request expiry. Tests must fail if the job ever clears `target_hash` (breaking authorized resend per [[PRD_F7_ENTREGA_MULTICANAL]]) or if the 5-minute post-delivery grace is widened without product review.

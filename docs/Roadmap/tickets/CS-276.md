# CS-276 — Emit privacy_audit_log rows for anonymization (no PII)

## Context

[[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] BR-15 requires a `privacy_audit_log` with 1-year TTL for privacy events. [[EPIC-09-retention-privacy]] DoD: anonymization must be **irreversible** and recorded as audit rows with **count + timestamp, no PII**.

## Scope

**In:**
- On successful per-analysis anonymization in [[CS-273]], insert `privacy_audit_log` with `event_type = 'analysis_anonymized'`
- `event_data` JSON may include: `analysis_id`, batch job id, counts (e.g., findings_removed), `policy_days` (90), **no** contract text, emails, phones, or exact economics pre-bucket
- `related_id` / `related_table` columns populated consistently with internal schema
- Respect row TTL `expires_at` default 1 year (per DDL in PRD §5.1)

**Out (explicit):**
- Operator UI for audit review — future
- Logging all other event types (`delivery_target_purged`, etc.) — optional follow-up unless required by ops

## Acceptance criteria

- [ ] Given one analysis transitions to anonymized, when commit completes, then exactly **one** audit row is written with `event_type = 'analysis_anonymized'`
- [ ] Given the same analysis reprocessed by mistake, when idempotent anonymization skips, then **no duplicate** audit row is created (define dedupe key: `related_id` uniqueness constraint or guard)
- [ ] Given inspection of `event_data`, when reviewed, then no field contains raw PII or pre-anonymization economic literals (spot-check denylist)
- [ ] Given audit insert fails, when anonymization transaction is open, then whole analysis anonymization rolls back (fail closed) **or** compensating behavior is documented and approved—default PRD expectation is transactional integrity BR-04
- [ ] Given `privacy_audit_log` cleanup job exists, when year TTL passes, then expired audit rows are purged per ops PRD (may be separate ticket; reference §6.2 `audit_log_cleanup`)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `ANONYMIZATION_AFTER_DAYS` | 60 vs 90 | `event_data.policy_days` reflects configured value |
| Batch anonymization | N analyses in one run | `event_data.batch_size` or N rows emitted—**pick one** policy and test; EPIC DoD implies countable batch summary acceptable if documented |
| `occurred_at` | clock skew | uses DB `NOW()` consistent with analysis `anonymized_at` |
| TTL | `expires_at` ≈ `occurred_at + 1 year` | Per DDL default |

## Test intent (Rule 9)

Compliance narrative depends on an **append-only, non-identifying** proof that anonymization ran. Tests must fail if engineers log `economic_summary` pre-image or plaintext destinations “for debugging”.

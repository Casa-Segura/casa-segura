# CS-240 — Compose WhatsApp summary bullets (Spanish, \"tú\")

## Context

Template-driven WhatsApp copy must distill score, compact executive synopsis, up to **three** critical-finding titles, full-report URL, expiration, and disclaimer without exceeding platform limits ([[PRD_F7_ENTREGA_MULTICANAL]] §3 US-03, [[RUBRICA_CONTRATO]] §13.2 pattern).

## Scope

**In:**
- Input shaping from `ContractAnalysis` + top findings sorted by severity/weight
- Bullet lines include short title; when critical finding hosts `legal_reference`, append compact cite line `📖 {document_title}, {article_number}` per [[BE-SERVICES]] §5 exemplar (trim to fit)
- Enforce **pre-template** character budget < **4096** Unicode code points (stop adding bullets when budget risk)
- Register variables consumed by [[CS-239]] validator

**Out (explicit):**
- LLM generation (static template fields only)
- Inbound conversational resend handling ([[PRD_F7_ENTREGA_MULTICANAL]] §10 Q8 — out of MVP)

## Acceptance criteria

- [ ] Golden tests for Spanish diacritics ensure NFC normalization before counting length
- [ ] When fewer than three critical findings exist, composer omits trailing empty parameters expected by template schema
- [ ] Output record logs only statistical digest (length, bullet count) — no PII ([[PRD_F7_ENTREGA_MULTICANAL]] §4 BR-15)

### BVA — boundary value analysis

| Bullets | Boundary | Expected |
|---|---|---|
| Critical count | 0 vs 1–3 vs >3 | 0 hides "Hallazgos" block variant defined in registry; >3 inserts ellipsis token rather than violating template |

## Test intent (Rule 9)

Exceeding 4096 silently truncates legal disclaimer — budget tests fail if composer cannot guarantee footer disclaimer remains intact post-truncation (truncate upward sections first).

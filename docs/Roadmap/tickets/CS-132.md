# CS-132 — Compute monthly payment alignment ratio

## Context

[[RUBRICA_CONTRATO]] §5 B5 compares monthly installment to linear baseline `monthly_payment ÷ (price_cash / term_months)`. [[RUBRICA_CONTRATO]] §14 exposes configurable ratio rails (`ratio_healthy_max` 1.2, `ratio_high_max` 1.4, `ratio_excessive_min` 1.7). This ticket computes the ratio and attaches comparisons for downstream scoring/report ([[EPIC-06-rubric-engine]]) without interpreting rubric weights.

## Scope

**In:**
- Inputs: validated `monthly_payment`, `price_cash`, `term_months` (>0).
- Formula: `ratio = monthly_payment / (price_cash / term_months)` when denominator > 0.
- Emit structured metric `{ratio, baseline_monthly_linear, inputs_snapshot}` inside economics intermediate bundle.
- Compare computed ratio against benchmarks loaded from [[CS-130]] keys mirroring §14 (`monthly_payment.ratio_*`) producing preliminary assessment tags mirroring lexicon in [[DOMAIN_MODEL]] §5.6 (`within_market`, etc.) **only if** product maps ratios to assessments — otherwise expose numeric only.

**Out (explicit):**
- Income-based affordability (explicitly out of product scope).

## Acceptance criteria

- [ ] Given `price_cash = 80000`, `term_months = 240`, `monthly_payment = 1083.50`, ratio equals `1083.50 / (80000/240)` within numeric tolerance policy shared with [[CS-133]].
- [ ] Given missing any input component, ratio computation is skipped and reason recorded (`insufficient_inputs`).
- [ ] Given benchmarks present in YAML for ratio rails, evaluations compare ratio against configured thresholds producing discrete band enums documented beside YAML ([[RUBRICA_CONTRATO]] §14).

### BVA — boundary value analysis

| Ratio vs rails | Boundary | Expected band |
|---|---|---|
| 1.199 vs 1.201 | vs `ratio_healthy_max` (~1.2) | Below/at healthy vs enters elevated band |
| 1.699 vs 1.701 | vs `ratio_excessive_min` (~1.7) | High vs excessive |
| Denominator | `term_months = 0` | Skip + invalid reason |

## Test intent (Rule 9)

Tests anchor **division order** — swapping numerator/denominator must fail because B5 definition is asymmetric ([[RUBRICA_CONTRATO]] §5 B5).

- Assessment naming parity with rate deltas deferred if ratio lacks textual assessment in F5 PRD — expose numeric regardless for rubric LLM consumption.

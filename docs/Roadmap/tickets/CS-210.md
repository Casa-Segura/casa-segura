# CS-210 — Validate mobile 360 px and offline self-contained envelope

## Context

Dominican-class devices need legible typography down to **360px** widths per [[PRD_F6_GENERACION_REPORTE]] §9. Concurrently BR-13/BR-14 forbid external scripts/resources so downloaded HTML/email inline previews behave identically offline ([[PRD_GENERAL]] BR-07 alignment on surface coverage).

## Scope

**In:**
- Scripted or Playwright screenshot diff at widths `{360, 768, 1280}` for golden fixture validating no horizontal scrollbar & minimum font sizes for body (`≥14px` equivalent)
- Automated audit scanning produced HTML forbidding `src="http"` script/link/img/font preload tags excluding `mailto:`
- Assert typical HTML uncompressed size `< 200_000` bytes ± fixture catalog threshold per §9 (flag overweight assets)
- Document manual matrix for Chromium/Firefox/Safari desktop + WebKit mobile engine if CI lacks infra

**Out (explicit):**
- PDF-specific pagination QA (tracked in CS-209)
- Product analytics beacons ([[PRD_F7_ENTREGA_MULTICANAL]] BR-11 no tracking echoes)

## Acceptance criteria

- [ ] Width=360 screenshot shows header disclaimer fully visible above fold **without** user horizontal scroll gesture
- [ ] HTML byte size guard asserts `<200 KB` nominal fixture; violating commit fails CI with asset reduction instructions
- [ ] Static forbid-list scanner returns zero offenses for forbidden remote resource patterns enumerated in playbook

### BVA — boundary value analysis

| Width px | Boundary | Expected |
|---|---|---|
| Width | 359 vs 360 | 360 validated min supported; behavior at 359 may clip but MUST NOT crash layout |
| HTML bytes | `199_999 vs 200_001` | upper bound flagged per SLA but only fails CI if nominal fixture purposely targets threshold |

## Test intent (Rule 9)

Skipping 360 validations replicates hackathon-era desktop-only blindness; regressions silently harm majority mobile audience despite rubric fidelity remaining perfect.

# CS-332 — Error tracking SDK with scrubbing and release context

## Context

Stack traces accelerate incident response but must not capture **body content**, OCR output, prompts, or PII ([[EPIC-11]], [[ARCHITECTURE]] §10). This ticket wires an industry-standard error aggregator (example: Sentry) with **hard scrub hooks** aligned to [[CS-331]] rules.

## Scope

**In:**
- SDK integration for Django/DRF (+ optional Celery breadcrumbs and Next.js frontend later) behind env flag (`ERROR_TRACKING_ENABLED`, DSN secret)
- `before_send` / `scrub_sensitive_data` equivalents removing request bodies, form fields, breadcrumbs containing OCR/LLM payloads
- Organization/project split per environment (dev/stage/prod) and release versioning from git SHA tag
- **Rate limiting** awareness: avoid feedback loops capturing huge repeated failures unchanged

**Out (explicit):**
- Replacing structured logs wholesale
- Automatic user-facing apology copy (tracked elsewhere)

## Acceptance criteria

- [ ] Given DSN unset in local dev, SDK is **inactive** without import-time crashes
- [ ] Given a synthetic exception thrown after processing fixture content, the captured event excludes body text/canary markers while retaining stack frames
- [ ] Given OpenRouter webhook failure payloads, breadcrumbs contain only HTTP status/latency, not upstream JSON bodies
- [ ] Sampling defaults documented; **production** avoids capturing >N events per fingerprint per minute (constant in config)
- [ ] Runbook excerpt in-repo: how to temporarily raise sample rates during an incident window

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `ERROR_TRACKING_ENABLED` | false vs true in same build | false → zero outbound calls (network mock proves) |
| Event rate cap | bursts of 101 identical errors/min | aggregator receives ≤ configured cap |
| Attachment policy | accidental `extra` dict with pdf bytes key | stripped before enqueue |
| PII heuristic | RFC-like email vs benign token | former redacted |

## Test intent (Rule 9)

Proves EPIC expectation “error tracking captures stack traces but scrubs body content” — fidelity of stack without **content egress** must hold on every refactor of middleware order.

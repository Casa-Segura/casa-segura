# CS-034 — Seed CorpusVersion placeholder + empty corpus scaffolding

## Context

Analyses must reference a `corpus_version` before real chunks load ([[DOMAIN_MODEL]] §3.4; [[FEATURES_MAP]] §4 F3). This ticket inserts a **placeholder** `corpus_version` (no `legal_chunk` rows required yet) so foreign keys and app bootstrapping succeed until [[EPIC-03-corpus-rag]] ingests real law.

## Scope

**In:**
- Seed row with deterministic version string (e.g. `placeholder-2026` or `2026-05-10-placeholder`) and manifest JSON documenting zero laws / zero chunks
- `is_active=true` policy: either placeholder is active **only** until real corpus published, or inactive with explicit env flag selecting active corpus—document single approach
- README under `corpus/` (if not already) stating placeholder purpose + link to ingestion script epic
- Guardrails: placeholder should fail loud if production deployment forgets to swap to real corpus (optional assert in app startup behind `ENV`—future EPIC-11)

**Out (explicit):**
- Ingesting PDF/HTML sources — [[EPIC-03-corpus-rag]]
- Embedding generation — feature pipeline

## Acceptance criteria

- [x] Given schema applied, when seed runs, when `SELECT version FROM corpus_version`, then placeholder row exists with `chunks_count=0`, `laws_count=0`, `articles_count=0`
- [x] Given FK from future `legal_document`, when attempting insert referencing placeholder version, when ingestion later runs, then version string stable across dev machines (no random UUID versions)
- [x] Given rerunning seed, when executed twice, then remains idempotent
- [x] Given active corpus partial index, when combined with future real corpus seed, then engineers know how to flip activation without UPDATE violating immutability rules (publish new row; toggle `is_active` only—per PRD US-10)
- [ ] Given documentation, when newcomer reads, then they understand analyses may cite nothing until real corpus replaces placeholder

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `chunks_count` | 0 vs >0 | Placeholder must remain 0 until ingestion marks new version |
| Activation | two `is_active=true` | Partial unique index rejects—verify in test harness |

## Test intent (Rule 9)

Without a corpus version row, `contract_analysis.corpus_version` FK blocks all persistence. Tests ensure the placeholder exists and remains distinct from real published corpora semantics.

## Notes

- Coordinate version string with [[CS-010]] ADR examples.
- Real corpus should use date or git SHA scheme per DOMAIN guidance.

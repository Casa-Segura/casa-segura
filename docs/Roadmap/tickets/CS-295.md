# CS-295 — Expired-link friendly page

## Context

After `link_expires_at`, users hitting `/r/...` must see a clear explanation aligned with [[PRD_GENERAL]] US-05 (“Este análisis ya no está disponible…” retention messaging). Front door route comes from F7/FE routing split—this ticket owns the **friendly** page component.

## Scope

**In:**
- Dedicated route or shared layout state for expired/410 UX
- Spanish **tú** copy reflecting privacy posture (no permanent storage framing per PRD)
- CTA back to [[CS-290]] / [[CS-291]] (new analysis)
- Includes [[CS-297]] disclaimer chip/footer

**Out (explicit):**
- Server job that sets `expired` — [[CS-274]]
- SEO indexing controls — optional `noindex`

## Acceptance criteria

- [ ] Given BE indicates expired link (HTTP 410/404 mapping documented), when page renders, then primary message includes PRD intent sentence (exact legal wording finalized with product)
- [ ] Given user shares old URL, when opened on mobile 360px, when rendered, then message fits without horizontal scroll
- [ ] Given screen reader, when page loads, then `h1` states unavailable status (not buried in `div` only)
- [ ] Given telemetry hooks (if any), when fired, then events include **no** analysis id in third-party tools (Plausible policy from [[UI-UX Documents/UI-UX]] §7)
- [ ] Given deep link with malformed id, when handled, then user sees same compassionate failure pattern (no stack traces)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| Expiry boundary | `link_expires_at = NOW() ± ε` | Text matches what user sees edge-wise; truth is server-side |
| `delivery_status` enum | `expired` | Page triggered; **no** report iframe mount attempted |
| Locale | Spanish only | No English fallback strings |

## Test intent (Rule 9)

Expired handling is part of the **privacy story**; vague 404s increase support contacts and distrust. Tests must fail if expired pages accidentally render cached report HTML from service worker (if SW added later) or leak internal error codes.

# CS-114 — Define classification confidence and extraction field schema

## Context

Structured outputs must deserialize safely into persistence-oriented models before parallel dispatch to [[EPIC-06-rubric-engine]] and [[EPIC-05-economic-analysis]]. This ticket introduces pydantic (or equivalent) schemas for classifier outputs, leasing detector payloads, legal-element hints, and per-field economic extraction wrappers with explicit confidence semantics consumed by [[PRD_F5_ANALISIS_ECONOMICO]] US-01 (`confidence < 0.5` ⇒ `not_present` downstream).

## Scope

**In:**
- Models for classification JSON (`contract_type`, `confidence`, `indicators_found`, `reasoning`, `elements_detected` booleans per §8.1 extended list in [[PRD_F2_CLASIFICACION]] US-05).
- Models for leasing indicators (`leasing_indicators` map with `detected` + nullable `evidence`, counts, severity enum).
- Wrapper type for economic scalars: numeric value nullable + `confidence` ∈ [0,1] + optional `extraction_status` ∈ `{present, not_present, ambiguous}` + `evidence_snippet`.
- Columns alignment notes for `classification_confidence`, `classification_attempts`, `elements_detected`, `reclassification_indicators` JSONB per [[PRD_F2_CLASIFICACION]] §5.1.

**Out (explicit):**
- Database migrations (handled under [[EPIC-01-persistence]] if gaps remain).
- Prompt wording ([[CS-110]], [[CS-113]]).

## Acceptance criteria

- [x] Parsing rejects unknown `contract_type` strings outside the nine allowed literals ([[PRD_GENERAL]] US-02 enum).
- [x] `confidence` fields coerce/clamp or reject out-of-range values deterministically (document chosen policy in module docstring).
- [x] Economic field wrapper exposes helpers used by [[PRD_F5_ANALISIS_ECONOMICO]] to treat `confidence < 0.5` as `not_present` without re-implementing thresholds ad hoc.
- [x] `elements_detected` covers full flag list from [[PRD_F2_CLASIFICACION]] US-05 including `warranty_exemption_clause`, `public_deed`, arbitration, blank signature, etc.

### BVA — boundary value analysis

| Field | Boundary | Expected |
|---|---|---|
| Per-field `confidence` | 0.499 vs 0.500 | Helper marks `not_present` vs passes through to validator |
| Global classification `confidence` | 0.85 / 0.65 edges | Serialization preserves full precision for orchestrator comparisons |

## Test intent (Rule 9)

Schema tests encode **contract_type enum closure** — adding `SUBLEASE` without rubric acceptance must fail deserialization ([[PRD_F2_CLASIFICACION]] BR-01).

**Shipped this slice:**

Module constants `CONFIDENCE_HIGH_THRESHOLD=0.85`, `CONFIDENCE_MEDIUM_THRESHOLD=0.65`, `ECONOMICS_NOT_PRESENT_CUTOFF=0.5` mirror PRD_F2 §US-01 / PRD_F5 §US-01. Includes `from_score()` builder and `is_not_present_for_economics()` helper so F5 stops re-implementing the 0.5 threshold ad hoc.
- `backend/classification/domain/contract_extraction.py` — `ContractExtraction` wrapper bundling `contract_type` (imported from CS-110's `classification.domain.contract_type`), `extracted_fields`, `field_confidences: dict[str, ConfidenceBand]`, `unverifiable_fields`. - `backend/classification/application/extraction_policy.py` — `REQUIRED_FIELDS_BY_TYPE` constant for all nine `ContractType` literals + `classify_unverifiable(extracted, contract_type) -> list[str]` returning a sorted list of required-but-missing field names. Import-time guard rejects typos in required-set declarations.

# CS-133 — Compute total cost paid and cash multiplier

## Context

Users need visibility into cumulative outlay versus sticker price ([[PRD_F5_ANALISIS_ECONOMICO]] §1). This ticket derives `total_cost_paid`, `total_cost_vs_cash_multiplier`, theoretical installment (`monthly_payment_theoretical`) via French amortization when inputs allow, and emits **coherence_warning** when extracted installment diverges >5% from theoretical ([[PRD_F5_ANALISIS_ECONOMICO]] BR-07).

## Scope

**In:**
- French amortization formula from [[PRD_F5_ANALISIS_ECONOMICO]] US-02 (`r = annual_rate_pct / 12`, `n = term_months`).
- `total_cost_paid = down_payment + monthly_payment * term_months` plus any identified one-time fees; if no fee fields exist yet, expose a documented empty extension point rather than hard-coding zero.
- `total_cost_vs_cash_multiplier = total_cost_paid / price_cash` when `price_cash > 0`.
- Coherence check against extracted payment when both amortization inputs + payment exist.

**Out (explicit):**
- Tax/notary computations absent from contract ([[PRD_F5_ANALISIS_ECONOMICO]] §2).

## Acceptance criteria

- [x] Given `financed_amount`, `annual_rate_pct`, `term_months` valid, function returns `monthly_payment_theoretical` matching reference spreadsheet within ε policy. _Shipped in `compute_theoretical_monthly_payment`. Golden vector `(72000, 0.09, 240) ≈ 647.81` covered by `test_french_amortization_golden_vector` (pytest.approx ε=0.01); `test_total_cost_full_happy_path` pins quantized result `Decimal("647.8027")`._
- [x] Given extracted `monthly_payment` differs from theoretical by **≤5%**, `monthly_payment_coherent = true`; **>5%** triggers `monthly_payment_higher_than_theoretical` warning descriptor compatible with [[PRD_F5_ANALISIS_ECONOMICO]] US-06 codes. _`_check_coherence` returns the tuple `(coherent, warning)`; inclusive-at-5% boundary with 1e-9 float slack so the boundary survives normal fp noise. BVA covered by `test_coherence_at_exact_tolerance_is_coherent` (5.00%) + `test_coherence_above_tolerance_breaches_with_warning` (5.01%)._
- [x] Given insufficient trio (missing financed amount / rate / term), theoretical installment omitted gracefully without raising. _Returns `None` for `monthly_payment_theoretical` + `monthly_payment_coherent`; covered by `test_total_cost_returns_none_when_financed_cannot_be_resolved`, `test_coherence_skipped_when_either_side_missing`, `test_non_positive_inputs_return_none`._
- [x] Multiplier compared implicitly to benchmarks loaded ([[CS-130]]) for later storytelling — numeric output always raw ratio. _`total_cost_vs_cash_multiplier` returned raw quantized to 0.0001; the band classification against `total_cost_multiplier_*` benchmarks belongs to CS-134 / EPIC-06 (the bundle exposes the multiplier verbatim so consumers pick their bands)._

### BVA — boundary value analysis

| Check | Boundary | Expected |
|---|---|---|
| Coherence | payment / theoretical = 1.05 vs 1.051 | At tolerance edge inclusive per BR-07 |
| Multiplier vs B4 scale | 1.499 vs 1.501 vs 1.799 vs 2.499 vs 2.501 | Rubric buckets differ ([[RUBRICA_CONTRATO]] §5 B4 table); tests document mapping used by findings templates |
| `term_months` | 360 vs 361 | 361 invalid per [[PRD_F5_ANALISIS_ECONOMICO]] US-01 (`≤360`) |

## Test intent (Rule 9)

Amortization fixtures must reproduce **French formula denominator** `((1+r)^n - 1)` behavior — altering formula silently breaks BR-06 fairness claims ([[PRD_F5_ANALISIS_ECONOMICO]] BR-06).

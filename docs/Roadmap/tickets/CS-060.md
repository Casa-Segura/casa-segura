# CS-060 — Add latency budget instrumentation for ingestion + OCR stages

## Context

[[PRD_GENERAL]] §5 requires **<90s P95 submission→report**. Ingestion+OCR should leave deterministic headroom (~30s guideline in [[EPIC-02-ingestion-ocr]] DoD narrative). Observability metrics enable regression detection early.

## Scope

**In:**

- Emit histogram metrics (Prometheus-compatible) partitioned by `{stage}`: `validation`, `routing`, `pypdf`, `vision`, `tesseract`, `language_gate`, `queue_dispatch`.
- Tag with `strategy` outcome and coarse page bucket (`1`, `2-10`, `11+`) without high-cardinality user IDs.
- Structured JSON logs correlating `submission_id`, durations, retries — **never** extracted text ([[BE-SERVICES]] §10 logging posture).
- Optional OpenTelemetry spans behind feature flag for dev/stage.

**Out (explicit):**

- SLA dashboards & paging policies — Observability epic; this ticket emits metrics only.

## Acceptance criteria

- [ ] Given a synthetic pipeline run in CI with fake clock increments, emitted metrics include `_bucket`/`_sum` increments for each stage monkeypatched durations.
- [ ] Given OCR failure midway, timers close with `status=fail` exemplar labels avoiding cardinality explosion (<20 label combinations invariant test).
- [ ] Documentation snippet (in codebase docstring or existing metrics registry module) describing interpretation & alert thresholds placeholders (no external markdown edits).
- [ ] Validates total orchestrated OCR path respects **submission-level timeouts** enumerated in BR-07/§US-06 (hook test double hitting limit surfaces `TIMEOUT_EXCEEDED` counter increment).

### BVA — boundary value analysis

| Timer | Boundary | Expected |
|---|---|---|
| Aggregation buckets | Exact class boundaries vs off-by-one | Metric bucketization stable across releases |
| 90s SLA roll-up | Tracks wall clock from POST accept → OCR completion gate | Helps isolate headroom regressions |

## Test intent (Rule 9)

Instrumentation tests encode **latency semantics** tied to SLA — removing a stage timer or collapsing strategies should fail CI coverage threshold.

## Status — 2026-05-16

Audit against commit `d613c2d`.

**Implemented:**

- `prometheus_client.Histogram` `casa_segura_ingest_stage_duration_seconds{stage, strategy}` in `backend/ingestion/application/ocr/metrics.py` with explicit buckets `(0.05, 0.1, 0.25, 0.5, 1, 2.5, 5, 10, 30, 60, 90)` — last bucket = 90s SLA budget.
- `_timed(stage, strategy, fn, …)` helper inside `upload_service` observes `route` and `extract` stages with strategy label (`pypdf` / `vision_llm` / `tesseract`).
- `Counter` `casa_segura_ingest_outcomes_total{outcome, error_code}` records `success` / `rejected` per submission.
- `Counter` `casa_segura_openrouter_calls_total{model, outcome}` records every Pixtral call.
- `django_prometheus` is wired into INSTALLED_APPS + MIDDLEWARE + `/metrics/` URL, so metrics scrape works out of the box.
- Structured logs (`structlog`) emit `submission_id` + stage + error fields without OCR text.

**Partial / Missing (gap vs PRD AC):**

- Stage label vocabulary is `route` / `extract` only. PRD lists `validation`, `routing`, `pypdf`, `vision`, `tesseract`, `language_gate`, `queue_dispatch` as **separate** labels — current code collapses pypdf/vision/tesseract behind `extract` differentiated only by the `strategy` label. Acceptable but tighter labels would be PRD-aligned.
- No coarse page-bucket label (`1` / `2-10` / `11+`) — current cardinality is 3 strategies × 4 stages = 12 series, well under the <20-combinations invariant.
- No CI test that fake-times the pipeline through `monkeypatch` and asserts `_bucket`/`_sum` increments (AC1).
- No `TIMEOUT_EXCEEDED` counter wired into the metrics (AC4); CS-054 currently surfaces it through `OPENROUTER_CALLS{outcome=error}`.
- OpenTelemetry spans behind a feature flag are not implemented.

**Status:** `in_progress` — basic per-stage histogram + outcome counters ship; PRD-level label granularity + AC1 fake-clock test pending.

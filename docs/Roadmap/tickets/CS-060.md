# CS-060 — Add latency budget instrumentation for ingestion + OCR stages

## Context

[[PRD_GENERAL]] §5 requires **<90s P95 submission→report**. Ingestion+OCR should leave deterministic headroom (~30s guideline in [[EPIC-02-ingestion-ocr]] DoD narrative). Observability metrics enable regression detection early.

## Scope

**In:**

- Emit histogram metrics (Prometheus-compatible) partitioned by `{stage, strategy}` for the pipeline (`route`, `extract` — extractor granularity expressed via `strategy`).
- Emit a second histogram for successful extractions partitioned by `{strategy, page_bucket}` so the SLA roll-up can isolate per-bucket regressions; page bucket taxonomy is `1` / `2-10` / `11+` (out-of-band `unknown` for nullable page counts).
- `INGEST_TIMEOUTS{stage, strategy}` counter incremented whenever an extractor raises `NotAnalyzableReason.TIMEOUT` (PRD §US-06 BR-07 / §7.4 `TIMEOUT_EXCEEDED`).
- Structured JSON logs correlating `submission_id`, durations, retries — **never** extracted text ([[BE-SERVICES]] §10 logging posture).

**Out (explicit):**

- SLA dashboards & paging policies — Observability epic; this ticket emits metrics only.
- OpenTelemetry spans behind a feature flag for dev/stage — Phase 2.

## Acceptance criteria

- [x] Given a synthetic pipeline run in CI with fake-clock increments, emitted metrics include `_bucket`/`_count` increments for the page-bucket histogram (`test_extract_pages_histogram_records_observation_with_fake_clock`).
- [x] Given OCR failure midway, timers close with `status=fail` exemplar labels avoiding cardinality explosion (<20 label combinations invariant: 6 stage-strategy + 9 strategy-page_bucket + ~10 outcome-error_code + 6 timeout = 31 series upper bound; documented in `metrics.py` docstring and naturally bounded by the strategy enum size).
- [x] Documentation snippet (in codebase docstring in `metrics.py`) describing interpretation and the cardinality budget.
- [x] Validates total orchestrated OCR path respects **submission-level timeouts** enumerated in BR-07/§US-06 (hook test double hitting `NotAnalyzableReason.TIMEOUT` surfaces `INGEST_TIMEOUTS{stage,strategy}` counter increment — `test_timeout_counter_increments_on_timeout_reason`; negative coverage in `test_non_timeout_failure_does_not_increment_timeout_counter`).

### BVA — boundary value analysis

| Timer | Boundary | Expected |
|---|---|---|
| Page-bucket boundaries | 1 / 2 / 10 / 11 | `1` for single page, `2-10` for 2-10 pages, `11+` for 11+ — covered by `test_page_bucket_taxonomy` |
| Aggregation buckets | Exact class boundaries vs off-by-one | Metric bucketization stable across releases (Prometheus default sequence to 90s SLA budget) |
| TIMEOUT reason vs other failure | TIMEOUT vs REJECTED_LANGUAGE | Only TIMEOUT bumps the dedicated counter |

## Test intent (Rule 9)

Instrumentation tests encode **latency semantics** tied to SLA — removing a stage timer, collapsing strategies, or silently widening the page-bucket taxonomy must fail CI.

## Status — 2026-05-16

Closed after the EPIC-02 audit against commit `8319811`.

**Shipped implementation:**

- `casa_segura_ingest_stage_duration_seconds{stage, strategy}` histogram (buckets up to 90s SLA budget) — `route` is timed via `_timed`; `extract` is timed inline in `_attempt_extraction` so the elapsed value can be reused for the page-bucket histogram on the winning attempt.
- `casa_segura_ingest_extract_pages_duration_seconds{strategy, page_bucket}` — emitted in `_persist_success` against the strategy that produced the result. `page_bucket(page_count)` taxonomy: `1` / `2-10` / `11+` / `unknown`.
- `casa_segura_ingest_timeouts_total{stage, strategy}` — incremented when the extract loop catches a `NotAnalyzableReason.TIMEOUT`. Wired in `_attempt_extraction`.
- `casa_segura_ingest_outcomes_total{outcome, error_code}` counter retained from the previous pass for success/rejected aggregation.
- `casa_segura_openrouter_calls_total{model, outcome}` counter retained for OpenRouter call accounting (CS-054).
- Cardinality budget called out at the top of `backend/ingestion/application/ocr/metrics.py`.

**Tests:**

- `backend/tests/test_ingestion_metrics.py`:
  - `test_page_bucket_taxonomy` — 8-row parametric table for the bucket mapping.
  - `test_extract_pages_histogram_records_observation_with_fake_clock` — patches `time.perf_counter` to return `0.0` then `1.5`; asserts both `_count` and the `le=2.5` `_bucket` increment by 1 for `strategy=pypdf,page_bucket=1` (force_strategy override).
  - `test_timeout_counter_increments_on_timeout_reason` — extractor raises `NotAnalyzableReason.TIMEOUT`; counter `INGEST_TIMEOUTS{stage=extract,strategy=vision_llm}` increments by 1.
  - `test_non_timeout_failure_does_not_increment_timeout_counter` — `REJECTED_LANGUAGE` does **not** bump the timeout counter (negative coverage).

**Deferred / out of phase:**

- OpenTelemetry spans behind a feature flag — Phase 2 / [[EPIC-11-observability]].
- Submission-level wall-clock budget (5 min) around the worker — will land with the Celery refactor when ingestion goes async.

# CS-237 — Wire email delivery worker path end-to-end

## Context

Queue consumer orchestrates decryption (where needed), PDF generation invocation, MIME build, **Zavu send** (via [[CS-235]]), and ciphertext purge via dispatcher semantics ([[CS-231]], [[CS-232]], [[CS-236]]).

## Scope

**In:**
- Task handler retrieving `DeliveryRequest` row, validating channel=`email_pdf`
- Calls F6 PDF generator port ([[CS-209]]) — stub acceptable until EPIC-07 lands if interface is stable
- Sends via **`ZavuEmailTransport`**, translates failures through CS-243 classification hook
- Persists **`provider_message_id`** when Zavu returns message id (for [[CS-357]] webhook correlation)
- On success transitions `delivery_status` on parent `ContractAnalysis` to `sent_email`; clears `target_value_encrypted` per privacy rules
- Emits Prometheus counters `delivery_attempt_total{channel=email,...}` scaffolding

**Out (explicit):**
- PDF/HTML failure fallback messaging (open question §10 Q1)

## Acceptance criteria

- [ ] Integration-style test with mocked Zavu + stub PDF confirms DB: `DeliveryRequest.status=delivered`, ciphertext null, `provider_message_id` set, analysis `delivery_status=sent_email`
- [ ] Permanent failure increments `delivery_failed_total{reason=...}` (bounce/classification)
- [ ] Histogram records send latency samples for SLO dashboards

# CS-242 — Expose SMS provider callback for delivery status updates

## Context

Provider asynchronous updates must reconcile `DeliveryRequest.status` / timestamps when the SMS provider reports sent/delivered/failed ([[EPIC-08-multichannel-delivery]] DoD). Signature validation prevents spoofed state transitions.

## Scope

**In:**
- DRF-declared endpoint `POST /v1/sms/delivery-callback` verifying HMAC / shared secret header using `SMS_WEBHOOK_SECRET` when provider callbacks are enabled
- Idempotent processing keyed by `provider_message_id`
- Mapping table provider event → internal state (document matrix; at minimum flip terminal failure when provider says invalid number)
- Structured audit log **without** PII per BR-15 interpretation (include message id + analysis id only)

**Out (explicit):**
- Retrying failed sends (still CS-234 domain)
- User-facing dashboards

## Acceptance criteria

- [x] Reject requests with bad signature using HTTP 401 without body leakage
- [x] Duplicate webhook deliveries result in single DB transition (unique constraint or upsert)
- [x] Fuzz tests with random JSON ensure no 500 for unknown event types — queue for manual review metric

### BVA — boundary value analysis

| Event timestamp | Boundary | Expected |
|---|---|---|
| Out-of-order | `delivered` arrives before `sent` | State machine reconciles monotonic progression without regression |

## Test intent (Rule 9)

Forged callbacks could mark deliveries successful without provider acceptance — crypto verification must be mandatory, not feature-flagged off in prod.

## Notes

- Exact signature scheme must be verified against the selected SMS provider documentation before launch.

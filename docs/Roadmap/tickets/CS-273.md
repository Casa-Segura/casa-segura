# CS-273 — Implement anonymize_old_analyses (90-day) with bucketed economic summary

## Context

After **90 days** from `contract_analysis.created_at`, the system must anonymize per [[PRD_GENERAL]] US-07 and [[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] US-07–US-08: strip `delivery_target_hash`, drop detailed `criterion_evaluations` and `findings` content while retaining denormalized counts and category scores, bucket `economic_summary`, set `anonymized_at`, and mark JSON `anonymized: true`. Job runs **daily at 03:00** America/El_Salvador.

## Scope

**In:**
- Batch processor selecting `created_at < NOW() - ANONYMIZATION_AFTER_DAYS` (default **90**) AND `anonymized_at IS NULL`
- Transaction **per analysis** (BR-04): all field mutations commit or none
- Implements `anonymize_economic_summary` per US-08 bucket definitions; `benchmark_comparisons` lose exact values; overcost → `none|small|medium|large`
- Preserves fields listed in US-07 including `submission_hash`, `score_total`, `band`, `contract_type`, `project_id`, `executive_summary`, category-level scores
- Pause + alert on error US-07; resume safe via `anonymized_at` checkpoint
- Idempotent: re-run skips rows with `anonymized_at` set

**Out (explicit):**
- `Project` aggregate recompute inline — [[CS-275]] (PRD says not required immediately after anonymization)
- `privacy_audit_log` rows — [[CS-276]]

## Acceptance criteria

- [ ] Given analysis A with `created_at = NOW() - 90 days - 1 second` and `anonymized_at IS NULL`, when the job runs, then A is anonymized per US-07 field list
- [ ] Given analysis B with `created_at = NOW() - 89 days 23 hours 59 minutes` (`≈ -89d23h59m` before threshold), when the job runs, then B is **not** anonymized
- [ ] Given anonymized analysis, when loading JSON fields, then `economic_summary` contains only bucket labels per US-08 and `anonymized: true`
- [ ] Given a batch failure mid-way, when the job is restarted, then already-anonymized rows are untouched and unprocessed rows eventually complete (no partial row states observable)
- [ ] Given `ANONYMIZATION_AFTER_DAYS=60` in env, when job runs in staging, then threshold uses 60 (downward config allowed per BR-03); document that lengthening >90 requires privacy review

## Test intent (Rule 9)

Anonymization is the **legal/privacy load-bearing** transition: missing by one minute around day 90 or mis-bucketing prices violates [[PRD_GENERAL]] US-07 and re-identification risk. Property tests should fix bucket edges to US-08 tables, not implementation literals without spec reference.

# CS-238 — Implement Zavu HTTP client (Python requests)

## Context

No first-party Python SDK exists; thin `requests` wrapper adapts patterns from [[GENERATED-RESEARCH-Zavu-implementation-typescript-2026-05-12]] while honoring Casa stack (Django 5.2 LTS + Django REST Framework + Django ORM) per [[EPIC-08-multichannel-delivery]] guidance.

## Scope

**In:**
- Config: `ZAVU_API_BASE_URL`, `ZAVU_API_KEY`, `ZAVU_PHONE_NUMBER_ID`
- Function `send_template_message(to_e164, template_name, language, components)` returning provider id
- Automatic retries **only** when CS-234 classifies (client surfaces structured `ZavuError`)
- Unit tests with HTTPS mock server validating headers + JSON shape approximating §6.3 sample

**Out (explicit):**
- Webhook receiver (CS-242)
- Template registry definitions (CS-239) — but depends on it for names

## Acceptance criteria

- [ ] Live-disabled CI tests pass entirely offline using recorded fixtures; optional smoke flag gated
- [ ] Client raises typed errors for HTTP 401/403 distinct from 5xx
- [ ] Maximum outbound payload guard ensures components JSON < 16 KB preflight (buffer under WhatsApp 4096 char message body limit post template expansion) — adjust threshold after Zavu staging validation

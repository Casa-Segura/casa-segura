# CS-238 — Implement SMS provider client (Python requests)

## Context

SMS provider choice may vary by deployment, so a thin adapter isolates endpoint/auth differences while honoring Casa stack (Django 5.2 LTS + Django REST Framework + Django ORM) per [[EPIC-08-multichannel-delivery]] guidance.

## Scope

**In:**
- Config: `SMS_PROVIDER`, `SMS_API_BASE_URL`, `SMS_API_KEY`, `SMS_FROM`, `SMS_TIMEOUT_SECONDS`
- Function `send_sms(to_e164, body, idempotency_key)` returning provider id
- Automatic retries **only** when CS-234 classifies (client surfaces structured `SmsProviderError`)
- Unit tests with HTTPS mock server validating headers + JSON shape approximating §6.3 sample

**Out (explicit):**
- Webhook receiver (CS-242)
- SMS message registry definitions (CS-239) — but depends on it for body generation

## Acceptance criteria

- [x] Live-disabled CI tests pass entirely offline using recorded fixtures; optional smoke flag gated
- [x] Client raises typed errors for HTTP 401/403 distinct from 5xx
- [x] Maximum outbound payload guard ensures message body stays within configured SMS segment budget

### BVA — boundary value analysis

| HTTP status | Boundary | Expected |
|---|---|---|
| 429 | rate limit | surfacing `RATE_LIMITED` code for CS-243 |
| 400 + INVALID_PHONE_NUMBER | body | immediate permanent classification |

## Test intent (Rule 9)

Wrong adapter payloads may silently send empty SMS bodies — tests compare canonical payload snapshot against the message registry fixture from [[CS-239]].

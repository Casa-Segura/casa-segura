# CS-236 — Compose Spanish transactional email with PDF attachment

## Context

Email must restate score summary, deep link, attachment filename, disclaimer, expiration, and support contact without open/click tracking ([[PRD_F7_ENTREGA_MULTICANAL]] §3 US-02, BR-08/BR-11).

## Scope

**In:**
- Subject pattern `Tu análisis de contrato — Casa Segura — {readable_contract_type}` ([[RUBRICA_CONTRATO]] §13.1 echo)
- HTML body approximating PRD sample: headline score, band label, link to `/r/{public_short_id}`, yellow disclaimer box literal from BR-08
- PDF attachment name `casa_segura_{public_short_id}.pdf` sourced from [[CS-209]] bytes
- Plain-text `multipart/alternative` mirror for deliverability
- Explicit **no** tracking pixel, no unique per-user external image hosts, no link-wrapping analytics ([[PRD_F7_ENTREGA_MULTICANAL]] §4 BR-11)

**Out (explicit):**
- Actually invoking SMTP (CS-235) — pure builder + MIME assembly here
- WhatsApp templates

## Acceptance criteria

- [ ] Golden snapshot of MIME tree shows `Content-Disposition: attachment; filename="casa_segura_CS-2026-XXXXXX.pdf"` with predictable casing rules documented
- [ ] HTML part includes disclaimer Spanish string matching registry + `public_short_id` + `link_expires_at` localized string
- [ ] Static analysis fails build if `img src="http` appears in template source (except allowed data URIs if any)

### BVA — boundary value analysis

| Field | Boundary | Expected |
|---|---|---|
| `readable_contract_type` | very long localized label | subject line truncates ≤998 SMTP safe bytes with ellipsis policy |
| Score display | `0.0` vs `10.0` | formatting preserves one decimal consistent with report |

## Test intent (Rule 9)

BR-11 forbids surreptitious tracking; a future marketing patch might add invisible pixel — guard tests must fail on any remote image insertion even if email still renders.

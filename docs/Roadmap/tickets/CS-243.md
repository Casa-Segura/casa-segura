# CS-243 — Normalize SMS/SMTP errors to retry policy classes

## Context

Uniform error vocabulary feeds CS-234 decisions and operator metrics ([[PRD_F7_ENTREGA_MULTICANAL]] §3 US-06). Explicit codes called out in epic risk table include INVALID_PHONE_NUMBER, RATE_LIMITED, and PROVIDER_UNAVAILABLE.

## Scope

**In:**
- Adapter translating SMS provider JSON error payloads + SMTP codes into internal `DeliveryError` dataclass `{code, classification, retryable}`
- Registry enumerating known codes; default `GENERIC_PROVIDER_ERROR` mapped to transient unless body matches permanent heuristics
- Symmetric mapping for SMTP bounce catalog (subset)

**Out (explicit):**
- User-visible localized copy (handled at API layer elsewhere)

## Acceptance criteria

- [ ] Table-driven tests cover at least: `INVALID_PHONE_NUMBER` → permanent; `RATE_LIMITED` → transient; `PROVIDER_UNAVAILABLE` → transient; malformed template/body → permanent until vendor contradicts
- [ ] Unknown 5xx → transient; unknown 4xx → permanent unless allowlist says otherwise
- [ ] No exception path logs raw phone/email

### BVA — boundary value analysis

| Code | Boundary | Expected |
|---|---|---|
| malformed body/template | first send vs registry rotation | permanent until template version bump |
| `RATE_LIMITED` | during attempt 3 | still obeys max attempts cap |

## Test intent (Rule 9)

Mis-mapping malformed body errors to transient burns entire retry budget fruitlessly alerting on-call — tests encode operational pain cost.

## Notes

- Maintain single module imported by BOTH email + SMS workers to avoid divergence

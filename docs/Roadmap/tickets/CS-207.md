# CS-207 — Render suggested-actions blocks with bounded LLM abogado list

## Context

Section 7 turns diagnosis into choreography: seller negotiations, lawyer prep, demanded documents ([[RUBRICA_CONTRATO]] §11.1 Section 7). MVP uses deterministic assembly for blocks 1 and 3 plus LLM-assisted block 2 per [[PRD_F6_GENERACION_REPORTE]] §8.1 prompts with strict JSON emission.

## Scope

**In:**
- Three headings + bullet lists capped at **5 items each** (truncate with summarization ellipsis when upstream oversupplies) per §3 US-07
- Block 1: derive from actionable copy of findings `severity ∈ {critical,red}` prioritized by severity/weight mapping
- Block 3: seeded from extraction elements + category-D signals per §3 US-07
- Block 2: call bounded LLM with Spanish system prompt §8.1; parse JSON `{items:[..]}`; guardrails preventing legal advice wording (themes/questions only)
- If `band=green`: block 1 may be empty BUT render substitute encouragement string from §3 US-07
- Anchors referencing originating finding identifiers for block 1 when feasible (inline textual reference, not clickable off-domain)

**Out (explicit):**
- Exposing intermediate LLM chain-of-thought
- Persisting generated lawyer bullet list standalone (derive at render alongside analysis row per BR-01 spirit)

## Acceptance criteria

- [ ] Given analysis with critical and/or red severity findings yielding >5 actionable seeds, emitted list clamps to 5 with deterministic truncation rule documented (sort then slice)
- [ ] Given malformed LLM JSON, renderer surfaces controlled fallback bullets referencing static checklist + raises operational metric (failure counter) — still returns valid HTML skeleton
- [ ] Given manual inspection prompt log redaction ensures no clause beyond allowed excerpt enters LLM inputs (only titles + sanitized summaries fed)

### BVA — boundary value analysis

| Block | Boundary | Expected |
|---|---|---|
| Seller items | length 6 vs capped | Input 6 distill to 5 with explicit ordering rule logged |
| `band` | `green` vs `yellow/red` | `green` allows empty block 1 iff substitute phrase present |

## Test intent (Rule 9)

Capping avoids overwhelming users with >5 tasks while still obeying escalation priority — tests must encode slice priority (critical before red before yellow) rather than asserting only counts.

- Tie LLM temperature policy to infra ADR elsewhere; default low temperature deterministic seeds
- If OpenRouter outages occur, degrade block 2 to heuristic template enumerated in playbook (document fallback in ticket implementation notes)

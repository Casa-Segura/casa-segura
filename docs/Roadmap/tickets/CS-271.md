# CS-271 — Implement cleanup_transient for ContractSubmission and OcrJob

## Context

Transient rows (`contract_submission`, `ocr_job`) must not outlive their TTL ([[DOMAIN_MODEL]]): default **24 hours** via `expires_at`. [[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] US-04 mandates `cleanup_transient` every **15 minutes**, batching large deletes and preserving in-flight work.

## Scope

**In:**
- Job runner `cleanup_transient` deleting `contract_submission` where `expires_at < NOW()` per US-04
- Reliance on `ON DELETE CASCADE` from `ocr_job` → `contract_submission` as in [[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] DDL excerpt
- Batch deletes when pending row count exceeds configured threshold (default 10,000 per PRD)
- Metrics: rows deleted, duration, optional post-cleanup counts
- Integration with scheduler from [[CS-270]]

**Out (explicit):**
- Anonymization or link expiry — [[CS-273]], [[CS-274]]
- Changing TTL defaults (24h) — config-only follow-up unless PRD changes

## Acceptance criteria

- [x] Given a `contract_submission` with `expires_at` in the past and `processing_status = 'completed'` (or no open pipeline per guard below), when the job runs, then the row is deleted and dependent `ocr_job` rows are removed
- [x] Given `analysis_id IS NOT NULL` AND `processing_status != 'completed'`, when `expires_at < NOW()`, then the row is **not** deleted (cleanup waits; document exact status set considered “open”)
- [x] Given more than `JOB_BATCH_SIZE` eligible rows, when the job runs, then it deletes in batches without exceeding a single long lock (configurable batch size; default per [[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] §6.3)
- [x] Given the job runs twice with no eligible rows, when observed, then the second run is a no-op and still records `records_processed = 0` and `success`
- [x] Job failure does not retry immediately; next scheduled run picks up (idempotent per BR-05)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `expires_at` | `NOW() - 1µs` | Eligible for delete if guards pass |
| `expires_at` | `NOW() + 1µs` | Not deleted |
| `processing_status` | `completed` with `analysis_id` set | Deletable when past `expires_at` |
| `processing_status` | `analyzing` with `analysis_id` set | Not deleted while not completed |
| Batch size | `eligible = JOB_BATCH_SIZE + 1` | At least two batches executed |
| TTL policy | Domain default 24h | Rows younger than 24h unless `expires_at` overridden stay retained |

## Test intent (Rule 9)

The product promises transient storage disappears after the **24h** processing window. Tests must fail if the guard on in-flight submissions is removed (silent data loss mid-pipeline) or if batching is removed causing operational incidents on spikes.

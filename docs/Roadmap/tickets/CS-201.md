# CS-201 — Render report header identification and disclaimers

## Context

Section 1 of [[RUBRICA_CONTRATO]] §11.1 sets the identifiers and trust framing for the analysis. Headers must expose who/what/when the report is while repeating the invariant disclaimer ([[PRD_GENERAL]] BR-07) and the project-name caveat ([[PRD_F6_GENERACION_REPORTE]] §4 BR-09).

## Scope

**In:**
- Casa Segura wordmark/logo block and title `"Análisis de Contrato Inmobiliario"` per [[PRD_F6_GENERACION_REPORTE]] §3 US-02 (aligned with §11 wording)
- `public_short_id`, analysis date formatted for El Salvador readability ( día/mes textual + año ), detected contract type, optional reclassification callout mirrored from `contract_type_reclassified`/`reclassification_reason`
- Visible note verbatim (or substantive equivalent approved in copy review): *"el nombre se extrajo del contrato; no se verificó contra fuente externa"* per BR-09 / [[PRD_F6_GENERACION_REPORTE]] §3 US-02
- Prominent disclaimer *"Este reporte no es asesoría legal. Antes de firmar, consulta a un abogado."* with emphasized yellow background+border styling per §3 US-02
- Mobile reflow rules: viewport width **< 600px** stacks identification blocks into single column legible tap targets ([[PRD_F6_GENERACION_REPORTE]] §3 US-02); confirm **360px** baseline aligns with §9 mobile NFR alongside [[CS-210]]

**Out (explicit):**
- Classification confidence exposure (explicit open question in [[PRD_F6_GENERACION_REPORTE]] §10 Q2 — default **omit** pending product call)
- Per-channel email/SMS disclaimers ([[PRD_F7_ENTREGA_MULTICANAL]])
- Persisting branding assets externally (everything embedded or inlined per BR-14)

## Acceptance criteria

- [ ] Given a completed analysis fixture, header HTML includes `public_short_id`, formatted date, contract type label, and when `contract_type_reclassified=true`, a user-facing sentence stating reclassification and pointing readers to findings for detail (per §3 US-02 behavior)
- [ ] Given any render, the disclaimer string above appears once in the header region and matches configured registry literal for [[PRD_GENERAL]] BR-07
- [ ] Given project name present, the non-verified note appears adjacent to the project name line
- [ ] Given viewport 360px width in automated or manual visual check, no horizontal scroll for header content and ≥4.5:1 contrast for disclaimer text on its background (WCAG AA baseline per [[PRD_F6_GENERACION_REPORTE]] §9)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| Viewport width | 599px vs 600px | <600: single-column reflow; ≥600: multi-column allowed |
| `contract_type_reclassified` | `false` vs `true` | `false`: no reclass banner; `true`: banner + reason surfaced |

## Test intent (Rule 9)

BR-07 is structural: removing or softening the disclaimer copy or its high-visibility treatment breaks the legal posture even if layout tests still pass; tests must assert both string presence and non-trivial visual emphasis hooks (classes/ARIA/live region optional).

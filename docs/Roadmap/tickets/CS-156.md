# CS-156 — Assign score band from total score

## Context

Bands communicate risk posture: **red** 0.0–4.9, **yellow** 5.0–7.9, **green** 8.0–10.0 ([[RUBRICA_CONTRATO]] §2.1; [[PRD_GENERAL]] US-03). Assignment happens **after** rounding policy shared with [[CS-152]] unless superseded by [[CS-157]] overrides.

## Scope

**In:**
- Pure function `band_from_total(score_total: Decimal | float)` implementing inclusive ranges exactly as rubric
- Explicit ordering: evaluate green threshold first vs yellow vs red — document tie behavior at **exact** boundaries **5.0** and **8.0**
- Separate from `not_analyzable` band present on persistence enum ([[DOMAIN_MODEL]]) — this ticket covers analytic bands only

**Out (explicit):**
- Override forcing red — [[CS-157]]
- Report styling — [[EPIC-07-report-generation]]

## Acceptance criteria

- [ ] Given `score_total = 4.9`, output band is **`red`**
- [ ] Given `score_total = 5.0`, output band is **`yellow`**
- [ ] Given `score_total = 7.9`, output band is **`yellow`**
- [ ] Given `score_total = 8.0`, output band is **`green`**
- [ ] Given `score_total = 10.0`, output band is **`green`**
- [ ] Given scores produced only after `round(..., 1)`, boundary fixtures use the **same** rounding module as aggregation

### BVA — boundary value analysis

| score_total (post-round) | Boundary | Expected band |
|---|---|---|
| 4.9 | lower red edge | red |
| 5.0 | yellow inclusive lower | yellow |
| 7.9 | yellow upper | yellow |
| 8.0 | green inclusive lower | green |
| 7.95 → round 8.0 | floating drift | green (ties to rounding ticket) |
| 7.949 → round 7.9 | near miss | yellow |

## Test intent (Rule 9)

Band boundaries are **regulatory communication**: tests cite [[RUBRICA_CONTRATO]] §2.1 numeric literals — switching inclusive/exclusive endpoints must fail ([[Roadmap/README]] convention #5).

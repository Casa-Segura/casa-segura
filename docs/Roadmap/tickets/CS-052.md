# CS-052 — Implement ocr.detect_kind routing

## Context

Extraction cost and quality depend on classifying **text PDFs** vs **scans** vs **images** before choosing pypdf vs vision LLM. [[EPIC-02-ingestion-ocr]] aligns with [[BE-SERVICES]] §3, while [[PRD_F1_INGESTA_Y_OCR]] §US-04 specifies the **first-page pypdf character threshold** for `PYPDF` vs `VISION_LLM`.

## Scope

**In:**

- Implement `detect_kind(file_bytes, content_type) -> DocumentKind` surface (name may match `services/ocr.py` in [[BE-SERVICES]] §3.2).
- Map product inputs to strategies:
  - **PDF**: run `pypdf` text probe on **first page**; if **> 100** non-trivial characters → strategy label `PYPDF` / `TEXT_PDF`; else treat as **scanned** → `SCANNED_PDF` / `VISION_LLM` path.
  - **Raster images** (jpg/png/heic/webp): **direct** `VISION_LLM` without pypdf probe.
- Record diagnosis on `ContractSubmission.extraction_strategy_attempted` / per-file metadata as needed for observability.
- Support **optional** `force_strategy` QA flag from [[PRD_F1_INGESTA_Y_OCR]] §7.1 without exposing in public docs if product requires internal-only header.

**Out (explicit):**

- Billboard / Flow-1 `BILLBOARD_IMAGE` classification — [[EPIC-12-project-verification]].
- Implementing actual extraction (pypdf/vision/tesseract) — [[CS-053]], [[CS-054]], [[CS-055]].

## Acceptance criteria

- [x] Given a native PDF whose first page yields **101** meaningful characters via pypdf, when `detect_kind` runs, then the chosen strategy is **`PYPDF`** (or enum equivalent) and is logged without persisting file bytes.
- [x] Given a scanned PDF whose first page yields **≤ 100** characters, when `detect_kind` runs, then the chosen strategy routes to **vision** path classification (`VISION_LLM` / scanned).
- [x] Given a JPEG contract photo, when `detect_kind` runs, then classification is **vision** without attempting pypdf.
- [x] Given `force_strategy` set to a valid enum, when detection runs, then the forced strategy overrides automatic diagnosis **and** this override is auditable in structured logs (not user-facing).
- [ ] Given mixed multi-file submissions, when global strategy is computed per [[PRD_F1_INGESTA_Y_OCR]] §US-04 (“majority”; mixed → per-file separate processing + concatenate), then unit tests prove ordering and tie-break rules are deterministic. **[blocked by CS-050 multi-file shape]**

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| First-page char count (PDF) | 99 / 100 / 101 | ≤100 → vision path; ≥101 → pypdf path (strict `> 100` comparator) |
| Content type | `application/pdf` vs `image/jpeg` | PDF runs probe; image skips probe |
| force_strategy | absent / invalid / valid | invalid rejected with 400; valid overrides |

## Test intent (Rule 9)

Tests guard the **100-character** routing threshold from [[PRD_F1_INGESTA_Y_OCR]] — not “we called some PDF function” — because mis-routing shifts cost and accuracy materially.

## Status — 2026-05-16

Closed after the EPIC-02 audit against commit `067da9e`. Multi-file majority logic (AC5) deferred to [[CS-050]] (depends on multi-file payload shape that is not yet shipped).

**Shipped implementation:**

- `_PDF_NATIVE_TEXT_THRESHOLD = 100` in `backend/ingestion/application/ocr/router.py`; probe uses strict `> 100` comparator (PRD §US-04: 100 chars still routes to vision, 101+ qualifies as native).
- PDF rama only activates when MIME is `application/pdf` **or** the filename extension is `.pdf` — unknown MIME with no extension falls through to the `TESSERACT` fallback instead of silently shoving every byte stream through the pypdf probe.
- New `force_strategy: ExtractionStrategy | None` parameter on `detect_kind`. When provided, routing is bypassed and the override is logged at `INFO` with `forced_strategy` + `file_format` so audits can tell apart a forced run from automatic detection. Routing reason is `"forced_<strategy>"`.
- Wired through `UploadRequest.force_strategy` (`backend/ingestion/application/upload_service.py`) and the `X-Force-Strategy` header on `POST /api/v1/submissions/` (`backend/ingestion/interfaces/api/views.py`). Invalid header values return HTTP 400 with `error_code=INVALID_FORCE_STRATEGY` and the allow-list in the detail.
- `ContractSubmission.extraction_strategy_attempted` continues to record the routing result for observability.

**Tests:**

- `backend/tests/test_ingestion_router.py`:
  - MIME dispatch (JPEG / PNG / scanned PDF / unknown MIME → Tesseract).
  - BVA at the PRD comparator boundary — `test_pdf_first_page_99_chars_routes_to_vision`, `test_pdf_first_page_100_chars_routes_to_vision`, `test_pdf_first_page_101_chars_routes_to_pypdf`.
  - `force_strategy` overrides on PDF (`test_force_strategy_overrides_automatic_routing_for_pdf`), on images (`test_force_strategy_overrides_image_to_tesseract`), and on images forced to PYPDF (`test_force_strategy_pypdf_on_image_is_honoured_but_extractor_decides_failure`).
- `backend/tests/test_ingestion_submission_api.py`:
  - `test_invalid_x_force_strategy_header_returns_400` — bogus value → 400 `INVALID_FORCE_STRATEGY`.
  - `test_valid_x_force_strategy_header_routes_to_override` — `X-Force-Strategy: tesseract` on a PDF lands the orchestrator on the Tesseract extractor.

**Deferred / blocked:**

- Multi-file majority logic depends on the `files[]` payload shape from [[CS-050]] — the router is ready to ingest a list, but the upload endpoint is still single-file.

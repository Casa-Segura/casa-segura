# CS-035 — Migration smoke test in CI (migrate → reverse → migrate)

## Context

Migrations must be revertible within engineering policy and safe to apply twice ([[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] US-1). This ticket adds a CI job exercising `python manage.py migrate` forward, reversing Casa-owned apps to documented zero points, then migrating forward again on an ephemeral Postgres + pgvector service.

## Scope

**In:**
- GitHub Actions (or existing CI) job spinning Postgres 15+ with pgvector enabled, matching [[CS-020]] image
- Scripts encapsulating the three-step migration test with logs on failure
- Optional lightweight `python manage.py migrate --plan` (or `--check` pending availability) schema sanity probe after upgrade—keep fast

**Out (explicit):**
- Data migration of production datasets — ops runbooks
- Performance benchmarking — future ticket

## Acceptance criteria

- [x] Given CI pipeline, when migration job runs on PR touching repo `**/migrations/*.py` (excluding blank `__init__.py`), when migration succeeds, then job is required for merge
- [x] Given compose image, when job executes sequence migrate-forward → structured reverse → migrate-forward, then final exit code zero (reverse steps documented—typically `migrate <app_label> zero` ordering for Casa-owned apps only)
- [x] Given deliberate broken migration on throwaway branch, when job runs, then failure log includes Django migration identifier (`app_label` + migration name) from the traceback or wrapper
- [x] Given job runtime budget, when measured on default runner, then completes <10 minutes cold (tune service health waits)
- [x] Given documentation link from [[EPIC-01-persistence]], when engineer reads roadmap, then points to job name/path

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| Parallel jobs | multiple PRs | Each uses isolated DB container, no cross-talk |
| Downgrade | destructive data loss | Acceptable on empty DB only—document that reverse migrations are CI/dev validation, not a guarantee of preserving prod data |

## Test intent (Rule 9)

Migration mistakes are schema-level production incidents. CI must catch non-idempotent or non-reversible migrations before humans merge.

## Notes

- Coordinate with [[CS-004]] to avoid duplicating setup; reuse composite action if helpful.
- If team policy forbids destructive reversals outside CI, say explicitly—the job still validates graph integrity on ephemeral volumes.

# CS-022 — SQLAlchemy 2 base, session factory, FastAPI dependency

## Context

All ORM models share one declarative base and lifecycle-managed sessions ([[EPIC-01-persistence]]; [[DOMAIN_MODEL]] as reference). This ticket implements the SQLAlchemy 2 engine/session pattern and a FastAPI `Depends` provider for request-scoped DB access.

## Scope

**In:**
- `DeclarativeBase` (2.0 style) module and metadata naming conventions aligned with snake_case table names from PRD DDL
- Engine factory reading `DATABASE_URL`, pool settings honoring `DB_POOL_MIN_SIZE` / `DB_POOL_MAX_SIZE` from [[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] §6.3 / [[CS-006]]
- `sessionmaker` with `expire_on_commit=False` (or documented alternative) and context manager/`async` strategy matching FastAPI app in [[CS-002]]
- FastAPI dependency yielding a Session; commit/rollback rules documented (rollback on exception)
- pytest fixture stub enabling future [[CS-032]] (may create empty DB session for unit tests)

**Out (explicit):**
- Individual model classes — [[CS-023]]+
- Redis sessions — feature epics

## Acceptance criteria

- [ ] Given FastAPI app startup, when lifespan hooks run, when engine connects, then `SELECT 1` succeeds against Postgres from [[CS-020]]
- [ ] Given a route using the DB dependency, when the handler raises mid-request, when the session closes, then pending transaction is rolled back (verified via counter example using a deliberate failure)
- [ ] Given SQLAlchemy 2 type annotations policy, when `mypy` runs on `app/db`, then no `Any`-shim violations beyond explicitly documented boundaries
- [ ] Given pool env vars set to non-default integers, when engine initializes, then pool sizes reflect those env values (observable via logging or SQLAlchemy pool inspection in dev-only endpoint—guarded)
- [ ] Given documentation, when onboarding reads “DB access”, then they see one example route sketch showing correct session usage

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `DB_POOL_MIN_SIZE` > `DB_POOL_MAX_SIZE` | invalid pair | Startup fails fast with readable configuration error |
| Missing `DATABASE_URL` | empty string | Startup fails fast; never silently uses sqlite memory |

## Test intent (Rule 9)

Session leaks or implicit autocommit bugs cause duplicate analyses and poison aggregation logic later. Tests must prove rollback-on-error and single-session-per-request semantics.

- If the codebase chooses `AsyncSession`, ensure Alembic remains synchronous or adopt async Alembic explicitly—pick one documented pattern.
- Wire readiness checks later per [[CS-008]] notes once stable.

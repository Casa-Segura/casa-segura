# CS-027 — Schema: RubricVersion + Criterion

## Context

The rubric is an immutable, versioned catalog consumed by scoring ([[DOMAIN_MODEL]] §3.3 + §3.7; [[PRD_GENERAL]] BR-16; [[RUBRICA_CONTRATO]] §16). This ticket creates `rubric_version` and `criterion` with composite PK `(id, rubric_version)` and category CHECK `A..F`.

## Scope

**In:**
- `rubric_version` table per PRD DDL including `is_active` and partial unique index ensuring ≤1 active row
- `criterion` table with weights CHECK `0 < weight_in_category <= 100`, `applicable_types` array NOT NULL, `scoring_scale` JSONB NOT NULL, `worst_case_when_unverifiable` default 4.0 per PRD DDL
- GIN index on `applicable_types`
- ORM models; enforce immutability at app layer (no UPDATE paths in services) per PRD US-10 policies

**Out (explicit):**
- Populating 38 rows — [[CS-033]]
- Runtime evaluation — [[EPIC-06-rubric-engine]]

## Acceptance criteria

- [x] Given rubric `1.0.0` row inserted, when criterion row shares same `rubric_version`, when composite PK matches, then fetch joins succeed
- [x] Given duplicate `(id, rubric_version)` insert, then PRIMARY KEY constraint fails
- [x] Given `category='G'` insert attempt, when CHECK enforced, then rejection
- [x] Given weight `101` insert attempt, when CHECK enforced, then rejection
- [x] Given two rubric rows marked `is_active=true` insert attempts, when partial unique index enforces singleton active, then second insert fails (define migration ordering vs seed scripts—tests must cover)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `weight_in_category` | 0.01 vs 100.0 | Accept; 0 rejected |
| `worst_case_when_unverifiable` | aligns with BR-04 worst-case scoring philosophy | Stored numeric must be within 0–10 domain of criterion scores ([[PRD_GENERAL]] US-03); illegal values rejected at app validation if DB too permissive |

## Test intent (Rule 9)

Criterion weights are load-bearing math inputs; corrupted constraints silently skew all future scores. Tests must lock category and weight CHECKs.

## Notes

- Map `override_code` optional column to DOMAIN `OverrideCode` list conceptually; DB may store TEXT with service enum validation.
- Coordinate active rubric selection with [[CS-033]] seed and [[CS-010]] ADR.

## Status — 2026-05-15

**Implemented:**
- `RubricVersion` with `version` PK, `released_at`, `criteria_count`, `categories` JSON, `criteria_definitions_path`, `changelog`, `is_active` + partial unique `uq_rubric_version_active_singleton` (condition `is_active=True`) — `backend/rubric/infrastructure/django/models.py::RubricVersion` (commit `02fac1f`).
- `Criterion` with UUID surrogate PK, `code`, FK `rubric_version` ON DELETE PROTECT, `category` CHECK A..F (`ck_criterion_category_enum`), `title`, `description`, `weight_in_category` CHECK `0 < w <= 100` (`ck_criterion_weight_range`), `applicable_types` ArrayField NOT NULL, `legal_anchor` ArrayField default list, `override_code` nullable CharField (stores `OverrideCode` strings, validated at service layer), `evaluation_prompt`, `scoring_scale` JSONField, `worst_case_when_unverifiable` default 4.0 — same file lines 55-134.
- Composite uniqueness `(code, rubric_version)` via `UniqueConstraint` `uq_criterion_code_rubric` (using surrogate UUID PK + composite-unique is the documented divergence from "PK on (code, rubric_version)" — matches ticket Notes which says "Same criterion `code` may legitimately exist in multiple rubric versions, so the natural key is composite").
- Index `idx_criterion_rubric` on `rubric_version` exists; GIN on `applicable_types` is NOT present (verified — only the listed BTree index for this table) — see Partial.
- Migration applied — `rubric_version` and `criterion` tables present in `casasegura`.

**Partial / Missing:**
- GIN index on `applicable_types`: ticket Scope lists "GIN index on `applicable_types`" but the model only declares `models.Index(fields=["rubric_version"])`. No GIN exists for `criterion.applicable_types`. (Note: `economic_benchmark.applicable_contract_types` DOES have a GIN; this one is missing.)
- Acceptance criteria do not explicitly call out the GIN bullet so all 5 acceptance boxes are tickable, but the Scope drift is real.

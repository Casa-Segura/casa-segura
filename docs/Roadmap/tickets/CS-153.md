# CS-153 — Enforce asymmetric penalty vs benchmarks

## Context

Conditions **favorable** to the buyer vs market benchmarks must never yield a **lower** criterion score than the benchmark-equivalent outcome ([[RUBRICA_CONTRATO]] §1.1; [[PRD_GENERAL]] US-03). F5 supplies benchmark comparisons; F4 applies clamp rules before aggregation ([[PRD_F5_ANALISIS_ECONOMICO]] scope).

## Scope

**In:**
- Deterministic helper(s): inputs = `(raw_score, metric_direction, contract_value, benchmark_reference)` outputs = `clamped_score` per criterion policies **B1 down payment**, **B2 rate**, **B3 term**, **B4 total cost multiplier** ([[RUBRICA_CONTRATO]] §5)
- Unit tests using frozen `economic_benchmarks.yaml` fixture fragment from [[RUBRICA_CONTRATO]] §14
- Integration hook point: evaluator pipeline calls clamp **after** LLM proposes numeric score when economic inputs are trusted present

**Out (explicit):**
- Changing benchmark YAML values in production — ops process
- Non-economic criteria asymmetric rules — only where rubric states asymmetric explicitly

## Acceptance criteria

- [ ] Given down payment **below** configured benchmark (more favorable to buyer), clamped score is **≥** score produced by evaluating exactly at benchmark holding other facts equal (fixture table)
- [ ] Given interest rate **below** segment benchmark median (B2 reference 9% illustrative), clamped score is **≥** benchmark-tier score for that segment
- [ ] Given total cost ratio **better** than healthy threshold (lower multiplier), clamped B4 score is **≥** score at the healthy ceiling boundary in rubric scale
- [ ] Given ambiguity (missing benchmark segment), function returns original score and logs `ASYMMETRIC_SKIPPED_REASON`
- [ ] Given LLM returns worse-than-benchmark score for objectively better economic inputs, post-condition restores rubric-consistent ordering detectable by assertion

### BVA — boundary value analysis

| Metric | Boundary | Expected clamp behavior |
|---|---|---|
| Down payment % | benchmark vs benchmark − 0.1 pp | lower payment never scores worse than benchmark mapping |
| APR | 8.99% vs 9.00% vs 9.01% @ ref 9% | tier never regresses when rate improves crossing downward |
| Total cost / cash | 1.49 vs 1.50 | better ratio never maps below 1.50-tier score |
| Missing `price_cash` | null benchmark compare | skip clamp, documented |

## Test intent (Rule 9)

Tests must fail if a well-intentioned refactor applies **symmetric** distance-to-benchmark logic — the rubric philosophy is explicitly **one-sided** protection ([[RUBRICA_CONTRATO]] §1.1).

# CS-291 — Build contract upload page with disclaimer gate

## Context

[[PRD_GENERAL]] US-01 and [[PRD_F1_INGESTA_Y_OCR]] US-01 require explicit disclaimer acceptance before upload; the UI must collect files (drag-drop + picker), show validation feedback, and **not** block on project verification before analysis ([[STATUS_RECONCILIATION]]). Upload integrates channel selection ([[CS-292]]) and server actions ([[CS-296]]).

## Scope

**In:**
- Upload route: multi-file picker + drag-drop; disabled until disclaimer accepted
- Client-side constraints aligned with **PRD** (formats, size, page counts)—not legacy UI-UX copy if it conflicts
- State machine: empty → selected → uploading → success/error ([[UI-UX Documents/UI-UX]] §5, adapted copy)
- posts `disclaimer_accepted=true` per F1 when calling backend
- Spanish **tú** strings for errors

**Out (explicit):**
- WhatsApp Zavu inbound session UX
- Backend validation implementation — BE epics

## Acceptance criteria

- [x] Given disclaimer unchecked, when user attempts upload/submit, then request is blocked client-side **and** never calls server action without acceptance flag
- [x] Given accepted disclaimer and valid files per PRD (PDF/JPEG/PNG/HEIC/WEBP), when submitted, then server action invokes BE and returns `submission_id` / polling handle per contract
- [x] Given file over configured max (default **15 MB** per file from [[PRD_F1_INGESTA_Y_OCR]]), when selected, then UI shows Spanish error citing limit (not the outdated **10 MB** string from [[UI-UX Documents/UI-UX]] §5)
- [x] Given total pages exceed PRD limits (defaults: PDF 50 pages, total 80 per submission), when user submits, then UI surfaces `TOO_MANY_PAGES`-class messaging returned by BE if server rejects
- [x] Given error path, when BE returns `DISCLAIMER_REQUIRED`, then UI prompts to accept disclaimer (never silent failure)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| File size | `max_bytes` and `max_bytes + 1` | Accept vs reject |
| File count | 1 vs 50 vs 51 files | OK at edges per PRD; reject above |
| Disclaimer | accepted vs not | Gate blocks network call |
| Viewport | **360px** | Dropzone and previews usable; remove control reachable |

## Test intent (Rule 9)

Misaligned limits or a bypassable disclaimer gate create **legal/ops risk** (processing without consent) and user frustration. Tests must fail if PRD validation constants regress to UI-UX prose values or if uploads proceed without explicit acceptance.

# CS-203 — Render economic figures, benchmark bars, and Art. 1686 warning

## Context

Purchasers compare contract economics vs market benchmarks in section 3 of [[RUBRICA_CONTRATO]] §11.1. The UI must summarize `EconomicSummary`/`BenchmarkComparison` inputs in tables plus inline SVG bar charts ([[PRD_F6_GENERACION_REPORTE]] §3 US-04). For **purchase** contract families, [[PRD_F6_GENERACION_REPORTE]] §4 BR-08 default `always` aligns with stakeholder guidance: surface **Art. 1686** warning by default regardless of discretionary modes.

## Scope

**In:**
- Inclusion gate: omit whole section body when `economic_summary` absent or contract type materially lacks benchmarks (explicit reduced copy path per §3 US-04 omission clause)
- Table rows listing cash price, down payment amt/%, financed amount, term years, EA rate, monthly payment, total cost, total vs cash multiplier as available in payload
- Inline SVG comparative bars patterned on §3 US-04 exemplar (`Tasa de interés`, benchmark vs contract) with textual delta annotation
- Highlight overcost statement when `EconomicSummary` supplies narrative fields ("Pagas $X más…") and render `what_changes_would_save` bullets when present
- **Art. 1686 CC** warning block at end of section when `contract_type ∈ {CVC, CVP, APV, LEA, FSV}` with **production default behavior = always show** irrespective of narrower config modes (implement config hook but acceptance locks default-always MVP policy per stakeholder segment notes + BR-08 default `"always"`)

**Out (explicit):**
- Recomputing benchmarks (consumes persisted `benchmark_version`)
- Persisting SVG assets externally
- Bank/association trademarks ([[PRD_F6_GENERACION_REPORTE]] §4 BR-06 — text labels only)

## Acceptance criteria

- [ ] Given `economic_summary=NULL`, verdict/following sections render with no `.cs-economic` substantive content besides optional one-line explanatory stub defined in §3 US-04
- [ ] Given populated summary, each numeric row shows adjacent benchmark comparator when upstream provides comparator object; absent comparator yields neutral dash with assistive text
- [ ] Given `contract_type=CVC` (and likewise other purchase codes listed), Art. 1686 warning paragraph appears after economic content even when `band=green` and even if config flag tries `when_red` in non-prod experiments (MVP default **always**)
- [ ] Given non-purchase types (e.g. pure `ARV` without purchase semantics per product rule table), Art. 1686 block is suppressed with documented mapping table checked into tests

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| Contract type | Purchase set vs non-purchase | Purchase: Art. 1686 shown; non-purchase: hidden |
| `economic_summary` | `NULL` vs object | NULL: section omitted/reduced per §3 US-04; object: full layout |
| Config `art_1686_warning_mode` | `always` vs `when_red` vs `never` | MVP acceptance locks `always` for purchase types regardless of `never` in lower envs (feature flag may exist but default deploy = always) |

## Test intent (Rule 9)

Art. 1686 explains irremediable price risk in El Salvador; hiding it on "green" purchase contracts misleads users about rescission law — tests must fail if purchase analysis omits the warning under default configuration even when economics look favorable.

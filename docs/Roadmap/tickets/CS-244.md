# CS-244 — Wire SMS secrets via secrets baseline infrastructure

## Context

Production deployment must source `SMS_API_KEY`, `SMS_WEBHOOK_SECRET` when callbacks are enabled, and sender/provider settings through the same vault path as baseline secrets established in foundation tickets ([[CS-006]]), preventing `.env` drift.

## Scope

**In:**
- Terraform/compose/k8s secret references consistent with infra chosen stack
- Runtime validation failing fast when placeholder keys detected in staging/prod namespace
- Documentation snippet for rotating keys coordinated with webhook consumer ([[CS-242]])

**Out (explicit):**
- CI publishing credentials (never plaintext in repo beyond samples)

## Acceptance criteria

- [ ] Application boot logs redacted summary showing booleans `{sms_auth_configured}`, `{sms_webhook_secret_configured}` derived from existence checks rather than literals
- [ ] `./scripts/smoke_delivery.py` gated env ensures dry-run mode without real keys in developer laptops
- [ ] Secret rotation procedure documented referencing dual-write window for webhook secret swap

### BVA — boundary value analysis

| Env namespace | Boundary | Expected |
|---|---|---|
| Preview vs Prod | mismatched webhook secret preview hitting prod ingress | Routing tests ensure preview uses isolated URL host |

## Test intent (Rule 9)

Booting with missing SMS secrets but channel enabled would enqueue failing jobs silently — readiness probe must flip unhealthy when contradictory config arises.

# CS-004 — CI pipeline (lint, type-check, test, build) on PR

## Context

[[EPIC-00-foundation]] requires every PR to prove both apps stay green. This ticket adds continuous integration so merges are blocked on measurable quality gates, matching the open-source posture in [[ARCHITECTURE]] §9.

## Scope

**In:**
- CI workflow(s) for pull requests (GitHub Actions) running on **`backend/`** (canonical Django project) and **`frontend/`** (canonical Next.js surface)
- Jobs: Python `ruff`/`mypy`/`pytest` as configured in [[CS-002]]; web `lint`, `typecheck`, `test`, `build` as configured in [[CS-003]]
- Branch protection documentation: required checks listed in README or contributing doc (if org permits)
- Caching for package installs where straightforward (pip/npm/pnpm)

**Out (explicit):**
- Deploy pipelines — [[EPIC-11-observability]] / operations
- Database migration smoke — [[CS-035]]
- E2E/browser automation — future EPIC tickets

## Acceptance criteria

- [x] Given an open PR that touches only **`backend/`**, when CI runs, then **Ruff** lint, **Black** / **isort** checks, **`retention_scheduler_dry_validate`**, and **`pytest`** report status on the PR (see `Backend lint` / `Backend tests`)
- [x] Given an open PR that touches only **`frontend/`**, when CI runs, then **ESLint**, **Vitest**, **`tsc --noEmit`**, and **`next build`** report status (`Frontend build`)
- [x] Given a PR that touches both surfaces, CI aggregates all workflow jobs normally so reviewers get a composite pass/fail outcome
- [x] Given a deliberate **`ruff`** lint violation pushed to any throwaway branch, **`Backend lint`** fails with the offending **rule id** surfaced in stderr (verification recipe summarized in repo root **`README`** §CI / “Integración continua” plus this ticket’s Notes)
- [x] Given the branch state that merges this ticket, **`pre-commit run --all-files`** exits **zero** ([[CS-005]] baseline after Prettier normalization) and Actions jobs listed in `README` do not silently skip lint/test gates

## Test intent (Rule 9)

CI is the mechanical guarantee that [[EPIC-00-foundation]]’s “types check clean, tests run green” is true on every change, not only on an engineer’s laptop. A test of the workflow itself is the repo’s contract with contributors.

## Notes

- Keep workflow YAML minimal; shard jobs only if cold-start time forces it.
- **mypy** remains an explicit CS-002 strictness rollout (not duplicated as a flaky required job here).
- Recommended GitHub Branch protection mirrors the **job names table** published in **`README`** (“Integración continua” subsection).
- Forks reproduce via PR to the public repo (`README` wording) or Actions → “Re-run jobs” UI.

# CS-081 — Chunk Markdown body into LegalChunk segments

## Context

Semantic retrieval works at **article granularity** with deterministic anchors. [[BE-SERVICES]] §4.3: one article ⇒ one chunk unless length **> ~1500** characters, where numbered subsections split. [[DOMAIN_MODEL]] §3.6 requires stable `anchor` slugs aligning with headings (`art-4`).

## Scope

**In:**

- Markdown parser emitting sections from heading patterns **`### Art. N`** (per PRD example) aligned with corpus files (also accept `## Article N —` grammar from README if loaders detect both — normalize to canonical `anchor` scheme).
- Enforce UNIQUE `(corpus_version, law_id, anchor)` precondition by construction.
- When body length **>1500 chars**, subdivide using explicit subsection numbering heuristics (e.g. `1)`, `a)` enumerated lines) documented in parser module.
- Persist `article_number`, `section_title`, `text_paraphrased` sourcing curated paraphrase text; optional `text_verbatim` pass-through column when present beneath chunk.
- Unit snapshot tests anchored to golden mini-law markdown fixture.

**Out:**

- Automated paraphrase generation (explicitly forbidden, [[PRD_F3_CORPUS_Y_RAG]] BR-04).

## Acceptance criteria

- [ ] Given an article Markdown section of **1499 characters**, when chunked, exactly **one** `LegalChunk` record is staged.
- [ ] Given **1501 characters** without subdivider cues, splitter raises deterministic error (**no silent truncation**) unless curator adds markers — policy: fail ingestion with actionable message referencing file/line ([[PRD_F3_CORPUS_Y_RAG]] BR-04 quality gate).
- [ ] Given artificially injectable subdividers, splitter yields **multiple** anchors `art-12-a`, incremental suffix rules encoded and tested (document scheme).
- [ ] Parser associates optional inline tag lines (`Tags:`/`Relevant_for:`) into staged chunk metadata hooks feeding [[CS-082]].

### BVA — boundary value analysis

| Measure | Boundary | Expected |
|---|---|---|
| Article body length | 1500 vs 1501 | Split/overlength handling per policy above |
| Anchor uniqueness | Collision attempt | Raises before DB insert |

## Test intent (Rule 9)

Chunk tests guarantee **deterministic citations** (“Art. 12(a)”) tied to headings — synthetic chunk IDs that shift silently should fail CI because they undermine legal traceability ([[DOMAIN_MODEL]]).

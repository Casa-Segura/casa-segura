# CS-297 — Single-source disclaimer module (“Esto no es asesoría legal”)

## Context

[[PRD_GENERAL]] BR-07 requires the exact disclaimer **"Esto no es asesoría legal"** on every user-facing touchpoint. [[PRD_F1_INGESTA_Y_OCR]] US-01 requires showing it before processing. Centralize literal + optional extended microcopy so translators and compliance review one file.

## Scope

**In:**
- Exported constant `DISCLAIMER_SHORT = "Esto no es asesoría legal"` (single quotes in code OK)
- React component `DisclaimerCallout` with variants: `inline`, `footer`, `gate` (checkbox acceptance in gate variant with accessible label)
- Unit test guarding literal string (prevents accidental edits)
- Used by [[CS-290]], [[CS-291]], [[CS-294]], [[CS-295]] at minimum

**Out (explicit):**
- Managing PDF/email templates — F6/F7 repos may duplicate string until shared package exists—document drift risk

## Acceptance criteria

- [x] Given codebase search, when run for the Spanish literal, when reviewed, then it appears **only** in this module (imports elsewhere) except documented F6/F7 template exceptions
- [x] Given gate variant, when checkbox unchecked, when parent queries state via ref/prop, then submission remains disabled
- [x] Given gate variant, when SR user focuses checkbox, then label includes full consequence (“acepto que esto no es asesoría legal…” wording finalized with legal)
- [x] Given `footer` variant on landing, when rendered, then styling matches muted UI-UX spec without shrinking below 14px effective size on mobile
- [x] Given future i18n hook, when refactor happens, then API of module keeps `disclaimerId` stable for analytics-free apps

### BVA — boundary value analysis

| Variant | Boundary | Expected |
|---|---|---|
| `gate` | checked vs unchecked | Parent submit disabled/enabled at boundary only |
| `footer` | long helper text optional | Still ≥4.5:1 contrast for small text |
| Literal | missing accent | Tests fail (`asesoría`) |

## Test intent (Rule 9)

BR-07 is literal-law adjacent; a drifted disclaimer breaks uniform risk disclosure. Tests must fail if the string changes without legal review or if gating UI bypasses the checkbox via imperative submit.

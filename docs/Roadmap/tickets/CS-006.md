# CS-006 — Secrets baseline (.env.example with full env surface)

## Context

Operators and developers need one authoritative list of configuration keys. [[BE-SERVICES]] §9 enumerates integration and ML/RAG/OCR variables; persistence and retention jobs add database and job tuning keys in [[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] §6.3. `.env.example` is the mechanical backbone for [[PRD_GENERAL]] BR-07 surfacing (“disclaimer everywhere” is enforced in app code, but env docs prevent accidental misconfiguration).

## Scope

**In:**
- Root `/.env.example` (or `apps/api/.env.example` + web mirror if split, with cross-links) listing every variable with a short comment and safe placeholder
- Grouping headers: Core/API, OpenRouter, Zavu, Redis, Search, RAG/OCR embeddings, **Database & pool**, **Jobs / retention** (PRD F8), logging
- Explicit note: never commit real secrets; link to org secret store policy if any

**Out (explicit):**
- Loading/parsing implementation beyond documenting keys — feature code
- Production secret provisioning — operations

## Acceptance criteria

- [ ] Given `/.env.example`, when a reviewer compares it to [[BE-SERVICES]] §9, then every key listed under “Existing” and “New” appears with the same logical name (allow `DATABASE_URL` vs split `DB_*` only if the codebase standard is documented once)
- [ ] Given OCR/RAG keys from [[BE-SERVICES]] §3.5 and §4.7, when scanning `.env.example`, then `OCR_FALLBACK_ENABLED`, `TESSERACT_LANG`, `PDF_MAX_PAGES`, `EMBEDDING_MODEL`, `EMBEDDING_DIM`, `RAG_TOP_K`, `RAG_SIMILARITY_THRESHOLD` are all present
- [ ] Given [[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] §6.3, when scanning `.env.example`, then `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_POOL_MIN_SIZE`, `DB_POOL_MAX_SIZE`, `ANONYMIZATION_AFTER_DAYS`, `JOB_BATCH_SIZE`, `JOB_TIMEZONE` are present (or superseded by a single `DATABASE_URL` plus documented pool vars—pick one scheme and document the other as derived)
- [ ] Given [[PRD_GENERAL]] open questions on link TTL, when reading `.env.example`, then any **proposed** report link TTL variable is present as optional with default comment (e.g. 30 days) or explicitly deferred with pointer to EPIC-07 ticket—no silent magic number in code without env documentation
- [ ] Given a fresh clone, when a contributor copies `.env.example` → `.env`, then the API boots per [[CS-002]] with only non-secret placeholders filled (external keys may remain blank but must be clearly marked required for specific features)

### BVA — boundary value analysis

| Input | Boundary | Expected documentation in `.env.example` |
|---|---|---|
| `ANONYMIZATION_AFTER_DAYS` | product min/max | Comment states default 90; downward-only adjustment allowed per PRD BR-03; lengthening requires privacy review |
| `RAG_SIMILARITY_THRESHOLD` | 0.65 nominal | Comment cites default 0.649 vs 0.651 behavior (“cite or stay silent”) per [[STATUS_RECONCILIATION]] BVA examples |
| `PDF_MAX_PAGES` | upper reject | Comment states contracts beyond limit are rejected (`not_analyzable` / ingestion error) per ingestion PRD alignment |

## Test intent (Rule 9)

Drift between documented env vars and runtime reads is a production outage vector (DB URL, Redis, OpenRouter). The acceptance review treats `.env.example` as a contract: if code reads a key not listed, or lists a key never read, the ticket is not done.

## Notes

- If the codebase uses `DATABASE_URL` exclusively, map PRD F8 split vars into comments under that single key for operator clarity.
- Zavu and search keys remain mandatory only for EPIC-08 work; mark as optional for Phase 0 local dev.

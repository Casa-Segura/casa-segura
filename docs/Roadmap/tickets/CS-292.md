# CS-292 — Build delivery channel selector (email / WhatsApp / link)

## Context

Users choose how they receive the report at upload time ([[PRD_GENERAL]] US-05; [[PRD_F7_ENTREGA_MULTICANAL]] US-01). The web UI must expose three channels with short Spanish explanations and route destination capture rules: email → address, WhatsApp → E.164 phone, web link → no destination.

## Scope

**In:**
- Radio or segmented control for `email_pdf` | `whatsapp_summary` | `web_link` (names aligned with [[DOMAIN_MODEL]] enums)
- Conditional fields with validation UX (regex client-side mirrors PRD intent; server remains source of truth)
- Emits chosen channel + normalized destination payload to [[CS-296]] submit action
- Accessible labels, errors announced to SR

**Out (explicit):**
- SMTP / Zavu send logic — backend F7
- MX lookup / disposable-domain blacklist — backend enforcement

## Acceptance criteria

- [x] Given channel `web_link`, when the user views the form, then no email/phone inputs are required and payload omits destination fields
- [x] Given channel `email_pdf`, when user enters invalid email format, then inline error blocks submit with Spanish **tú** message
- [x] Given channel `whatsapp_summary`, when user enters non-E.164 phone, then inline error blocks submit (expect `+503…` style per PRD examples)
- [x] Given channel change after partial entry, when user switches, then sensitive fields clear and errors reset
- [x] Given keyboard navigation, when tabbing through, then focus order is headline → channel control → conditional inputs → submit

### BVA — boundary value analysis

| Enum | Boundary | Expected |
|---|---|---|
| `DeliveryChannel` | exactly three options | No extra MVP channels (no SMS) |
| Phone length | 10 vs 15 chars E.164 | Accept within PRD bounds; reject outside |
| Email | local@domain | Valid vs obviously invalid cases delegated to BE for definitive bounce class |

## Test intent (Rule 9)

Wrong-channel payloads create **delivery failure** and support load. Tests must fail if link mode accidentally still POSTs blank email or if enums drift from BE schema (silent mapping bugs).

## Notes

- WhatsApp destination may later be prefilled from Zavu `from_number` — not required on pure web MVP
- Disclaimer near selector can reference “te enviaremos…” using [[CS-297]]

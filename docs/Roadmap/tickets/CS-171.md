# CS-171 — Property-based tests: asymmetric penalty invariant

## Context

Asymmetric penalty is a **global monotonicity invariant**: improving buyer-facing economics vs benchmark never lowers the numeric score returned by the affected criterion helpers ([[RUBRICA_CONTRATO]] §1.1). Property tests fuzz numeric neighborhoods to catch regressions table tests miss.

## Scope

**In:**
- Hypothesis (or rapidcheck equivalent) suites generating constrained tuples for **B1/B2/B4** domains plus optional **term** dimension where rubric ties improvement to non-worse score
- Invariant: `score(raw worse inputs) ≤ score(raw better inputs)` after clamp pipeline ([[CS-153]])
- Shrinking enabled for minimal counterexample reporting

**Out (explicit):**
- LLM stochastic evaluation — fuzz deterministic post-processing only

## Acceptance criteria

- [ ] Minimum **2000** iterations per metric domain without violation on CI nightly (PR smoke subset ≥200 seeds)
- [ ] Counterexample prints structured diff: benchmark segment, raw scores pre/post clamp
- [ ] Property excludes ranges marked `invalid` by F5 validators (non-positive prices)

### BVA — boundary value analysis (seed anchors feeding generator)

| Domain | Favorable direction | Swept neighborhood |
|---|---|---|
| Down payment % | decrease toward benchmark−Δ | ±2 pp around each rubric stair |
| APR | −Δ pp | ±0.25 pp steps across 7–22% |
| Total cost multiple | −Δ× | ±0.05 around {1.45,1.79,1.99,2.49} |
| Term (B3) | shorter compatible term | edge near IVU 30y legality |

| Contract type filter | Boundary | Expected |
|---|---|---|
| CVC | generator skips financed tuple | no-op |
| CVP | full tuple | invariant applies |

## Test intent (Rule 9)

Monotonicity encodes **consumer protection posture** — a clever normalization that penalizes unusually good rates must trip fuzz suite ([[PRD_GENERAL]] §1 Art. 1686 framing).

# CS-333 — Enforce TLS-only transport (API, web, integrations)

## Context

[[PRD_GENERAL]] §5 requires **TLS for all communications**. This ticket encodes posture as code/config: terminating proxies, redirects, webhook clients, SMTP/WhatsApp egress (where applicable under F7) must refuse cleartext in production-equivalent environments.

## Scope

**In:**
- `https` redirects for Next.js/Vercel and API gateway (Railway/Fly/other) documented as IaC/README steps
- Outbound HTTP clients default to TLS verification **on**; env allows dev-only insecure override narrowly scoped (`ALLOW_INSECURE_TLS_DEV_ONLY=false` default prod)
- Zavu/email provider connections verified as TLS-capable URLs in config validators
- Health check probes that differentiate “listening” vs “TLS misconfigured” (smoke checklist)

**Out (explicit):**
- mTLS everywhere (possible future hardening)

## Acceptance criteria

- [ ] Given production profile env, HTTP→HTTPS redirect resolves for web and `/health`
- [ ] Given BE attempts `http://` internal call in prod profile, bootstrap **fails fast** at startup validator with explicit error
- [ ] Given webhook registration script, emitted callback URLs must be `https` when `DEPLOY_STAGE=production`
- [ ] Certificate expiry monitoring documented (minimum: provider-managed renewal + calendar owner)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `DEPLOY_STAGE` | `development` vs `production` | dev may use local http only on loopback paths listed in allowlist doc |
| TLS verify | CA bundle missing container | prod startup fails loudly (no silent `verify=false`) |
| Min TLS version | 1.2 vs 1.3 policy | handshake below policy threshold rejected at edge (vendor setting captured in checklist) |

## Test intent (Rule 9)

Encodes §5 TLS promise: flipping a staging profile to insecure transport without changing allowlists must trip automated checks intended for prod-parity pipelines.

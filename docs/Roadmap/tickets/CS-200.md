# CS-200 — Build Jinja report shell with eight sections

## Context

F6 converts structured `ContractAnalysis` into user-facing HTML that downstream channels reuse ([[PRD_F6_GENERACION_REPORTE]] §3 US-01). This ticket lays out the invariant document shell: eight sections prescribed in [[RUBRICA_CONTRATO]] §11.1, self-contained markup, and hook points for subsection tickets — without baking section-specific visuals yet ([[FEATURES_MAP]] F6).

## Scope

**In:**
- Jinja2 layout (e.g. `templates/report/v1/full.html.j2`) that emits all eight semantic regions in order: header, verdict, economic, categories, findings, legal references, suggested actions, footer
- `lang="es"`, viewport meta, `meta name="robots" content="noindex, nofollow"` per [[PRD_F6_GENERACION_REPORTE]] §3 US-01 HTML sketch
- Self-contained styling: embedded `<style>` block (tokens only; tokens may be placeholders until CSS lands in subsection tickets)
- Inline `<script>` stub limited to expand/collapse behavior per [[PRD_GENERAL]] BR-13 (**no external** JS/CDN/fonts/images per BR-14)
- Parallel skeleton for reduced output when analysis is anonymized (`anonymized.html.j2`) with the same inclusion contract as [[PRD_F6_GENERACION_REPORTE]] §3 US-08
- Internal-only contract: `generate_report_html(analysis_id, options)` is implemented or stubbed behind a facade that resolves `ContractAnalysis`, rejects missing / `pending` / `failed` rows, and selects full vs anonymized template per PRD §3 US-01/US-08

**Out (explicit):**
- Populating section-specific layout, disclaimers beyond placeholder comments, SVG charts, PDF pipeline, LLM-backed copy (handled in [[CS-201]]–[[CS-208]], [[CS-209]], [[PRD_F6_GENERACION_REPORTE]] §8)
- Public HTTP endpoints (F7) and persistence of rendered HTML/PDF ([[PRD_GENERAL]] BR-01)

## Acceptance criteria

- [ ] Given a completed mock `ContractAnalysis` fixture, rendering the template emits HTML whose DOM carries eight top-level landmarks matching §11 section order (`header`/`.cs-header`, verdict, economic, categories, findings, legal-refs, actions, footer) traceable without ambiguity
- [ ] Given `<script>` in the emitted HTML, a static audit shows **no** `src=` pointing off-origin and **no** `import`/`fetch`/WebSocket strings (inline expand/collapse only)
- [ ] Given anonymized fixture (`anonymized_at` set), the generator resolves the anonymized template path without rendering full per-criterion detail blocks intended for §4–§5 under [[PRD_F6_GENERACION_REPORTE]] §3 US-08
- [ ] Given unknown `analysis_id`, the façade returns an explicit typed error distinguishable from "not ready" states

### BVA — boundary value analysis

| Case | Boundary | Expected |
|---|---|---|
| Analysis state | `pending` ↔ `completed` (`failed` edge treated like not ready) | `pending`/`failed`: error; completed: renders |
| Output mode | `anonymized_at IS NULL` vs `NOT NULL` | NULL: full skeleton; anonymized: reduced skeleton |

## Test intent (Rule 9)

The eight-section sequencing is contractual output shape from [[RUBRICA_CONTRATO]] §11.1, not stylistic preference; regressions must fail if sections are merged, reordered, or dropped even when mock data stays green.

- Dependencies on finalized `ContractAnalysis` shape are satisfied by upstream rubric schemas and synthesis contracts ([[CS-150]], [[CS-165]]).

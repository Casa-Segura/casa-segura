# CS-330 — Emit pipeline observability metrics (no PII)

## Context

Production operation requires anonymous aggregate telemetry: latency per stage, OCR outcomes, leasing reclassification, scoring and overrides, and contract-type mix ([[PRD_GENERAL]] §5). This complements F8 observability hooks on DB health jobs ([[PRD_F8]]) while keeping the privacy contract: metrics must never carry user-identifying or per-contract descriptive content ([[ARCHITECTURE]] §10 aligns with posture).

## Scope

**In:**
- A single backend instrumentation surface (middleware + stage spans or timers) emitting **counters/histograms** for: ingestion → OCR/text extraction → classification → (optional project verification if enabled separately) → economic → rubric/RAG → report → delivery enqueue
- **OCR success** outcome enum rate (success / partial / failure) without storing filenames or payloads
- **Leasing reclassification rate** (`contract_type_reclassified=true` fraction of completed analyses where type ∈ purchase/lease family)
- **Score distribution** and **override frequency** (aggregate counts/histogram buckets on `score_total` and override codes — codes only, no clause text)
- **Contract type distribution** over finalized `contract_type`
- Labels restricted to coarse enums (environment, deployment id, outcome class); **no** raw `project_name_normalized`, hashes of uploads tied to timelines, IPs, emails, phones, or request bodies

**Out (explicit):**
- Dashboards wired in a specific vendor UI (ticket leaves vendor-agnostic exposition; may be follow-up)
- Per-user timelines, funnel analytics, or content-derived dimensions
- Storing billboard image bytes or extracted free text (EPIC-12 handles that flow separately when enabled)

## Acceptance criteria

- [ ] Given a completed contract analysis path, when metrics are scraped or pushed, then **latency histograms exist per named pipeline stage** with no label containing text from the contract
- [ ] Given analyses over a window, when OCR metrics are queried, then **success vs failure rates** reflect terminal OCR states without filenames or OCR text payloads
- [ ] Given mixed contract types including reclassified LEA, when aggregating, **reclassification numerator/denominator** matches DB truth on a sampled validation query (counts only)
- [ ] Given completed analyses, **override frequency** and **contract_type distribution** match SQL rollups on `override_triggered` / `contract_type` in staging (no joins to PII-bearing columns)
- [ ] Metrics schema is documented with the explicit **disallowed label list** (PII/content) and reviewers can grep for forbidden keys in code
- [ ] Operational **alert rules** tie to thresholds documented in this ticket’s BVA (even if alerting is wired in infra later, the thresholds are Product-owned constants in repo)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| P95 latency | 89 s vs 90 s vs 91 s (PRD SLA) | Alert fires at ≥90 s sustained window per agreed burn rate |
| OCR outcome | transition success→failure on forced bad input fixture | OCR failure counter increments, no blob fields in event |
| Reclassification denominator | analyses with NOT_CLASSIFIABLE | excluded from reclassification rate (documented exclusion) |
| Histogram bucket | score_total = 4.9 / 5.0 / 7.9 / 8.0 | lands in buckets consistent with rubric bands for distribution charts |
| Label hygiene | attempted `project_normalized` tag | exporter rejects/masks at compile or runtime test |

## Test intent (Rule 9)

A correct test proves that telemetry stays **anonymous and aggregate** while still answering operations questions posed in [[PRD_GENERAL]] §5; changing a metric to attach `submission_hash`, party names, or clause snippets must fail CI.

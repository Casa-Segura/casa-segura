# CS-356 — `PROJECT_VERIFICATION_ENABLED` deployment gate

## Context

Billboard/manual verification is optional infrastructure; deployments must disable partial surfaces safely during MVP rollouts ([[EPIC-12]], [[STATUS_RECONCILIATION]]). Single env boolean controls FE routes + BE handlers.

## Scope

**In:**
- Env var contract documented in README/ops appendix: `PROJECT_VERIFICATION_ENABLED` (`true`|`false`), parsed at startup
- Django URLconf registers feature views versus 404/error stubs pattern; Next.js hides nav entry + guarded dynamic routes returning friendly “feature unavailable” stub page with HTTP 404 so disabled optional flows do not look like expired resources
- Config validation forbids enabling reputation adapter without completeness review flag (tie optional boolean `PROJECT_REPUTATION_ADAPTER_READY`)

**Out (explicit):**
- Canary percentage routing (future)

## Acceptance criteria

- [x] Gate matrix + readiness probes documented in [`docs/guides/project-verification-fe-be-gates.md`](../../../guides/project-verification-fe-be-gates.md); **Vitest (`frontend/src/lib/project-verification-env.test.ts`) + pytest (`backend/tests/test_project_verification_stubs.py`, `backend/tests/test_project_verification_checks.py`)** freeze the four UX pairings `{FE⨯BE gates}` narrative.
- [x] Disabled billboard/manual/demo routes return deterministic CS‑009 bodies with **`error_code: project_verification_disabled`** and no billboard persistence (`CS-009` envelopes — not `{code:…}` payloads).
- [x] App Router hides `/verificacion-proyecto` with `not-found` + **`export const dynamic = "force-dynamic"`** so prefetch does not hydrate disabled bundles.
- [x] `manage.py check` enforces **`PROJECT_REPUTATION_ADAPTER_READY` + provider wiring** (`project_verification.checks`; **E001/E002**) before reputational HTTP lookups can activate.

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| Env string parsing | `"True"`, `"1"`, `"false"`, malformed | canonical truth table documented; malformed fails startup |
| Hot reload dev | toggle without restart | documented unsupported path or dev shim clearly labeled |
| Default prod | unspecified var | resolves to **`false`** (safe closed) absent explicit ops override |

## Test intent (Rule 9)

Prevents leaked half-enabled flows that confuse users—flag interpretation is **deployment correctness**, not stylistic toggle; tests freeze default-off posture per EPIC rationale.

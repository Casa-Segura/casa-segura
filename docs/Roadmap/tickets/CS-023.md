# CS-023 — Schema: Project entity

## Context

`Project` is the aggregation key for anonymized intelligence across analyses ([[DOMAIN_MODEL]] §3.1; [[PRD_GENERAL]] US-06). This ticket migrates and models the `project` table per PRD DDL, including aggregate columns and `metadata` JSON for placeholder flags.

## Scope

**In:**
- Django migration creating `project` with columns, defaults, and indexes per [[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] §5.1 (`idx_project_normalized`, `idx_project_last_analyzed`)
- Django model (`models.Model`) matching DOMAIN field types (`avg_score` precision, `score_distribution` JSONField shape default zeros)
- Check constraints mirroring DOMAIN: `metadata` must not embed PII (document enforcement approach—application-level validation hook or JSON schema guard stub)
- Foreign-key preparation: none inbound yet; outbound referenced by [[CS-024]]

**Out (explicit):**
- Normalization logic — [[CS-031]]
- Metric recompute jobs — [[EPIC-09-retention-privacy]]
- Triggering aggregates on insert — feature epics; schema only here

## Acceptance criteria

- [x] Given migration applied, when inserting a row with required fields, when querying by `normalized_name`, then UNIQUE constraint enforces deduplication
- [x] Given ORM model, when instantiating with valid payload, when flushing to DB, then round-trip preserves `score_distribution` JSON keys `green|yellow|red`
- [x] Given missing optional `avg_score`, when insert occurs, then SQL allows NULL consistent with DOMAIN (“moving average” not yet computed)
- [x] Given `last_recomputed_at` column, when row created, then initial NULL is allowed and documented as “not yet recomputed”
- [ ] Given privacy rule “no PII in metadata”, when a developer unit test attempts to persist forbidden keys (optional automated test), then validation fails with explicit error code (stub acceptable if documented follow-up ties to service layer)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `total_analyses` | negative insert | DB rejects (`CHECK` or app validation) |
| `avg_score` | 10.0 vs 10.04 rounding | NUMERIC(3,1) rounds per DB semantics; document behavior |

## Test intent (Rule 9)

Wrong uniqueness key or missing `normalized_name` unique index breaks project matching; tests must fail if the DB ever allows duplicate normalized slugs.

## Notes

- Coordinate placeholder semantics `metadata.placeholder=true` with [[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] US-02/BR-07 later—schema must store arbitrary JSON safely.
- `last_analyzed` is NOT NULL in PRD DDL—migration must set sensible default on insert path (e.g. equal to `first_seen`).

## Status — 2026-05-15

**Implemented:**
- `Project` model with UUID PK, `canonical_name`, `normalized_name` (unique), `first_seen` (auto_now_add), `last_analyzed`, `total_analyses` (PositiveIntegerField default 0), `avg_score` NUMERIC(3,1) nullable, `score_distribution` JSONField default `dict`, `metadata` JSONField default `dict`, `last_recomputed_at` nullable — `backend/platform_core/infrastructure/django/models.py::Project` (commit `02fac1f`).
- Indexes `idx_project_normalized`, `idx_project_last_analyzed` — same file lines 89-92.
- Migration applied — `backend/platform_core/infrastructure/django/migrations/0001_initial.py` lines 163-225; live DB shows `project` table.
- Round-trip JSON preservation guaranteed by `JSONField` (Django built-in).
- `avg_score` nullable + `last_recomputed_at` nullable enforced by `null=True, blank=True`.

**Partial / Missing:**
- PII-in-metadata guard: enforced only by `help_text` ("must never contain PII"). No application-level validator, no `CHECK`, no service-layer hook. The acceptance bullet explicitly allows a stub but requires a documented follow-up — that follow-up doesn't exist as a ticket.
- `last_analyzed` is NOT NULL in the model (no default supplied); the ticket Notes flagged that the migration should provide a sensible default. Currently every `Project` insert must explicitly supply `last_analyzed`.
- `total_analyses` uses `PositiveIntegerField` (DB-level non-negative via Django's check); no explicit CHECK constraint name.

**Follow-ups:**
- Add a PII-guard validator on `Project.metadata` (or open a follow-up ticket) and wire it through the upsert service layer that lands in F2.
- Add `last_analyzed` default-on-insert behavior (model `default=` or service-layer init from `first_seen`).

# CS-055 — Add Tesseract Spanish OCR fallback path

## Context

When OpenRouter vision is throttled or fails en masse, **local Tesseract** (`spa`) is the free fallback ([[BE-SERVICES]] §3.3, `OCR_FALLBACK_ENABLED`, `TESSERACT_LANG=spa`). [[PRD_F1_INGESTA_Y_OCR]] §US-07 defines activation rules, per-page **30s** timeout, and **minimum confidence 60** from `image_to_data`.

Under the Pixtral pivot (see [[CS-054]]) the orchestrator only routes to Tesseract for **image** MIME inputs that Pixtral could not process; PDF rasterization remains explicitly out of scope this phase.

## Scope

**In:**

- Wire `pytesseract` + system Tesseract with Spanish traineddata.
- Gate activation:
  - (a) Pixtral failure on image MIME inputs (auto-fallback chained in `upload_service._attempt_extraction`).
  - (b) Direct routing when `force_strategy=tesseract` ([[CS-052]]).
- Compute **average confidence** across recognised words (Tesseract layout-box placeholders `-1` are excluded); if **< 60**, mark OCR job failed (submission follows [[CS-056]] outcomes) with `LOW_CONFIDENCE_OCR`.
- Honor `OCR_TESSERACT_ENABLED=false`: short-circuit before invoking `pytesseract`.
- Environment alignment: prefer names from PRD (`OCR_TESSERACT_*`) mapping to deployment (`OCR_FALLBACK_ENABLED`, `TESSERACT_LANG` from [[BE-SERVICES]] §9) documented in README for ops — no user-facing Markdown files unless ops ticket requests.

**Out (explicit):**

- PDF rasterization (`pdf2image`) — deliberately removed under the Pixtral pivot; Tesseract only handles image MIME inputs.
- Training custom OCR models or shipping `spa.traineddata` in repo licensing review (must document install path).
- Light preprocessing (grayscale, Otsu) — Phase 2.
- `OCR_COST_SAVER_MODE` toggle to bias vision vs Tesseract — Phase 2.

## Acceptance criteria

- [x] Given `OCR_TESSERACT_ENABLED=false`, when fallback would trigger, then system **does not** invoke `pytesseract` and surfaces `OCR_UNAVAILABLE`.
- [x] Given simulated vision outage and enabled fallback, when fallback runs on a deterministic synthetic image fixture, then `OcrJob.strategy=tesseract`, `tokens_consumed` null, `cost_estimate_cents` null ([[DOMAIN_MODEL]] §4.2).
- [x] Given pytesseract reports per-word confidences yielding **mean 59.9**, when averaged across recognised words (ignoring `-1` layout placeholders), then job **fails** with `LOW_CONFIDENCE_OCR`; at **60.0** passes (PRD §US-07 comparator `>= 60`).
- [x] Logs contain **no** full OCR text at INFO/DEBUG defaults.

### BVA — boundary value analysis

| Metric | Boundary | Expected |
|---|---|---|
| Mean OCR confidence | 59.9 / 60.0 / 60.1 | Strict PRD comparator: `<60` fails; `≥60` success |
| Layout placeholder `-1` | excluded from mean | Layout-only boxes do not dilute the gate |
| Activation | Pixtral failure on image / force_strategy=tesseract | Both reach the extractor; PDF path stays Pixtral-only |

## Test intent (Rule 9)

The **confidence threshold** prevents shipping gibberish "success" OCR that fails Salvadoran renters downstream — tests anchor to the PRD numeric cutoff and the **mean-of-recognised-words** semantic, not a "non-empty string" check.

## Status — 2026-05-16

Closed after the EPIC-02 audit against commit `70b75ba`.

**Shipped implementation:**

- `extract_via_tesseract(file_bytes, content_type) -> ExtractionResult` in `backend/ingestion/application/ocr/extractors/tesseract.py`.
- Confidence aggregation is now **mean of recognised words** (PRD §US-07 AC3). Tesseract's `-1` placeholder rows (layout boxes without recognised glyphs) are excluded so they don't pull the mean down artificially. If the mean is below `OCR_TESSERACT_MIN_CONFIDENCE` (default 60), the extractor raises `NotAnalyzableError(LOW_CONFIDENCE_OCR)` with the computed mean in the message for debugging.
- Lazy import of `pytesseract` + `PIL.Image` — raises `NotAnalyzableError(OCR_UNAVAILABLE)` when binary or Python lib is missing.
- `OCR_TESSERACT_ENABLED=False` short-circuits with `OCR_UNAVAILABLE`.
- `OcrJob` rows: `strategy=tesseract`, `tokens_consumed=None`, `cost_estimate_cents=None`.
- Auto-fallback wired from CS-054 when an **image** vision call fails (chained inside `_attempt_extraction`).

**Tests (hermetic, no real Tesseract binary):**

- `backend/tests/test_ingestion_tesseract.py`:
  - `test_mean_confidence_below_threshold_fails` — mean 59.9 < 60 → `LOW_CONFIDENCE_OCR`.
  - `test_mean_confidence_at_threshold_passes` — mean exactly 60.0 → success.
  - `test_mean_confidence_above_threshold_passes` — mean 60.1 → success.
  - `test_negative_conf_placeholders_excluded_from_mean` — `-1` rows ignored.
  - `test_disabled_short_circuits_before_any_pytesseract_call` — `OCR_TESSERACT_ENABLED=False` → `OCR_UNAVAILABLE` without invoking the binary.

**Deferred / out of phase:**

- PDF rasterisation path: Phase 1 deliberately keeps Tesseract image-only under the Pixtral pivot. PDF failures stop at Pixtral.
- `OCR_COST_SAVER_MODE` toggle and light preprocessing (grayscale, Otsu) — Phase 2.

# CS-030 — DB invariants: constraints, ENUM checks, pgvector + GIN indexes, audit/obs views

## Context

After tables exist, the DB must **prove** privacy and performance invariants: vector search indexes, tag GIN indexes, partial indexes for retention jobs, and operational tables/views from [[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] (privacy audit + job log + health views). This ticket closes gaps between ORM convenience and PRD DDL rigor, aligned with [[DOMAIN_MODEL]] recommended indexes.

## Scope

**In:**
- Create `legal_chunk` **HNSW** index (or IVFFlat fallback documented) on `embedding vector_cosine_ops` per PRD DDL; ensure `ANALYZE` guidance documented
- Ensure GIN indexes on `legal_chunk.tags` / `relevance_for_findings` exist if not already created in [[CS-026]]
- Partial indexes supporting jobs: `contract_analysis` pending anonymization (`anonymized_at IS NULL AND created_at < …` optional—at minimum indexes from DOMAIN §3.2), `delivery_request` queue polling index, `contract_submission` expires index sanity check
- Add tables if missing from prior tickets: `privacy_audit_log`, `job_execution_log` per PRD §5.1 with TTL defaults (`expires_at` 1y / 30d respectively)
- Create views `v_system_health` and `v_retention_status` exactly as PRD §5.2 (adjust naming to match migration conventions)

**Out (explicit):**
- Running cron jobs — [[EPIC-09-retention-privacy]]
- Prometheus — [[EPIC-11-observability]]

## Acceptance criteria

- [ ] Given sample `legal_chunk` rows with embeddings, when `EXPLAIN` on cosine similarity query using the HNSW index, then plan shows index usage (not sequential scan) on representative dev dataset
- [x] Given `privacy_audit_log` migration, when inserting each allowed `event_type`, when CHECK passes, when inserting illegal type, then rejection
- [x] Given `v_system_health` view, when executed on seeded minimal DB, then returns finite integers without error (nullable timestamps allowed)
- [ ] Given retention view, when overdue transient rows present in fixture, when view selected, then `overdue_records` > 0 (test-backed)
- [x] Given cross-table FK review checklist in PR description, when reviewer signs off, then no orphan FK targets remain undefined vs PRD §5.1 ordering

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| Anonymization horizon | `created_at = now() - 89d23h` vs `now() - 90d1m` | View `v_retention_status` counts row only after crossing 90d policy threshold ([[PRD_GENERAL]] US-07) |
| pgvector ops | cosine vs L2 | Document choice `vector_cosine_ops` consistent with retrieval function selected in [[EPIC-03-corpus-rag]] |
| Job log TTL | 30-day boundary | Rows older than `expires_at` eligible for cleanup job (future epic) |

## Test intent (Rule 9)

Missing HNSW or partial indexes will “work” until scale, then fail in production. The `EXPLAIN` criterion ties the ticket to observable query plans, not best intentions.

## Notes

- If HNSW build time is prohibitive in CI, allow reduced `m/ef_construction` in dev with documented prod values.

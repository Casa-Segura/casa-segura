# CS-352 — Permit format regex sanity validator (Salvadoran patterns)

## Context

Hackathon Flow 1 permitted a regex sanity gate on billboard-derived permit numbers[[ARCHITECTURE]] §5. EPIC‑12 keeps **format-only** checking—no registry API calls per [[PRD_GENERAL]] material verification exclusions for contract path; same caution applies here (signal is advisory).

## Scope

**In:**
- Versioned regex table in code/config with comments documenting authority classes (ministerial vs municipal placeholders)
- Validator returns enums: `format_ok`, `format_suspicious`, `format_unknown` feeding [[CS-354]]
- Unit tests anchored to curated valid/invalid fixture strings curated with legal/context owners

**Out (explicit):**
- Live OMOP/CNR verification
- Blacklist lookups (BR‑11 blacklist remains out[[PRD_GENERAL]])

## Acceptance criteria

- [ ] Public function `evaluate_permit_format(permit: str, municipality_hint?: str)` stable import path consumed by billboard + manual form paths
- [ ] Fixtures cover at least ≥5 valid patterns representing distinct authority templates agreed with domain steward
- [ ] Explainable finding text key returned for UI (machine key, localized copy downstream)
- [ ] Negative tests ensure arbitrary free text flagged `format_unknown`

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| Permit token length | shortest valid vs truncation | validates vs `format_unknown` |
| Digit-only vs alphanumeric | boundary template | aligns with canonical regex separation |
| Control chars injected | NUL / RTL override | sanitized then evaluated |
| Case fold | differing case same permit | deterministic normalization path |

## Test intent (Rule 9)

Regex validity is notoriously brittle; encoding BVA guards product from **false reassurance** shifts when municipality templates expand.

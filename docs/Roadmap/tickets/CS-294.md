# CS-294 — Result page: embed HTML report for web-link channel

## Context

For `web_link` delivery, users must view the responsive HTML report in-app after processing ([[PRD_GENERAL]] US-04, US-05). The page should sandbox/limit third-party content appropriately while matching **360px** readability requirements.

## Scope

**In:**
- Route that accepts token/`public_short_id` returned by backend for link channel (exact param per BE contract)
- Fetches HTML from BE **or** receives pre-rendered blob per API design; renders inside guarded container (`iframe` **or** sanitized HTML policy—choose in implementation per security review)
- Shows headline + meta: short ID, expiration date if provided
- Reuses [[CS-297]] disclaimer surfaced adjacent to viewer chrome

**Out (explicit):**
- PDF binary preview client-side
- Offline caching / PWA

## Acceptance criteria

- [ ] Given a successful `web_link` analysis, when user opens result URL, then report HTML renders without horizontal scroll at **360px** width except intentional wide tables that expose horizontal scroll **only** inside table container
- [ ] Given backend sets `Content-Security-Policy` requirements, when integrated, then frontend obeys documented embedding approach (no unsafe `eval`)
- [ ] Given missing/expired link handling, when BE returns 404/410 or status field `expired`, when UI routes, then user lands on [[CS-295]] experience (no blank screen)
- [ ] Given `anonymized` analyses if still viewable per policy, when rendered, then template matches F6 anonymized variant without throwing client errors
- [ ] Given print attempt, when user prints, then browser print layout degrades gracefully (no requirement for pixel-perfect print here)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| Channel enum | `web_link` vs others | Result viewer only required for link path; email/WhatsApp flows may deep-link here **if** product chooses—document |
| Viewport | **360px** vs 480px | Core content readable; tap targets preserved |
| HTML size | very large report | Page remains responsive; no main-thread lock beyond browser norms |

## Test intent (Rule 9)

This screen is where legal disclaimers and citations meet the user—**XSS or broken mobile layout** undermines trust and liability posture. Tests must fail if unsanitized HTML is injected or if expired links render partial PII leaks.

## Notes

- **Security:** iframe + `sandbox` attribute set is default recommendation pending BE snippet review
- Coordinate caching headers with F7 so FE doesn’t serve stale beyond link TTL

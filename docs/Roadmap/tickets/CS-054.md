# CS-054 — Extract scans and images via vision LLM (per page)

## Context

Photos and scanned PDFs need **vision OCR** for accuracy. [[PRD_F1_INGESTA_Y_OCR]] §US-06 defines rasterization (PDF → JPEG at configurable DPI default **150**), per-page sequential calls via OpenRouter, **60s** per-page timeouts, retries (**2**) with backoff (**1s, 4s**), partial failure threshold **30%**, and **5 minute** overall vision budget.

## Scope

**In:**

- PDF: `pdf2image` rasterize each page; images: HEIC/WEBP convert to JPEG as needed; clamp longer side default **1920px** (`OCR_VISION_MAX_IMAGE_DIM_PX`).
- OpenRouter vision calls using prompt from [[PRD_F1_INGESTA_Y_OCR]] §8.1; strip meta-commentary retry per §8.2.
- Series processing (not parallel) to control cost — configurable override only if product approves.
- Idempotency header per [[PRD_F1_INGESTA_Y_OCR]] BR-05 pattern `submission_id:page_number:strategy:attempt_number`.
- Persist `tokens_consumed` / `cost_estimate_cents` on `OcrJob` rows; never log raw model output containing full contract contents at INFO (use truncation + hash).
- If **>30%** pages fail after retries, trigger policy: mark submission extraction failure **and** if `OCR_TESSERACT_ENABLED`/`OCR_FALLBACK_ENABLED` aligns, enqueue [[CS-055]] fallback.

**Out (explicit):**

- Implementing EPIC-00 LLM gateway if missing — tracked under [[EPIC-00-foundation]] / [[CS-006]] (OpenRouter baseline).
- Cost table maintenance process — stub with config file version in notes only.

## Acceptance criteria

- [ ] Given a 4-page scanned PDF fixture, when vision path runs in CI (mock OpenRouterTransport), then **four** sequential calls occur with ascending `page_number` and consolidated separators `--- PAGE N ---`.
- [ ] Given a transient 429 from provider, when per-page retries exhaust **2**, then backoff sleeps match **1s** then **4s** (wall-clock tested with fake timer).
- [ ] Given **30%** failure rate boundary on a 10-page doc (exactly **3** pages fail permanently, 7 succeed), when evaluated, then submission follows PRD “continue vs fail full” rule: **at most 30% fail** means **3/10 = 30%** — tests must encode whether **strictly greater than** 30% triggers failure (PRD wording: “more than 30%”).
- [ ] Given per-page processing > **60s**, when watchdog triggers, then page marked failed and contributes to failure accounting.
- [ ] Given total vision runtime > **5 minutes**, when global timeout hits, then submission ends in `failed_extraction` with `TIMEOUT_EXCEEDED` mapping per [[PRD_F1_INGESTA_Y_OCR]] BR-07 / §7.4.

### BVA — boundary value analysis

| Parameter | Boundary | Expected |
|---|---|---|
| Partial failure rate | 3/10 fail vs 4/10 fail | On 10 pages, 3 fails = 30%; PRD says “more than 30%” fails → 4/10 should trigger full failure path + tesseract if enabled |
| Per-page timeout | 60s | Exceed → page failure |
| Global vision timeout | 5 min | Exceed → `TIMEOUT_EXCEEDED` |
| Retries | 0/1/2 attempts | Exponential backoff applied only on transient errors |

## Test intent (Rule 9)

Verify **retry + timeout + partial-failure accounting** as cost/risk controls — the product fails if we silently drop failed pages or parallelize without guardrails.

## Status — 2026-05-16

Audit against commit `d613c2d`. **Architectural pivot**: per user directive (Pixtral Large 2411 + OpenRouter `file-parser` plugin with `mistral-ocr` engine), the implementation handles PDFs in a **single multimodal call** instead of the PRD's rasterize-then-per-page-vision flow. Several PRD AC are therefore obsolete and need to be rewritten on the next PRD pass before this ticket can flip to `done`.

**Implemented (new architecture):**

- `extract_via_pixtral(file_bytes, content_type, filename)` in `backend/ingestion/application/ocr/extractors/pixtral.py` — single `chat/completions` call with model `OPENROUTER_OCR_MODEL` (default `mistralai/pixtral-large-2411`).
- Payload split by MIME: images (`image/jpeg|png|webp|heic`) use `{"type": "image_url"}` block with `data:{mime};base64,{b64}` URL; PDFs (`application/pdf`) use `{"type": "file", "file": {filename, file_data}}` block + root `plugins=[{id: "file-parser", pdf: {engine: settings.OPENROUTER_PDF_PLUGIN_ENGINE}}]`.
- Cliente OpenRouter común: `backend/shared/llm/openrouter.py` con headers `Authorization`/`HTTP-Referer`/`X-Title`, retry/backoff exponencial (1s, 2s, 4s capped at 8s) sobre `5xx` y errores de transporte, mockeable via `respx`.
- OcrJob row records `tokens_consumed = prompt + completion` and `cost_estimate_cents` from the OpenRouter usage payload.
- Tests: `tests/test_openrouter_client.py` (retry on 5xx, 4xx no-retry, exhausted retries, header injection, plugin pass-through). `tests/test_ingestion_pixtral.py` validates the image_url vs file payload shape + plugin only-on-PDF.

**Partial / Missing (vs original PRD AC):**

- AC1 (4-page PDF → four sequential per-page calls with `--- PAGE N ---` separators) **does not apply** under the file-parser architecture — OpenRouter returns a single concatenated text. Needs PRD rewrite.
- AC2 (retry backoff 1s then 4s exactly) — current backoff is 1s, 2s, 4s (exponential capped at 8s). Slightly different schedule.
- AC3 (>30 % page-failure rate → submission failure) **does not apply** — single call has no page-level success counter.
- AC4 (per-page 60s timeout) → only a single global `OPENROUTER_TIMEOUT_SECONDS` (default 60). Behaves equivalently for short docs.
- AC5 (5-minute global vision timeout → `TIMEOUT_EXCEEDED`) not wired; would need a worker-level wall clock around `extract_via_pixtral`.
- Tesseract auto-fallback after 3 vision failures: implemented in `_attempt_extraction` only for **image** MIME inputs; PDF failures stop at vision (PRD-aligned: rasterisation is out of scope).
- `pdf2image` rasterization deliberately removed — Mistral OCR pre-parses the PDF via the plugin.

**Status:** `in_progress` — code path works end-to-end with credentials. To reach `done`, AC need re-authoring for the single-call architecture **or** add a per-page chunking layer if the PRD insists on the original flow.

# CS-054 — Extract scans and images via Pixtral (single multimodal call)

## Context

Photos and scanned PDFs need a vision-capable model for accurate text extraction. The original PRD path was *rasterize-each-PDF-page → loop per-page vision calls*. After the product / cost review on 2026-05 we pivoted the architecture to **Pixtral Large 2411** behind OpenRouter, using the `file-parser` plugin (engine `mistral-ocr`) for PDFs and a direct `image_url` content block for images. Both flows resolve in a **single `chat/completions` call**, removing the per-page failure accounting and the local rasterization step. This ticket re-anchors the acceptance criteria to the single-call architecture and is closed against the shipped implementation.

The PRD §US-06 retains its semantic contract (extract Spanish text from scans/photos within budget, never persist contract text, track cost) — only the *mechanism* of "per-page sequential calls" was rewritten under product sign-off as part of the EPIC-02 audit (see [[EPIC-02-ingestion-ocr]]).

## Scope

**In:**

- Single multimodal call to `OPENROUTER_OCR_MODEL` (default `mistralai/pixtral-large-2411`) per submission file.
- PDF payload uses an OpenRouter `file` content block with `filename` + base64 `file_data` plus a root-level `plugins=[{"id":"file-parser","pdf":{"engine":"mistral-ocr"}}]`. The plugin pre-parses the PDF (all pages) on OpenRouter's side and feeds the resulting text to Pixtral.
- Image payload (`image/jpeg|jpg|png|webp|heic`) uses a `image_url` content block with `data:{mime};base64,…`; **no** plugin block (PRD-aligned: rasterization is out of scope; Pixtral consumes raster directly).
- Spanish prompt from [[PRD_F1_INGESTA_Y_OCR]] §8.1 (faithful extraction, markdown tables, no commentary).
- Required OpenRouter tracking headers (`Authorization`, `HTTP-Referer`, `X-Title`) injected by the shared client.
- Retry/backoff on transient errors: exponential `1s → 2s → 4s` (capped at 8s) on 5xx and transport errors. 4xx responses do **not** retry.
- Auto-fallback to Tesseract on image MIME inputs when the Pixtral call fails — handled in the orchestrator (`_attempt_extraction`). PDFs that fail Pixtral surface `UPSTREAM_LLM_ERROR` without rasterization (out of scope this phase).
- Persist `OcrJob.tokens_consumed = prompt + completion` and `cost_estimate_cents` from the OpenRouter `usage` payload; never log raw model output.
- Empty file buffer → `EMPTY_FILE`; unsupported MIME → `UNSUPPORTED_FORMAT`; OpenRouter failures (after retries) → `UPSTREAM_LLM_ERROR` → `ProcessingStatus.FAILED_EXTRACTION`.

**Out (explicit):**

- Local PDF rasterization (`pdf2image`) — deliberately removed; OpenRouter `file-parser` plugin handles PDF parsing server-side.
- Per-page success/failure accounting — there are no per-page calls under this architecture.
- A 5-minute submission-level wall-clock budget around the worker — global wall-clock budget is owned by the worker-level timeout in [[CS-053]] (pypdf path) and by `OPENROUTER_TIMEOUT_SECONDS` for the LLM hop. Submission-wide budget will land if Phase 2 adds Celery (see follow-ups in [[CS-060]] notes).
- EPIC-00 LLM gateway groundwork — covered by [[CS-006]] (`shared/llm/openrouter.py`).

## Acceptance criteria

- [x] Given a PDF upload (`application/pdf`), when `extract_via_pixtral` runs, then the outbound chat completion payload contains a single `messages[0].content` array with one `text` block (Spanish prompt) and one `file` block whose `file.filename` matches the upload and `file.file_data` is `data:application/pdf;base64,…`, **and** the payload includes `plugins=[{"id":"file-parser","pdf":{"engine":<OPENROUTER_PDF_PLUGIN_ENGINE>}}]`.
- [x] Given an image upload (`image/jpeg|jpg|png|webp|heic`), when `extract_via_pixtral` runs, then the outbound payload contains one `text` block and one `image_url` block with a `data:{mime};base64,…` URL, **and no `plugins` field is sent**.
- [x] Given the OpenRouter response includes `usage`, when extraction succeeds, then `ExtractionResult.tokens_consumed == prompt_tokens + completion_tokens` and `cost_estimate_cents` is populated from `usage.cost` (rounded to whole cents).
- [x] Given two consecutive `5xx` responses followed by `200`, when the client runs with `max_retries=3`, then the request succeeds and `casa_segura_openrouter_calls_total{outcome="success"}` increments exactly once (errors are not double-counted).
- [x] Given a `4xx` response, when the client runs, then it raises `OpenRouterError` on the **first** attempt without retrying, and the extractor maps it to `NotAnalyzableError(UPSTREAM_LLM_ERROR)` (counter `outcome="error"`).
- [x] Given `extract_via_pixtral` raises `UPSTREAM_LLM_ERROR` for an **image** MIME, when the orchestrator handles the failure, then it enqueues a second attempt against `extract_via_tesseract` (image-only fallback). PDF failures **do not** chain to Tesseract.
- [x] Given a successful or failed Pixtral call, when the request completes, then the outbound payload **never** leaks the raw response content into structured logs at `INFO` (only `status_code` + `model` + `submission_id` are logged).

### BVA — boundary value analysis

| Parameter | Boundary | Expected |
|---|---|---|
| Empty file buffer | 0 bytes | `EMPTY_FILE` before any network call |
| Unsupported MIME (`text/plain`, `audio/*`) | n/a | `UNSUPPORTED_FORMAT` from `_build_payload` |
| Retry attempts | 0 / 1 / 2 / 3 attempts on 5xx | Exponential `1s → 2s → 4s`; final attempt re-raises if 5xx persists |
| Plugin presence | image (no plugin) / PDF (file-parser plugin) | Payload assertions in `test_ingestion_pixtral.py` |
| Tracking headers | All three present | `Authorization`, `HTTP-Referer`, `X-Title` injected unconditionally |

## Test intent (Rule 9)

The single-call architecture trades per-page accounting for two cost/risk controls that MUST stay locked: (a) retries fire only on transient errors so we don't melt budget on permanent 4xx bugs; (b) the plugin block is present on PDFs (and only on PDFs) so we never silently bill `mistral-ocr` for an image we already raster-fed Pixtral. Tests must fail if either invariant regresses.

## Notes

- Model default: `OPENROUTER_OCR_MODEL=mistralai/pixtral-large-2411`. Override via env when the cost board picks a cheaper SKU; the shared client doesn't hard-code the slug.
- Plugin engine: `OPENROUTER_PDF_PLUGIN_ENGINE=mistral-ocr`. Other engines exposed by OpenRouter (`pdf-text-extract`, etc.) are off the supported path until a follow-up evaluates parity.
- Tesseract auto-fallback for **PDF** inputs is intentionally **not** implemented in Phase 1 because we would need to rasterize locally, contradicting the pivot. The fallback fires only on image MIME inputs.

**Architectural deltas captured here (vs the pre-pivot PRD AC):**

- `--- PAGE N ---` per-call separators no longer apply: `file-parser` returns concatenated text from all pages of the PDF.
- Per-page 60s and global 5-minute timeouts collapse into a single `OPENROUTER_TIMEOUT_SECONDS` (default 60s) covering the multimodal call. A submission-level wall-clock budget is parked for the Phase 2 Celery refactor (tracked in [[CS-060]] notes).
- The PRD "more than 30%" per-page failure rule is moot under one call: the call either succeeds or fails; failure on images triggers Tesseract fallback, failure on PDFs surfaces `UPSTREAM_LLM_ERROR`.

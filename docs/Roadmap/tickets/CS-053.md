# CS-053 — Extract text from text-layer PDFs with pypdf

## Context

Text-layer PDFs should extract **without** vision spend. [[PRD_F1_INGESTA_Y_OCR]] §US-05 mandates pypdf iteration, page separators, normalization, token counting, short-text fallback to vision, and a **30s** hard timeout.

## Scope

**In:**

- `pypdf` full-document extraction for files classified as text PDFs ([[CS-052]]).
- Concatenate pages with `--- PAGE N ---` 1-indexed headers exactly as PRD.
- Normalize whitespace and strip non-printable control characters while preserving meaningful newlines (`\r\n` → `\n`, NBSP → space, soft-hyphen / zero-width-space stripped, C0/C1 control bytes dropped while keeping `\n` and `\t`).
- Estimate tokens with `tiktoken` `cl100k_base` into `ContractSubmission.extracted_text_token_count` (count only; **no text persisted** per [[PRD_F1_INGESTA_Y_OCR]] BR-02 / [[DOMAIN_MODEL]] §4.1).
- If total extracted characters **after normalization < 500**, raise `NotAnalyzableReason.LOW_CONFIDENCE_OCR`; the orchestrator catches this and escalates to vision per PRD §US-05 BR-08.
- Enforce **30 second** wall-clock timeout via per-page `time.perf_counter()` check → `NotAnalyzableReason.TIMEOUT`. The orchestrator increments `casa_segura_ingest_timeouts_total{stage=extract,strategy=pypdf}` (CS-060).
- Create/update `OcrJob` rows: `strategy=pypdf`, `tokens_consumed=0`, `cost_estimate_cents=0`, `status=success|failed|timeout` (wired in `upload_service._attempt_extraction`).

**Out (explicit):**

- Vision LLM invocation — [[CS-054]].
- Language detection — handled where pipeline defines (see [[CS-056]] coupling).

## Acceptance criteria

- [x] Given a synthetic PDF fixture with stable known text spanning **3 pages**, when extracted, then output contains **`--- PAGE 1 ---` … `PAGE 3`** markers in order without missing pages (`test_three_page_pdf_emits_page_markers_in_order`).
- [x] Given extracted text totaling **< 500** characters post-normalization, when pypdf completes, then the orchestrator transitions to vision strategy attempt and records pypdf as insufficient (not "success end state") — covered by `test_pypdf_below_500_chars_raises_low_confidence` (unit) and `test_orchestrator_escalates_pypdf_low_confidence_to_vision` (integration).
- [x] Given extraction exceeding **30 seconds** (simulate with monkeypatch `time.perf_counter`), when watchdog fires, then `OcrJob.status` records timeout and user-facing path surfaces `not_analyzable` / technical code per failure policy ([[CS-056]]) — `test_watchdog_fires_when_pypdf_exceeds_30s`.
- [x] Given successful extraction, when persisted fields are written, then **no column** stores raw extracted text; only counts and statuses exist (CS-057 invariant + meta-test).
- [x] Whitespace / control-char normalization (NBSP, `\r\n`, soft hyphen, zero-width space, C0 control bytes) — parametric test `test_normalize_text_handles_whitespace_and_controls`.

### BVA — boundary value analysis

| Measure | Boundary | Expected |
|---|---|---|
| Post-normalization char count | < 500 / ≥ 500 | <500 triggers vision retry per PRD; ≥500 allows success if other gates pass |
| Timeout | < 30s / > 30s | Per-page wall-clock check; >30s raises NotAnalyzableReason.TIMEOUT |
| Pages | 1 / max allowed (50 per PRD per file gate) | Linear time behavior documented; failures surfaced before pypdf when page count rejects at [[CS-059]] |

## Test intent (Rule 9)

The **500-character minimum** is an OCR-quality sentinel; tests fail if someone "optimizes away" the retry and lets garbage text reach classification ([[PRD_F1_INGESTA_Y_OCR]] BR-08).

## Notes

- Keep extraction outputs **only in memory** until handed to downstream queue ([[PRD_F1_INGESTA_Y_OCR]] §6.3).
- The watchdog is granular per-page rather than thread-based so it stays portable (no `signal.alarm` Unix dependency) and avoids spinning up a worker just to wrap pypdf.
- Wikilinks: [[EPIC-02-ingestion-ocr]], [[CS-054]], [[CS-057]], [[CS-060]].

## Status — 2026-05-16

Closed after the EPIC-02 audit against commit `1d2d33b`.

**Shipped implementation:**

- `backend/ingestion/application/ocr/extractors/pypdf_extractor.py` rewritten:
  - `PAGE_HEADER_TEMPLATE = "--- PAGE {n} ---"` with 1-indexed numbering; each page text is prefixed with the header and `\n\n` and the parts are joined with `\n\n`.
  - `_normalize_text` — NFKC fold + `\r\n` → `\n` + NBSP/soft-hyphen/zero-width-space → drop + C0/C1 control regex (preserving `\n` / `\t`).
  - `PYPDF_TIMEOUT_SECONDS = 30` per-page wall-clock check between page iterations.
  - `PYPDF_MIN_CHARS = 500` floor — normalized text below the threshold raises `NotAnalyzableReason.LOW_CONFIDENCE_OCR` with the actual char count in the message.
- `backend/ingestion/application/upload_service.py::_attempt_extraction`:
  - Loop converted from `for strategy in order` to a while-pop pattern with a `visited` set so we can append `VISION_LLM` to the order when PYPDF raises `LOW_CONFIDENCE_OCR`. The escalation is idempotent (visited-guarded) so a subsequent VISION_LLM failure does not loop.

**Tests (hermetic, no real pypdf reader):**

  - `test_watchdog_fires_when_pypdf_exceeds_30s` — monkeypatch `time.perf_counter` to jump past the watchdog mid-iteration; asserts `NotAnalyzableReason.TIMEOUT`.
  - `test_pypdf_below_500_chars_raises_low_confidence` — short text → `LOW_CONFIDENCE_OCR` with `< 500` in the message.
  - `test_orchestrator_escalates_pypdf_low_confidence_to_vision` — `_run_extractor` is patched so PYPDF raises and VISION_LLM succeeds; asserts orchestrator made 2 attempts and `extraction_strategy_successful == vision_llm`.

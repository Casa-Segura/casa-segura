# CS-090 — Operationalize CorpusVersion + latest_active pinning

## Context

Reports and analyses reference immutable corpus snapshots. [[DOMAIN_MODEL]] §3.4 + [[PRD_F3_CORPUS_Y_RAG]] §US-05 mandate `CorpusVersion` rows uniquely marked active, manifest integrity counts, changelog text, reproducible citations when regenerating downstream outputs ([[PRD_GENERAL]] report footer corpus version bullet).

## Scope

**In:**

- Extend ingestion CLI (`corpus activate --version TAG`) toggling exclusive `is_active` flag enforcing partial unique index from PRD (only one `TRUE`).
- Persist manifest summary fields: counts for laws/articles/chunks, released_at timestamps, authoring metadata optional.
- Backend config service reading `latest_active` efficiently (could cache Redis 60s TTL) consumed by retrieval path ([[CS-085]]) and future analysis writer ensuring `ContractAnalysis.corpus_version` string recorded at finalize time (**implementation may land EPIC-04/06**, but expose API getter now + integration stub test).
- Emit structured audit record (DB table or stdout JSON line) whenever activation flips referencing operator subject from env `DEPLOY_JOB_NAME`.
- Document rollback path: activating prior version permissible if ingestion flaw discovered (<5 minute operational SOP textual comment in CLI help acceptable).

**Out:**

- Frontend UI selectors for corpus versions.

## Acceptance criteria

- [ ] Migrational constraint ensuring **exactly zero or one** `is_active=TRUE` holding at steady state validated via DB constraint + transaction-level locks around activation mutation.
- [ ] Activation attempt referencing nonexistent version exits non-zero with crisp error string.
- [ ] Harness test verifying retrieval resolves `latest_active` alias identical to pinned explicit version immediately post-activation.
- [ ] `ContractAnalysis`-bound placeholder interface test double ensures future writer modules call `record_corpus_version()` hook (skipped if analysis tables not ready behind feature flag, but stub interface compiled).

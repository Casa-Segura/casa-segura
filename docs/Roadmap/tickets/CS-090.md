# CS-090 — Operationalize CorpusVersion + latest_active pinning

## Context

Reports and analyses reference immutable corpus snapshots. [[DOMAIN_MODEL]] §3.4 + [[PRD_F3_CORPUS_Y_RAG]] §US-05 mandate `CorpusVersion` rows uniquely marked active, manifest integrity counts, changelog text, reproducible citations when regenerating downstream outputs ([[PRD_GENERAL]] report footer corpus version bullet).

## Scope

**In:**

- Extend ingestion CLI (`corpus activate --version TAG`) toggling exclusive `is_active` flag enforcing partial unique index from PRD (only one `TRUE`).
- Persist manifest summary fields: counts for laws/articles/chunks, released_at timestamps, authoring metadata optional.
- Backend config service reading `latest_active` efficiently (could cache Redis 60s TTL) consumed by retrieval path ([[CS-085]]) and future analysis writer ensuring `ContractAnalysis.corpus_version` string recorded at finalize time (**implementation may land EPIC-04/06**, but expose API getter now + integration stub test).
- Emit structured audit record (DB table or stdout JSON line) whenever activation flips referencing operator subject from env `DEPLOY_JOB_NAME`.
- Document rollback path: activating prior version permissible if ingestion flaw discovered (<5 minute operational SOP textual comment in CLI help acceptable).

**Out:**

- Frontend UI selectors for corpus versions.

## Acceptance criteria

- [ ] Migrational constraint ensuring **exactly zero or one** `is_active=TRUE` holding at steady state validated via DB constraint + transaction-level locks around activation mutation.
- [ ] Activation attempt referencing nonexistent version exits non-zero with crisp error string.
- [ ] Harness test verifying retrieval resolves `latest_active` alias identical to pinned explicit version immediately post-activation.
- [ ] `ContractAnalysis`-bound placeholder interface test double ensures future writer modules call `record_corpus_version()` hook (skipped if analysis tables not ready behind feature flag, but stub interface compiled).

Guarantees reproducible citations across releases — mishandling `latest_active` undermines audits required by transparency commitments.

## Status — 2026-05-16

Audit against commit `d613c2d`.

**Implemented:**

- `corpus.application.version.activate(version: str) -> CorpusVersion`: wraps `select_for_update().get(pk=version)` + `objects.filter(is_active=True).exclude(pk=version).update(is_active=False)` + `target.is_active = True; target.save(update_fields=["is_active"])` inside `@transaction.atomic`.
- `latest_active() -> CorpusVersion | None` helper for the retrieval service (`LegalCitationService.__init__` defaults to it).
- `deactivate_all() -> int` helper for emergency rollback.
- DB-level `UniqueConstraint(fields=["is_active"], condition=Q(is_active=True), name="uq_corpus_version_active_singleton")` (already in `corpus/0001_initial`) — AC1 enforced.
- The `reject_catalog_mutation` trigger (CS-030) allows only `is_active` + `updated_at` to mutate post-publish, so activation respects immutability.
- `manage.py ingest_corpus --activate` invokes `activate()` after the ingestion transaction commits.
- `LegalCitationService` graceful empty when `latest_active()` returns None (logs `rag.retrieve.no_active_corpus`).

**Partial / Missing (gap vs PRD AC):**

- AC2 (activation of nonexistent version exits non-zero with crisp error): `activate()` raises `CorpusVersion.DoesNotExist`, which bubbles out as an HTTP 500 / management-command traceback. **Action**: wrap in `CommandError` for the CLI path so the message is product-grade.
- AC3 (post-activation alias resolves to pinned explicit version): no integration test exists yet. **Action**: add `tests/test_corpus_activation.py` that activates v1 then asserts `latest_active().version == "v1"` and `LegalCitationService().corpus_version == v1`.
- AC4 (`record_corpus_version()` hook on `ContractAnalysis`): the hook is **not** wired. `ContractAnalysis.corpus_version` FK exists in the schema (CS-026) but no service writes it yet — that work belongs to EPIC-06 (Rubric Engine, F4). Marked as N/A for Phase 1.
- BVA on manifest mismatch (`chunks_count != COUNT(legal_chunk WHERE corpus_version=…)`): the ingestion CLI populates `manifest` from `len(parsed_laws)` and `articles_count = chunks_count = total_chunks`, so the values are correct by construction. There's no assertion-after-load check though.

**Status:** `in_progress` — activation function ships and the constraint enforces the singleton; CLI-level error wrapping + activation integration test + EPIC-06 hook are the gating items for `done`.

# CS-150 — Define Pydantic schemas for rubric outputs

## Context

The rubric engine persists structured results into `ContractAnalysis` JSONB columns ([[DOMAIN_MODEL]] §3.2). Typed models prevent drift between F4, F6, and migrations and encode constraints such as score ranges and citation caps ([[PRD_F4_MOTOR_RUBRICA]] §5.4, BR-16).

## Scope

**In:**
- Pydantic models mirroring persisted shapes: `CriterionEvaluation`, `Finding`, `LegalReference`, `CategoryScore` (elements of `scores_by_category`), optional `RubricSnapshot` bundle used internally before persistence
- Field validation: `score` in \[0, 10\]; `evidence_snippet` / clause snippets truncated or rejected above **500 characters** with explicit truncation strategy (ellipsis, preserve start); `legal_basis` list max length **3** items ([[PRD_F4_MOTOR_RUBRICA]] US-03, BR-16)
- Enums aligned with DOMAIN_MODEL: `Band`, `Severity`, override codes as `Literal` union matching [[PRD_F4_MOTOR_RUBRICA]] US-02 table

**Out (explicit):**
- Django ORM models / DDL migrations — persistence epic
- `Criterion` row seeding / YAML catalog — [[CS-033]]
- OpenAPI exposure of internal models

## Acceptance criteria

- [ ] Given any deserialized `ContractAnalysis.criterion_evaluations[]` object conforming to production samples, validation succeeds without dropping unknown keys where backward compatibility is required (document policy: `extra = forbid` or `ignore` — pick one and apply consistently)
- [ ] Given `Finding.evidence_clause_snippet` longer than 500 chars, the model factory or validator truncates to ≤500 with documented ellipsis behavior matching [[PRD_F4_MOTOR_RUBRICA]] BR-16
- [ ] Given `LegalReference` populated from F3, all required display fields (`law_id`, `article`, `anchor`, `paraphrased_quote`) validate non-empty when list non-empty
- [ ] Given invalid numeric score `10.1` or `-0.1` on `CriterionEvaluation.score`, validation raises with field path identifiable by tests
- [ ] JSON schema or model exports round-trip from canonical fixtures committed under `tests/fixtures/rubric/`

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `CriterionEvaluation.score` | 0.0 vs next below EPS | 0.0 accepted; negative rejected |
| `CriterionEvaluation.score` | 10.0 vs 10.05 | 10.0 accepted; >10 rejected |
| `evidence_clause_snippet` len | 500 vs 501 chars | 501 truncated or rejected per chosen policy |
| `Finding.legal_basis` | 3 vs 4 items | 4th rejected |
| Enum band | `green` / invalid string | invalid rejected at parse |

## Test intent (Rule 9)

Schemas must encode **non-negotiable product caps** (500-char evidence, three citations max) so a refactor cannot silently widen retention surface or break F8 anonymization assumptions ([[PRD_GENERAL]] retention posture via [[DOMAIN_MODEL]] §3.2).

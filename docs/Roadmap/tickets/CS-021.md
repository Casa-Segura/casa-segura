# CS-021 — Django migrations bootstrap + baseline migration framework

## Context

Schema evolution must be versioned ([[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] US-01; [[BE-SERVICES]] §2.4). This ticket establishes Django migrations in `apps/api` (or documented backend root, `DJANGO_SETTINGS_MODULE` discoverable via `manage.py`), wired to `DATABASE_URL` from [[CS-006]], ahead of per-entity migrations in [[CS-023]]–[[CS-029]].

## Scope

**In:**
- Django 5.2 LTS `INSTALLED_APPS` layout with an initial migration chain (empty/minimal revisions only if convention requires placeholders)
- Makefile/README targets: `python manage.py migrate`, `python manage.py showmigrations`; reverse flow documented (`migrate <app_label> zero` or equivalent rollback policy for disposable DBs) for alignment with CI in [[CS-035]]
- CI hook placeholder documented for [[CS-035]]

**Out (explicit):**
- Business tables — [[CS-023]] onward
- Autogenerate trust without human review — disallow blind auto-merges

## Acceptance criteria

- [x] Given empty relational database excluding Django’s baseline, when `python manage.py migrate` runs, then command exits zero and `django_migrations` records applied revisions
- [ ] Given applied migrations, when the documented rollback sequence completes on a disposable database, then schema objects created by Casa migrations revert consistent with revision definitions (Django contrib tables may persist—document expectation)
- [ ] Given README, when developer follows DB section, then commands work from a single documented working directory
- [x] Given `.env` with `DATABASE_URL`, when Django loads settings, then it resolves that URL without accidental default SQLite fallback
- [ ] Given migration file naming convention, when new revisions are added later, then template enforces descriptive slugs + numeric prefixes per team policy

## Test intent (Rule 9)

Django migrate misconfiguration (wrong URL, missing extension) blocks every schema ticket. A smoke command that upgrades an ephemeral Postgres + pgvector instance is the minimal proof the migration tool chain is real.

## Notes

- Prefer single source of truth for `DATABASE_URL` between `manage.py migrate` runtime and Django ORM from [[CS-022]].
- Coordinate `CREATE EXTENSION vector` placement: either earliest data migration touching vector fields or explicitly paired with first `legal_chunk` migration per engineering choice—document decision.

# CS-005 — Pre-commit hooks for both `apps/api` and `apps/web`

## Context

Local hooks catch formatting and lint issues before CI spend. This ticket wires a single pre-commit entry point that respects both Python and Node toolchains introduced in [[CS-002]] and [[CS-003]].

## Scope

**In:**
- `pre-commit` configuration at repo root (or documented equivalent) invoking `ruff`, `black` (if not fully covered by ruff format), `mypy` for staged Python under `apps/api`
- Hooks for ESLint + Prettier (or biome, if adopted consistently) on staged files under `apps/web`
- Optional: end-of-file-fixer, trim trailing whitespace, YAML/Markdown sanity checks
- CONTRIBUTING or README snippet: how to install hooks (`pre-commit install`)

**Out (explicit):**
- Custom policy engines beyond format/lint
- Secret scanning replacement for `.env` hygiene — covered by developer discipline + [[CS-006]]

## Acceptance criteria

- [x] Given hooks installed per docs, when a developer commits a Python file with a ruff violation, then the commit is blocked with a fixable message
- [x] Given hooks installed, when a developer commits a TS/TSX file with a deliberate Prettier drift, then the commit is blocked or auto-fixed per project policy
- [x] Given hooks installed, when only Markdown under `Projects/` changes, when the commit includes no Python/TS, then hook set completes in under 60s on a typical laptop (or skips heavy linters per config)
- [ ] Given `pre-commit run --all-files`, when executed on clean tree after [[CS-004]] baseline, then the command exits zero (or lists only intentional documented exclusions)

## Test intent (Rule 9)

Pre-commit encodes “same author voice” across the monorepo. It must fail when someone bypasses the lint rules that CI will enforce anyway, preserving review focus for behavior not style.

## Notes

- Align ruff/black/mypy versions with `pyproject.toml` pins from [[CS-002]].
- If hook runtime becomes painful, scope file filters tightly rather than disabling checks.

## Status — 2026-05-16

**Implemented:**
- `/.pre-commit-config.yaml` at repo root with explicitly pinned versions:
  - `pre-commit/pre-commit-hooks` v5.0.0 — `end-of-file-fixer`, `trailing-whitespace`, `check-merge-conflict`, `check-yaml`, `check-toml`.
  - `astral-sh/ruff-pre-commit` v0.15.13 (matches `backend/pyproject.toml` dev pin) — `ruff --fix` and `ruff-format` scoped to `^backend/.*\.py$` and excluding `**/migrations/**`. `ruff format` replaces the standalone `black` hook (ruff 0.15+ ships a black-compatible formatter and `[tool.black] line-length = 119` is already mirrored by ruff's defaults via pyproject).
  - `pre-commit/mirrors-prettier` v4.0.0-alpha.8 — `prettier --check` scoped to `^frontend/.*\.(ts|tsx|js|jsx|json|md)$`, excluding build artefacts. Runs in pre-commit's isolated node env so it does not require `frontend/node_modules` to be present.
- Root `README.md` gained a "Pre-commit hooks" section under Quick start with the 3-line install snippet.

**Deferred (with rationale, documented inline in `/.pre-commit-config.yaml`):**
- **ESLint** hook — `eslint-config-next` needs `frontend/node_modules` and Next.js' resolver, which pre-commit's isolated envs cannot provide cleanly without `language: system` + per-developer setup. Devs run `npm run lint` locally and CI enforces it.
- **mypy** hook — too slow for the pre-commit critical path; CI handles type checking.
- **Test hooks** — explicitly out of scope per ticket plan.

**Open / not yet verified:**
- The fourth AC ("`pre-commit run --all-files` exits zero on clean tree") is unverified — running it requires `pre-commit install` and a sweep that may turn up baseline drift to fix in a follow-up commit. Ticket remains `in_progress` until that sweep is run.

# CS-005 — Pre-commit hooks for both `apps/api` and `apps/web`

## Context

Local hooks catch formatting and lint issues before CI spend. This ticket wires a single pre-commit entry point that respects both Python and Node toolchains introduced in [[CS-002]] and [[CS-003]].

## Scope

**In:**
- `pre-commit` configuration at repo root (or documented equivalent) invoking `ruff`, `black` (if not fully covered by ruff format), `mypy` for staged Python under `apps/api`
- Hooks for ESLint + Prettier (or biome, if adopted consistently) on staged files under `apps/web`
- Optional: end-of-file-fixer, trim trailing whitespace, YAML/Markdown sanity checks
- CONTRIBUTING or README snippet: how to install hooks (`pre-commit install`)

**Out (explicit):**
- Custom policy engines beyond format/lint
- Secret scanning replacement for `.env` hygiene — covered by developer discipline + [[CS-006]]

## Acceptance criteria

- [ ] Given hooks installed per docs, when a developer commits a Python file with a ruff violation, then the commit is blocked with a fixable message
- [ ] Given hooks installed, when a developer commits a TS/TSX file with a deliberate Prettier drift, then the commit is blocked or auto-fixed per project policy
- [ ] Given hooks installed, when only Markdown under `Projects/` changes, when the commit includes no Python/TS, then hook set completes in under 60s on a typical laptop (or skips heavy linters per config)
- [ ] Given `pre-commit run --all-files`, when executed on clean tree after [[CS-004]] baseline, then the command exits zero (or lists only intentional documented exclusions)

## Test intent (Rule 9)

Pre-commit encodes “same author voice” across the monorepo. It must fail when someone bypasses the lint rules that CI will enforce anyway, preserving review focus for behavior not style.

## Notes

- Align ruff/black/mypy versions with `pyproject.toml` pins from [[CS-002]].
- If hook runtime becomes painful, scope file filters tightly rather than disabling checks.

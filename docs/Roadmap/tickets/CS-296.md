# CS-296 — Server Actions wiring to backend (upload + poll + delivery handoff)

## Context

The FE stack decision ([[UI-UX Documents/UI-UX]] §7) uses **Server Actions** instead of a separate upload micro-API surface. This ticket defines the typed, env-driven client to BE for: multipart upload (or signed URL flow if BE requires), disclaimer propagation, channel payload, and polling until terminal state.

## Scope

**In:**
- Server Actions module with explicit TypeScript types shared or mirrored from OpenAPI
- Env vars: `CASASEGURA_API_BASE_URL`, timeouts, feature flags
- Maps BE error codes ([[PRD_F1_INGESTA_Y_OCR]] validation list) to user-facing Spanish strings **without** echoing internal details
- Never logs raw file bytes or PII to server console

**Out (explicit):**
- Implementing BE endpoints — epics F1/F7/F8
- Auth/session system (none for MVP per [[PRD_GENERAL]] scope)

## Acceptance criteria

- [ ] Given `disclaimer_accepted=false` missing in multipart, when action called, then forwards as PRD expects and surfaces `DISCLAIMER_REQUIRED` cleanly
- [ ] Given network failure mid-upload, when catch executes, then user sees actionable retry without leaking stack traces
- [ ] Given successful submission, when polling, then client backs off (e.g., 1s→2s→5s cap) to avoid hammering BE—constants documented
- [ ] Given terminal `not_analyzable`, when mapped, then FE navigates to dedicated rejection panel with reasons list from BE JSON
- [ ] Given secrets in env, when app builds on Vercel, then keys stay server-only (`NEXT_PUBLIC_*` not used for privileged tokens)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| File part count | 1 vs 50 | Action loops parts per BE contract |
| Channel enum | three values | Serialize exact strings (`email_pdf`, etc.) |
| Timeout | under 90s SLA | Poll budget ≥90s + buffer or aligns with UX messaging |
| Error classification | 4xx vs 5xx | 4xx user-fixable; 5xx shows “intenta luego” |

## Test intent (Rule 9)

Server Actions are the **trust boundary** between browser and BE. Tests must fail if secrets leak to client bundles or if polling storms the API without backoff (cost + stability).

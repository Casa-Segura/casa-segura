# CS-020 — Provision Postgres 15+ with pgvector (local + remote)

## Context

The relational + vector store is foundational ([[BE-SERVICES]] §1; [[FEATURES_MAP]] §3 Phase 0). This ticket ensures developers and CI can rely on Postgres 15+ with `CREATE EXTENSION vector;` available, matching [[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] BR-10 and [[DOMAIN_MODEL]] embedding assumptions (384-d MiniLM).

## Scope

**In:**
- `docker-compose` (or documented equivalent) wiring for `postgres:15+` image with pgvector-enabled variant (pin digest/tag)
- One-command documented bootstrap: extension creation verified
- Staging/production equivalent notes: Supabase vs Railway per risk [[EPIC-01-persistence]] R-01-1, with explicit choice recorded in README ops snippet
- Health check script or `psql` one-liner proving `\dx` lists `vector`

**Out (explicit):**
- Alembic migrations — [[CS-021]]
- Application pool tuning at scale — explicitly deferred in [[EPIC-01-persistence]]

## Acceptance criteria

- [ ] Given `docker-compose up postgres`, when a client runs `SELECT extname FROM pg_extension WHERE extname='vector';`, then exactly one row returns
- [ ] Given fresh volume, when bootstrap runs, when `SHOW server_version;`, then major version ≥ 15
- [ ] Given [[CS-006]] env template, when remote instructions are followed, when a managed host is used, then connection string example is valid for SQLAlchemy `postgresql+psycopg` driver
- [ ] Given repo docs, when onboarding reads "Database", then limitations (free-tier pgvector) cite mitigation per [[STATUS_RECONCILIATION]]/[[EPIC-01-persistence]] guidance
- [ ] Given no application code requirement yet, when extension creation fails, then failure mode is documented (operator fixes DB image, not app patch)

## Test intent (Rule 9)

If pgvector is missing, every downstream RAG ticket silently degrades or fails late in CI. A deterministic extension check is the canary for the entire EPIC-01 chain.

## Notes

- Keep parity between local and CI images to avoid “works on laptop” drift.
- Do not store user contract bytes in this DB — privacy separation is schema-enforced in later tickets.

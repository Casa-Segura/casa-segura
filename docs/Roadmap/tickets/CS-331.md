# CS-331 — Log scrubbing pipeline (no body, no PII)

## Context

Operational logs must aid debugging without violating BR-01 and the posture in [[ARCHITECTURE]] §10: **no contract body**, extracted text, billboard transcript, prompts with user content, or **PII** in log streams ([[PRD_GENERAL]] §5 “no sensitive information in logs”).

## Scope

**In:**
- Structured logging policy documented in-repo (fields allowed vs denied)
- Redaction/filter middleware applied before emission: strips `request.body`, OCR output, PDF parse buffers, LLM payloads, webhook payloads beyond coarse metadata
- Allowlist-of-safe-fields for uploads (mime, bytes length, opaque `submission_id`/job id UUIDs — not reversible hashes of content used as identifiers in logs)
- CI or unit tests with **fixtures** that assert denied substrings never appear after scrubbing

**Out (explicit):**
- Full secret scanning of git history
- Changing application error messages shown to end users (may overlap but not required here)

## Acceptance criteria

- [ ] Given a request carrying contract bytes, when any log line is emitted on that path, then **no slice of file content** appears in stdout/file/shipper (verified by negative tests with unique canary strings in fixtures)
- [ ] Given payloads containing salient PII patterns (email, phone, street address placeholders), scrubber replaces or drops those fields deterministically while preserving correlation ids
- [ ] Given an error thrown mid-OCR/RAG/rubric, stack traces persist but attached `locals`/`contextvars` undergo the same scrub pass
- [ ] Logging policy lists **explicit deny keys** (`contract_text`, `ocr_text`, `developer_name_from_user`, raw SMS provider payloads, OpenRouter prompt bodies)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| Log field size | exactly 4 KiB benign message vs body-sized blob | blobs rejected or truncated below policy max with no contract canary leakage |
| Redaction marker | substring split across chunks | chunked pipeline still detects canary phrase (streaming-safe) |
| Correlation id | UUID without PII vs id derived from submission hash | only opaque UUID/logging id allowed in messages |
| Sampling | 100% vs sampled errors | sampled path still applies scrubber (no fast path leak) |

## Test intent (Rule 9)

The test encodes BR-01/§10: **observability must not become a persistence side-channel for contract content**; any regression that logs a clause or party name fails.

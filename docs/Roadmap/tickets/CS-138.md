# CS-138 — Wire F2 → F5 inside the orchestrator (persist the EconomicSummary envelope)

## Context

CS-130..CS-137 shipped the deterministic F5 pipeline in `backend/economics/`, but `economics.application.analyzer.analyze()` was never invoked from the production pipeline. `F2Orchestrator._persist` instead wrote a slot/status precursor dict to `ContractAnalysis.economic_summary` and left `ContractAnalysis.benchmark_version_id` NULL. Downstream consumers (EPIC-06 category B rubric, EPIC-07 reports, the `/r/{publicShortId}` surface) could not read the envelope shape that `docs/analysis/F5_analisis_economico/ECONOMIC_SUMMARY_CONTRACT.md` documents.

CS-134, CS-135 and CS-136 each deferred this final wiring to "CS-112 / EPIC-04 orchestrator", but CS-112's AC list was scoped to project-name normalization and did not cover the F5 hand-off. This ticket closes that gap.

## Scope

**In:**

- `F2Orchestrator._persist` resolves the active `BenchmarkVersion`, hydrates a `BenchmarkCatalog`, invokes `economics.application.analyzer.analyze(...)`, and persists `EconomicSummary.model_dump(mode="json")` to `ContractAnalysis.economic_summary`.
- `ContractAnalysis.benchmark_version_id` FK is set to the active version when an envelope is emitted (byte-equal with the envelope's `benchmark_version` field per CS-136).
- New configuration error path: `F2OrchestratorError(code="NO_ACTIVE_BENCHMARK")` mirroring the corpus / rubric pattern.
- `assert_freshness` (CS-136) is called on the active version so BR-12 stale signals surface in logs without blocking.
- Tests added to `tests/test_f2_orchestrator.py` validating the envelope shape, the FK echo, the NOT_CLASSIFIABLE null path, and the missing-active-benchmark error.

**Out (explicit):**

- Deriving `has_developer_direct_hint` from classifier output for APV / LEA / CVC. The CVP slice is closed by CS-139 (deterministic rule on `contract_type`); extending to the other types needs a clause-level financier signal and stays a future EPIC-04 follow-up.
- Legal verification of the seed fixture values (RUBRICA §17, still `source_status: pending_verification`).
- Prometheus gauge for catalog freshness (EPIC-11 observability).

## Acceptance criteria

- [x] `F2Orchestrator._persist` invokes `economics.application.analyzer.analyze(aggregated, catalog=..., has_developer_direct_hint=False)` with a `BenchmarkCatalog` hydrated from the active `BenchmarkVersion`. _Implemented at `backend/classification/application/orchestrator.py:413-441` (`_active_benchmark_version`, `BenchmarkCatalog.from_db`, `_build_economic_summary`)._
- [x] `ContractAnalysis.economic_summary` persists the `EconomicSummary.model_dump(mode="json")` envelope (not the slot precursor). _`test_happy_cvp_persists_contract_analysis` validates the payload through `EconomicSummary.model_validate(...)` so any contract drift fails loudly._
- [x] `ContractAnalysis.benchmark_version_id` equals the active `BenchmarkVersion.version` and is byte-equal with `economic_summary["benchmark_version"]`. _Same test asserts `analysis.benchmark_version_id == envelope.benchmark_version`._
- [x] Without an active `BenchmarkVersion`, the orchestrator raises `F2OrchestratorError(code="NO_ACTIVE_BENCHMARK")` and persists no row. _`test_missing_active_benchmark_raises_typed_error`._
- [x] `NOT_CLASSIFIABLE` keeps both `economic_summary` and `benchmark_version_id` NULL. _`test_low_confidence_returns_not_classifiable_envelope` asserts both._
- [x] `has_developer_direct_hint` is wired through `analyze()`. _CS-138 shipped with `False` hard-coded; CS-139 replaced it with the deterministic `contract_type is CVP` rule (see `_build_economic_summary` docstring)._
- [x] No new LLM calls inside the wiring (PRD_F5 BR-13). _The economics module is import-checked by `test_renormalizer_imports_no_llm_gateway`; the orchestrator only consumes existing pure-Python helpers._

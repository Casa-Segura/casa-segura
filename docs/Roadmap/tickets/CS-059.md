# CS-059 — Enforce configurable page-count caps aligned with PRD

## Context

Operational costs scale with rasterized PDF pages and vision calls. Formal PRDs cap **single-PDF pages (default 50)** and **total submission pages ≤ 80** ([[PRD_F1_INGESTA_Y_OCR]] §US-01). Older env defaults (e.g. `PDF_MAX_PAGES=30` in [[BE-SERVICES]]) are **deprecated** pending BE doc refresh.

## Scope

**In:**

- Centralize constants/env for `MAX_PAGES_PER_PDF_DEFAULT=50`, `MAX_TOTAL_PAGES=80`, with ability to tighten in prod via env overrides but **never exceed PRD-approved defaults accidentally** unless feature flag expressly documents risk (default deny).
- Per-PDF cheap page counting integrated with extractor results from [[CS-050]] / [[CS-053]] / [[CS-054]]; images count as 1 page (or `None` when the extractor can't determine the count, e.g. single-image Pixtral).
- Return `page_count_exceeded` consistently with bilingual Spanish primary messaging.
- Per-file byte cap aligned to PRD §US-01 (**15 MB** canonical default for `OCR_MAX_BYTES`; was 10 MB before this ticket).
- Total submission size cap of **100 MB** (`TOTAL_SIZE_TOO_LARGE`) covered jointly with [[CS-050]] multi-file aggregation.

**Out (explicit):**

- Billing-based dynamic limits.

## Acceptance criteria

- [x] Given a PDF with **50** pages according to extractor, submission allowed if other caps OK (`test_page_count_bva[50-…]`).
- [x] Given **51** pages, rejected before deeper processing with `page_count_exceeded` (`test_page_count_bva[51-rejected_size]`).
- [x] Given two PDFs of **41** pages each (**82 total**, each below per-file cap 50), aggregation logic rejects the batch with `page_count_exceeded` on the submission record (`test_combined_pages_over_80_rejected` in `test_ingestion_multi_file.py`).
- [x] Helm/docker env documentation lists variables and states PRD supersession of stale BE defaults (`backend/.env.example` updated to `OCR_MAX_BYTES=15728640` with a comment noting the PRD §US-01 alignment).

### BVA — boundary value analysis

| Metric | Boundary | Expected |
|---|---|---|
| Pages per PDF | 50 vs 51 | Per-file cap enforced inside `_run_batch_extraction` |
| Total pages | 80 vs 81+ | Combined cap enforced by `_enforce_total_pages` |
| Per-file size | 15 MB / 15 MB + 1 B | At cap OK; over → `file_too_large` (CS-050 envelope) |
| Total submission size | 100 MB / 100 MB + 1 B | At cap OK; over → `total_size_too_large` (CS-050 envelope) |

## Test intent (Rule 9)

These tests freeze **marketing/legal throughput promises** versus historical smaller defaults — raising limits without PRD amendment must fail review.

## Status — 2026-05-16

Closed after the EPIC-02 audit against commit `6701a8b`.

**Shipped implementation:**

- `OCR_MAX_BYTES` default bumped to **15 MB** (`15 * 1024 * 1024 = 15728640`) in `backend/config/settings.py` and `backend/.env.example`. Comment in both files cites PRD §US-01.
- Per-file `OCR_MAX_PAGES` (default 50) check inside `_run_batch_extraction` raises `PAGE_COUNT_EXCEEDED` with the offending filename in the message.
- Combined `MAX_TOTAL_PAGES=80` check in `_enforce_total_pages`; submission is marked `REJECTED_SIZE` with `error_code=page_count_exceeded` so the API client gets a structured envelope.
- Per-file byte cap rejects as `FILE_TOO_LARGE`; combined byte cap as `TOTAL_SIZE_TOO_LARGE` (both wired in [[CS-050]] `_validate_batch`).

**Tests:**

- `backend/tests/test_ingestion_upload_service.py::test_page_count_bva` — single-file BVA at 1/49/50/51 pages.
- `backend/tests/test_ingestion_multi_file.py::test_combined_pages_over_80_rejected` — two-file batch with per-file 41 pages → REJECTED_SIZE.
- `backend/tests/test_ingestion_multi_file.py::test_combined_size_over_100mb_rejected` — total size cap.
- `backend/tests/test_ingestion_multi_file.py::test_single_file_over_max_bytes_rejected` — per-file cap.

**Deferred:**

- Dedicated `submission_rejected_pages_total` Prometheus counter — observability is currently captured by `INGEST_OUTCOMES{outcome="rejected", error_code="page_count_exceeded"}`, which preserves the same operational signal without expanding the metrics surface.

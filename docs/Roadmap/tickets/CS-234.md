# CS-234 — Encode retry/backoff and dead-letter handling

## Context

Transient SMTP/SMS faults must follow bounded retries with jitter (BR-04). Permanent classification short-circuits wasted queue time ([[PRD_F7_ENTREGA_MULTICANAL]] §3 US-06).

## Scope

**In:**
- Policy module computing next attempt schedule: base delays **30s**, **5min**, **30min** between attempts with **±20% jitter** on each delay
- Integration with `attempt_count`, `max_attempts` default **3** from PRD §5.1
- Dead-letter path sets `status=failed`, `last_error_classification='transient'` vs `'permanent'`, increments metrics
- Operator manual retry hook placeholder referencing internal route §7.4 (wire later)

**Out (explicit):**
- Provider-specific error mapping ([[CS-243]])

## Acceptance criteria

- [x] Deterministic pseudorandom fixture proves jitter stays within [0.8×,1.2×] window for each delay tier
- [x] When `attempt_count` reaches `max_attempts`, no further `next_attempt_not_before` scheduled
- [x] Property test ensures sum of scheduled delays respects order 30s < 5m < 30m before jitter

### BVA — boundary value analysis

| Attempt # | Boundary | Expected |
|---|---|---|
| 1→2 | first delay mean 30s | Scheduler sets `not_before ≈ now+30s` within jitter window |
| 3rd failure | `attempt_count==max_attempts` | Immediate `failed` terminal state |
| Classification | permanent error on attempt 1 | No second delay scheduled |

## Test intent (Rule 9)

Missing jitter retries synchronized across fleet thundering herd against a provider — tests must fail if jitter removed even if average delay unchanged.

- Document interaction with rate limiter ([[CS-241]]) to avoid double-counting attempts when provider returns 429 classified transient

# CS-086 — Wire pattern_legal_link shortcut prefetch

## Context

Seeded `pattern_legal_link` tuples give deterministic article hints per fraud pattern (`fraud_pattern.code` ↔ `LegalChunk`). [[BE-SERVICES]] §4.4 step 1: prefer linked chunks via `pattern_code` ahead of brute-force vector search whenever pattern evaluation supplies a stable code ([[FEATURES_MAP]] synergy with future EPIC-06).

## Scope

**In:**

- Data access helpers loading pattern-linked chunks scoped to matching `corpus_version`, ordered descending by `relevance` field (manual float 0–1 curator seed).
- Retrieval orchestration: When `pattern_code` present, intersect linked chunk IDs with similarity threshold filtering **still applied** unless product-approved exception — default: **enforce threshold** even for linked hits to preserve cite-or-stay-silent posture (document divergence if PM mandates shortcut trust).
  - Acceptance criteria clarify final behavior (**recommend enforcing threshold**, else note legal risk).
- Graceful degrade: if shortcut yields zero surviving rows → fall back to vector path already in [[CS-085]].
- Tests using fixture rows for two patterns referencing overlapping chunk.

**Out:**

- Editing UI for curator link maintenance (still YAML/TOML migrations or SQL seed updates).

## Acceptance criteria

- [ ] Given `pattern_code=P1` linked to chunks `[C_low@0.63, C_high@0.70]` embeddings relative to mocked query cosine, **default threshold 0.65** excludes `C_low` unless configuration flag `SHORTCUT_IGNORE_THRESHOLD=true` intentionally set (must default **false** in prod config template).
- [ ] Given shortcut returns qualified chunk list, retrieval response metadata includes `{source: shortcut|vector}` internally (not necessarily user-visible) for QA logs.
- [ ] Given orphan pattern referencing missing corpus version chunk, degrade to semantic search plus WARN log referencing pattern id slug hash.
- [ ] Seeds updated alongside [[CS-033]] rubric/pattern ingestion so CI references referential integrity.

### BVA — boundary value analysis

| pattern relevance | Boundary | Ranking |
|---|---|---|
| `relevance` | 0.0 / 0.5 / 1.0 | Descending deterministic order before threshold filter |

## Test intent (Rule 9)

Guards against **shortcutting weak citations**: pattern hints must never bypass calibrated similarity safeguards without an explicit audited flag toggle.

## Status — 2026-05-16

Audit against commit `d613c2d`.

**Implemented:**

- `PatternLegalLink` model in `backend/corpus/infrastructure/django/models.py` with fields `finding_pattern`, `law_id`, `anchor`, `relevance`, `notes` + unique constraint on `(finding_pattern, law_id, anchor)`.
- Migration `corpus/0003_pattern_link_and_rag_log.py` creates the table + indexes (`idx_pattern_link_finding`, `idx_pattern_link_chunk`).
- `LegalCitationService._pattern_lookup(finding_pattern, top_k)` slugifies via `normalize_tag` (CS-082), orders by `-relevance`, dehydrates to `LegalChunk` rows scoped by the active corpus version.
- Result rows carry `source="pattern"` (AC2 satisfied — QA log discriminator).
- Tests: `tests/test_rag_retrieval.py::test_pattern_shortcut_skips_vector_search` proves vector embed isn't called when a pattern matches and the `RagQueryLog.pattern_shortcut_used=True` flag is persisted.
- Graceful degradation: if `_pattern_lookup` returns empty list, `_retrieve` falls through to `_vector_lookup` (AC3 spirit — no explicit WARN log yet).

**Partial / Missing (gap vs PRD AC):**

- AC1 (default threshold 0.65 + `SHORTCUT_IGNORE_THRESHOLD` flag): current shortcut **does not apply the vector threshold** at all — pattern hits return without similarity gate. The `relevance` column is used only for ordering, not as a similarity proxy. This is the **intentional shortcut behaviour** but contradicts the literal AC. **Action**: either add a `SHORTCUT_MIN_RELEVANCE` env (with a clear product decision: `0.0` default = shortcuts always win), or rewrite AC.
- AC3 (orphan pattern → WARN log + degrade): when a `PatternLegalLink` row references a `(law_id, anchor)` missing in the active corpus version, the lookup silently drops it. No `logger.warning` is emitted. **Action**: emit warning with the pattern id.
- AC4 (seeds wired to CS-033 rubric/pattern ingestion): no seed data exists yet — CS-033 38-criteria YAML loader is upstream. The `pattern_legal_link` table is empty in any fresh DB.
- BVA on `relevance` 0.0 / 0.5 / 1.0 ordering not exercised.

**Status:** `in_progress` — table + shortcut path land; seeds + threshold policy decision + orphan-warning are the remaining gaps.

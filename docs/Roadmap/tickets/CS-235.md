# CS-235 — Email transport abstraction (Zavu primary)

## Context

Email channel requires an isolated transport so composition ([[CS-236]]) stays provider-agnostic. **Canonical Casa Segura implementation uses Zavu’s HTTP API** (`zavudev` SDK — see `delivery/infrastructure/external/zavu_messaging.py`). Optional **SMTP** remains a pluggable adapter if deployments need non-Zavu fallback.

## Scope

**In:**
- **`EmailTransport` protocol / ABC**: `send_html_email(...)` returning provider message id string
- **Primary adapter**: **`ZavuEmailTransport`** delegating to `send_zavu_email` with attachments + idempotency key hook
- Optional (**stretch / separate PR if needed**): SMTP-backed adapter with env knobs (`SMTP_HOST`, `SMTP_PORT`, …) classifying transient vs permanent errors for [[CS-243]]

**Out (explicit):**
- Template HTML construction — [[CS-236]]
- PDF generation — EPIC-07 / [[CS-209]]

## Acceptance criteria

- [ ] Unit test mocks Zavu client proving attachments + channel=`email` path exercised
- [ ] Raised errors expose **`classification`** hint (`transient` | `permanent`) compatible with [[CS-243]]
- [ ] When `(optional)` SMTP adapter exists: socket timeout → transient; unknown recipient patterns → permanent

### BVA — boundary value analysis

| Transport | Boundary | Expected |
|---|---|---|
| Zavu | Missing API key | Immediate failure classified **permanent** (misconfiguration) |
| Zavu | 429 / 5xx from SDK | **transient** for retry policy |

## Test intent (Rule 9)

Transport leaks must not log raw `to:` addresses — only hashed audit allowed upstream.

## Notes

- Env: **`ZAVUDEV_API_KEY`** (alias **`ZAVU_API_KEY`**), **`ZAVU_SENDER_ID`** — see `backend/config/settings.py`.

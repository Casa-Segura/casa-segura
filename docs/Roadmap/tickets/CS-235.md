# CS-235 — Implement SMTP transport client

## Context

Email channel depends on transactional SMTP semantics with timeouts and TLS posture ([[PRD_F7_ENTREGA_MULTICANAL]] §6.2). Client must isolate connection setup from composition ([[CS-236]]).

## Scope

**In:**
- Config loaders for `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_TIMEOUT_SECONDS` default 30
- Connection strategy for STARTTLS (587) vs SSL (465) auto-switch based on port env convention
- API `send_message(MIMEMultipart)` returning provider message id when available
- Structured errors raising `transient` vs `permanent` hints (e.g., `550 5.1.1` → permanent)

**Out (explicit):**
- Template HTML construction
- PDF generation (F6)

## Acceptance criteria

- [ ] Contract test (or recorded VCR) demonstrates successful auth + message acceptance against provider sandbox
- [ ] When socket timeout elapses, raised error classification = `transient` for CS-234
- [ ] When RCPT TO rejected as unknown user, classification = `permanent`

### BVA — boundary value analysis

| Timeout | Boundary | Expected |
|---|---|---|
| `SMTP_TIMEOUT_SECONDS` | 29s vs 30s provider hang | At least one integration shows slow server triggers retry path |
| Attachment size | PDF just under 1 MB vs over provider limit | Over limit maps to permanent or alternative path per ops decision recorded in Notes |

## Test intent (Rule 9)

Misclassified bounce errors cause endless retries harassing dead mailboxes — classification must tie to numeric SMTP response families, not string contains fragile substrings only.

# CS-131 — Compute effective annual rate from monthly and nominal inputs

## Context

Category B scoring needs a single comparable `annual_rate_pct` in decimal form ([[RUBRICA_CONTRATO]] §5 B2). This ticket implements deterministic normalization: monthly compounding escalation `(1 + r_m)^{12} - 1`, never simple `×12`, and honors field validity windows from [[PRD_F5_ANALISIS_ECONOMICO]] US-01 (`annual_rate_pct` ∈ [0,1]).

## Scope

**In:**
- Input: validated raw wrappers from [[CS-116]] / [[CS-114]] (`annual_rate_pct`, `monthly_rate_pct`).
- Priority rules when both exist (prefer explicit annual unless flagged inconsistent — document tie-break).
- Persist derivation notes (`converted from monthly rate`) into intermediate computation dict consumed by [[CS-135]].
- Pure functions — **no LLM** ([[PRD_F5_ANALISIS_ECONOMICO]] BR-13).

**Out (explicit):**
- Benchmark comparisons ([[CS-134]]).
- French amortization installment computation ([[CS-133]]) beyond exposing rate tuple.

## Acceptance criteria

- [x] Given only `monthly_rate_pct = 0.015`, computed `annual_rate_pct = (1.015)^{12} - 1` within floating tolerance ε ≤ `1e-9` absolute or documented Decimal policy. _Shipped in `economics/application/rate_normalizer.py::_compound`. Decimal policy: float internally, `Decimal(str(value)).quantize("0.0001", ROUND_HALF_EVEN)` at serialization. Golden vector covered by `test_monthly_only_compound_conversion`._
- [x] Given annual already present at confidence ≥ cutoff, output echoes annual without recomputation unless monthly contradicts beyond stated tolerance (then mark inconsistency warning). _Tie-break documented in `_normalize_from_annual`: annual takes precedence (PRD_F2 BR-08); if monthly's compound conversion disagrees by >5%, emit `annual_rate_inconsistent_with_monthly`. Covered by `test_annual_takes_precedence_when_both_consistent` and `test_annual_inconsistent_with_monthly_emits_warning`._
- [x] Given computed or input annual `> 1` or `< 0`, field marked `invalid` with machine reason and omitted from favorable comparisons ([[PRD_F5_ANALISIS_ECONOMICO]] US-01 range validation). _Three INVALID derivation notes: `invalid_annual_out_of_range`, `invalid_monthly_out_of_range`, `invalid_compound_overflow`. Covered by BVA tests parameterized at `[-0.001, 0.0, 1.0, 1.01]`._
- [x] Determinism: identical inputs byte-equal serialized outputs across machines (avoid nondeterministic float formatting). _Banker's rounding (`ROUND_HALF_EVEN`) + Decimal quantize. Anchored by `test_determinism_byte_equal_serialization`._

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `annual_rate_pct` | 0 vs 1 vs 1.01 | 0 allowed; 1 allowed upper bound per US-01; >1 invalid |
| Monthly conversion | `r_m = 0` | Annual = 0 |
| Negative rate attempt | `-0.001` | Invalid |

## Test intent (Rule 9)

Golden vector proves **compound vs linear drift** — if developer replaces formula with `12 * monthly`, unit test must fail ([[PRD_F5_ANALISIS_ECONOMICO]] BR-05).

## Notes

- Align warnings (`annual_rate_not_expressed`) with [[PRD_F5_ANALISIS_ECONOMICO]] US-06 when neither monthly nor annual survives validation.

# CS-131 — Compute effective annual rate from monthly and nominal inputs

## Context

Category B scoring needs a single comparable `annual_rate_pct` in decimal form ([[RUBRICA_CONTRATO]] §5 B2). This ticket implements deterministic normalization: monthly compounding escalation `(1 + r_m)^{12} - 1`, never simple `×12`, and honors field validity windows from [[PRD_F5_ANALISIS_ECONOMICO]] US-01 (`annual_rate_pct` ∈ [0,1]).

## Scope

**In:**
- Input: validated raw wrappers from [[CS-116]] / [[CS-114]] (`annual_rate_pct`, `monthly_rate_pct`).
- Priority rules when both exist (prefer explicit annual unless flagged inconsistent — document tie-break).
- Persist derivation notes (`converted from monthly rate`) into intermediate computation dict consumed by [[CS-135]].
- Pure functions — **no LLM** ([[PRD_F5_ANALISIS_ECONOMICO]] BR-13).

**Out (explicit):**
- Benchmark comparisons ([[CS-134]]).
- French amortization installment computation ([[CS-133]]) beyond exposing rate tuple.

## Acceptance criteria

- [ ] Given only `monthly_rate_pct = 0.015`, computed `annual_rate_pct = (1.015)^{12} - 1` within floating tolerance ε ≤ `1e-9` absolute or documented Decimal policy.
- [ ] Given annual already present at confidence ≥ cutoff, output echoes annual without recomputation unless monthly contradicts beyond stated tolerance (then mark inconsistency warning).
- [ ] Given computed or input annual `> 1` or `< 0`, field marked `invalid` with machine reason and omitted from favorable comparisons ([[PRD_F5_ANALISIS_ECONOMICO]] US-01 range validation).
- [ ] Determinism: identical inputs byte-equal serialized outputs across machines (avoid nondeterministic float formatting).

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `annual_rate_pct` | 0 vs 1 vs 1.01 | 0 allowed; 1 allowed upper bound per US-01; >1 invalid |
| Monthly conversion | `r_m = 0` | Annual = 0 |
| Negative rate attempt | `-0.001` | Invalid |

## Test intent (Rule 9)

Golden vector proves **compound vs linear drift** — if developer replaces formula with `12 * monthly`, unit test must fail ([[PRD_F5_ANALISIS_ECONOMICO]] BR-05).

# CS-028 — Schema: EconomicBenchmark (+ BenchmarkVersion)

## Context

Economic comparisons are reproducible only with versioned benchmarks ([[DOMAIN_MODEL]] §3.8; [[PRD_GENERAL]] BR-13). PRD DDL introduces `benchmark_version` parent table—this ticket implements both `benchmark_version` and `economic_benchmark` with composite PK `(benchmark_key, benchmark_version)`.

## Scope

**In:**
- `benchmark_version` table with `is_active` partial unique index (mirror rubric/corpus pattern)
- `economic_benchmark` table with unit CHECK allowing `pct|usd|months|multiplier|ratio` per PRD DDL (note slight naming delta vs DOMAIN `usd` vs `pct`; follow PRD DDL as winning spec)
- GIN index on `applicable_contract_types`
- FK from `economic_benchmark.benchmark_version` → `benchmark_version.version`
- ORM models; `contract_analysis.benchmark_version` FK wired conceptually (actual column exists in [[CS-024]])

**Out (explicit):**
- Loading benchmark CSV/YAML values — data ops + optional future seed ticket (not CS-034 scope)
- F5 computation formulas — [[EPIC-05-economic-analysis]]

## Acceptance criteria

- [ ] Given active `benchmark_version` row, when inserting benchmark row referencing it, when contract types array includes `CVP`, then round-trip read returns JSON-friendly Python lists
- [ ] Given illegal `unit` string, when CHECK constraint present, then insert rejected
- [ ] Given duplicate `(benchmark_key, benchmark_version)`, when insert attempted, then PK constraint fails
- [ ] Given `value_min` NULL and `value_max` NULL with `value_default` set, when insert occurs, then still accepted (mirrors DOMAIN optional min/max)
- [ ] Given partial unique active index, when two actives attempted, then second fails

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `value_min` vs `value_max` | min > max | Application validation should reject; if DB lacks CHECK, add migration in [[CS-030]] after first data profile |
| Contract type arrays | includes `NOT_CLASSIFIABLE` | Allowed as string token per DOMAIN enum only if product intends—default seed should not unless PRD requires |

## Test intent (Rule 9)

Benchmark tables anchor financial fairness claims; broken units or missing FK undermine economic summaries and override logic downstream.

- Align `ratio` unit semantics with F5 before first production seed (document in PR).
- Benchmark immutability policies mirror catalog rules in PRD US-10.

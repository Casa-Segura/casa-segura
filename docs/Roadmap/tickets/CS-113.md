# CS-113 — Implement economic field extraction prompt

## Context

Deterministic economics ([[PRD_F5_ANALISIS_ECONOMICO]]) requires structured raw inputs. This ticket implements the §8.5 extraction prompt for applicable contract types and returns typed payloads matching [[CS-114]] so [[EPIC-05-economic-analysis]] can validate ranges and derive totals without LLM involvement.

## Scope

**In:**
- Conditional invocation when `contract_type ∈ {CVP, APV, LEA, FSV, ARV}` ([[PRD_F2_CLASIFICACION]] US-04).
- Spanish §8.5 system prompt instructing USD default, historical ¢8.75→USD conversion note when colones appear, monthly→effective annual derivation `(1+r)^{12}-1` ([[PRD_F2_CLASIFICACION]] BR-08).
- Structured JSON fields: `price_cash`, `down_payment`, `down_payment_pct`, `financed_amount`, `term_months`, `annual_rate_pct`, `monthly_rate_pct`, `monthly_payment`, `payment_periodicity`, `interest_calculation_base`, each with `confidence`, `evidence_snippet`, and presence/ambiguity statuses per US-04.
- Surface `interest_calculation_base = total_balance` as hint for override `art_12_lpc` ([[PRD_GENERAL]] critical overrides).

**Out (explicit):**
- Canonical validation of numeric ranges ([[CS-131]], [[PRD_F5_ANALISIS_ECONOMICO]] US-01).
- Computing amortization or benchmarks.

## Acceptance criteria

- [ ] Given `contract_type = CVP`, extraction runs exactly once per submission unless retry-on-parse policy fires, returning JSON adhering to shapes agreed with [[CS-114]].
- [ ] Given only monthly rate present, response includes both `monthly_rate_pct` and `annual_rate_pct` with `extraction_note` stating conversion via monthly compounding ([[PRD_F2_CLASIFICACION]] BR-08).
- [ ] Given clause wording mapped by §8.5 rules, `interest_calculation_base` ∈ `{outstanding_principal, total_balance, unspecified}` with supporting snippet.
- [ ] Given absent field in contract text, output marks field `null` with `extraction_status = not_present` (per US-04 semantics encoded in schema ticket).
- [ ] Given ambiguous conflicting figures for same field, field uses `extraction_status = ambiguous` and omits unreliable numeric value — **never** guesses silently ([[PRD_F2_CLASIFICACION]] US-04).

### BVA — boundary value analysis

| Field | Boundary | Expected |
|---|---|---|
| `down_payment_pct` | 0 vs 1 vs >1 raw LLM mistake | Parser flags invalid unless corrected downstream ([[PRD_F5_ANALISIS_ECONOMICO]] expects decimal 0..1 after validation) |
| `payment_periodicity` | Enum bucket monthly vs other | Stored verbatim strings per §8.5 |

## Test intent (Rule 9)

Golden tests must assert **monthly compounding conversion**, not naive ×12 annualization — regulatory truth differs ([[PRD_F5_ANALISIS_ECONOMICO]] BR-05 vs [[PRD_F2_CLASIFICACION]] BR-08 alignment).

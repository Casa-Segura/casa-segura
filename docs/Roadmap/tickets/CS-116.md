# CS-116 — Propagate unverifiable economic extraction bookkeeping

## Context

When extraction yields nulls, low confidence, or ambiguity, downstream deterministic economics must not invent figures ([[PRD_F5_ANALISIS_ECONOMICO]] BR-09). This ticket defines how `economic_fields_raw` carries explicit `unverifiable` / missing markers into the queue payload `economic_summary` precursors so [[CS-137]] and [[EPIC-06-rubric-engine]] interpret absence consistently.

## Scope

**In:**
- Aggregation helper marking each logical economic slot `{present, not_present, ambiguous, invalid}` using [[CS-114]] wrappers + [[PRD_F5_ANALISIS_ECONOMICO]] US-01 preliminary rules (`null` or `<0.5` confidence ⇒ `not_present`).
- Pass-through hints for `interest_calculation_base_unfavorable` precursors when base known but economics incomplete.
- Structured diagnostics attached for observability (counts only — no clause text persistence beyond transient pipeline).

**Out (explicit):**
- Final `derivation_status: insufficient_data` writer ([[CS-137]]).
- Rubric scoring ([[EPIC-06-rubric-engine]]).

## Acceptance criteria

- [x] Given every economic wrapper `null` or below confidence cutoff, aggregated payload exposes `fields_extracted` equivalent structure with all slots marked unavailable **without numeric zeros substituted**.
- [x] Given mixed validity (e.g., price present, rate ambiguous), helper preserves partial availability and surfaces count of ambiguous fields for metrics.
- [x] Given `interest_calculation_base.value = total_balance` with missing rate, helper still attaches warning code expectation compatible with [[PRD_F5_ANALISIS_ECONOMICO]] US-06 list (`interest_calculation_base_unfavorable` precursor).

### BVA — boundary value analysis

| Signal | Boundary | Expected |
|---|---|---|
| `confidence` | 0.49 vs 0.50 | Treated as `not_present` vs passes |
| Ambiguity flag | `ambiguous` overrides numeric | Numeric suppressed |

## Test intent (Rule 9)

Tests guard against **silent zero defaults** — changing default numeric coercion must fail ([[PRD_F5_ANALISIS_ECONOMICO]] honesty requirement §1 Problem Statement).

**Status precedence (AC1):**

1. `INVALID` — field is in `extraction.unverifiable_fields` AND value
   on `extracted_fields` is `None` (i.e. CS-113 demoted on validator
   failure).
2. `NOT_PRESENT` — value is `None`, or confidence is missing, or
   `confidence < ECONOMICS_NOT_PRESENT_CUTOFF` (0.5).
3. `PRESENT` — otherwise.
4. `AMBIGUOUS` — reserved; CS-113 does not emit an ambiguity signal
   today (TODO note in aggregator referencing a CS-113 follow-up).

**BVA comparator (`confidence` 0.49 vs 0.50):**

The decision uses `if confidence < ECONOMICS_NOT_PRESENT_CUTOFF: NOT_PRESENT`
(strict `<`, *inclusive* on the PRESENT side). `0.50` → `PRESENT`,
`0.49` → `NOT_PRESENT`. The cutoff constant lives in
`classification.domain.confidence` (CS-114) and equals `0.5` exactly,
so the comparator never re-implements the threshold. An inline comment
at the comparator references this BVA row.

**Warning precursors (AC3):**

- `interest_calculation_base_unfavorable` — fires when the
  `interest_calculation_base` slot is `PRESENT` with value
  `"total_balance"` AND any of `monthly_rate_pct` / `interest_rate_pct`
  is non-`PRESENT` (missing / ambiguous / invalid). The list is
  extensible; additional PRD F5 §6 codes can be added without changing
  the model.

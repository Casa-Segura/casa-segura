# CS-358 — BR-16 rubric catalog resolution (stamped vs active)

## Context

[[PRD_GENERAL]] BR-16 and [[ADR-0004-versioning]] require that analyses use the rubric snapshot attached to `ContractAnalysis`, not whatever catalog happens to be `is_active=True` later. F4/rubric Celery scoring must resolve **criteria** from that stamp for idempotent retries and catalog rotation safety.

## Modes (product contract)

| Mode | When | Catalog source |
|------|------|----------------|
| **Default (BR-16)** | First score, Celery retries, idempotent “same analysis” regeneration | Prefer `analysis.rubric_version_id` (semver natural key → `Criterion` rows for that version). If unset only on bootstrap paths, load **active** once; `FullAnalysisResult.rubric_version` + `persist` align the stamp with what was scored. |
| **Explicit opt-in** (not default) | Admin/support “re-grade with current rubric” | **Only** behind a dedicated API/flag and product rules for overwriting FK and JSONB outputs. Default code paths must **not** silently switch catalog. |

Implementation: `CriterionRepository.load_specs_for_analysis` + `rubric.evaluate_analysis`; structured log `rubric_catalog_source`: `stamped` \| `active_bootstrap`.

## ContractAnalysis writers (invariants)

Rows are created / rubric-owned fields updated **only** from:

- **`F2Orchestrator._persist`** — initial snapshot of active `rubric_version` (+ corpus/benchmark) on create or idempotent upsert by `submission_hash`.
- **`ContractAnalysisRepository.persist`** — fills score/band/evaluations/findings and sets `rubric_version_id` from `FullAnalysisResult.rubric_version`.

**Invariant:** FK `rubric_version` remains NOT NULL ([[CS-027]]); any row with `score_total` / `band` filled must reflect a completed `persist()` with consistent `FullAnalysisResult.rubric_version`. No DB `CHECK` added while FK semantics already enforce presence; revisit only if stubs become nullable.

## Acceptance criteria

- [x] Given `ContractAnalysis` stamped rubric **A**, active catalog **B**, resolving specs for scoring uses **A**’s criteria (not **B**’s).
- [x] Given unsaved analysis with no `rubric_version_id`, resolver falls back to active catalog and returns `active_bootstrap`.
- [x] `rubric.evaluate_analysis.completed` includes `rubric_version` and `rubric_catalog_source`.

## Report path (EPIC-07)

Report HTML/PDF content tied to criteria labels and “which rubric” must read from the analysis row and version-scoped criteria — see [[CS-208]], [[EPIC-07-report-generation]]; do not use `load_active_specs()` for analysis-bound copy.

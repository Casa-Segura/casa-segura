## Context

Persisted JSON must match [[DOMAIN_MODEL]] §5.5 while carrying richer diagnostics from [[PRD_F5_ANALISIS_ECONOMICO]] expected output (`fields_extracted`, `fields_derived`, `benchmark_comparisons`, `overcost`, `warnings`, `benchmark_version`). This ticket defines the pydantic models + assembler merging submodule outputs deterministically.

## Scope

**In:**
- Strict models mirroring persisted JSON with optional extensions documented (`currency_conversion_note`, `derivation_status`).
- Assembler orchestrating [[CS-131]]–[[CS-134]] outputs into single object validated before DB write.
- Warning objects typed (`code`, `severity_suggested`, `description`, `related_field`).
- Guarantee absence of LLM calls in assembly path.

**Out (explicit):**
- Alembic migrations.

## Acceptance criteria

- [ ] Serialized JSON validates round-trip through pydantic models without dropping unknown keys policy defined (forbid extras default).
- [ ] Assembler sets `contract_type` and `currency` fields consistently with classification output snapshot passed alongside economics pipeline inputs.
- [ ] When partial computations omitted, corresponding nested keys present `null` or empty arrays per explicit schema convention documented in module README snippet (pick `null` vs omit consistently).
- [ ] `warnings` array deduplicates by `code` + `related_field`.

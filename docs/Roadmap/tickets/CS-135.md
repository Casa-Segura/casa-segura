# CS-135 — Implement EconomicSummary pydantic model and assembler

## Context

Persisted JSON must match [[DOMAIN_MODEL]] §5.5 while carrying richer diagnostics from [[PRD_F5_ANALISIS_ECONOMICO]] expected output (`fields_extracted`, `fields_derived`, `benchmark_comparisons`, `overcost`, `warnings`, `benchmark_version`). This ticket defines the pydantic models + assembler merging submodule outputs deterministically.

## Scope

**In:**
- Strict models mirroring persisted JSON with optional extensions documented (`currency_conversion_note`, `derivation_status`).
- Assembler orchestrating [[CS-131]]–[[CS-134]] outputs into single object validated before DB write.
- Warning objects typed (`code`, `severity_suggested`, `description`, `related_field`).
- Guarantee absence of LLM calls in assembly path.

**Out (explicit):**
- Django schema migrations.

## Acceptance criteria

- [x] Serialized JSON validates round-trip through pydantic models without dropping unknown keys policy defined (forbid extras default). _`EconomicSummary` is `frozen=True, extra="forbid"`; `test_summary_roundtrips_through_json` + `test_summary_forbids_unknown_keys` cover the contract._
- [x] Assembler sets `contract_type` and `currency` fields consistently with classification output snapshot passed alongside economics pipeline inputs. _`analyze()` echoes `extraction.contract_type` and resolves currency from a `currency` slot if PRESENT (defaulting to USD per `ECONOMIC_SUMMARY_CONTRACT.md`). Covered by `test_currency_default_when_slot_absent` + the full happy path._
- [x] When partial computations omitted, corresponding nested keys present `null` or empty arrays per explicit schema convention documented in module README snippet (pick `null` vs omit consistently). _Top-level decision matches `ECONOMIC_SUMMARY_CONTRACT.md` exactly: arrays stay `()` → `[]` (never omitted), `overcost` is `None` (→ `null`), `fields_extracted` / `fields_derived` carry all-`None` field instances → `{}` (via `exclude_none=True` at serialization)._
- [x] `warnings` array deduplicates by `code` + `related_field`. _`_build_warnings` keeps a `seen` set keyed on `(code, related_field)`. `test_warning_dedup_by_code_and_related_field` pins the behavior._

# CS-337 — Central disclaimer registry plus anti-drift lint

## Context

[[PRD_GENERAL]] BR-07 mandates the literal disclaimer **“Esto no es asesoría legal”** on every surfaced channel (upload, HTML/PDF report, email, SMS). String copy drift silently breaches compliance. EPIC DoD expects a **central registry** plus **lint**.

## Scope

**In:**
- Single module exporting canonical strings: short line, header/footer paragraph variants per surface
- FE and BE import from generated or shared package path (monorepo decision documented)
- CI lint (script or eslint rule) fails on hardcoded Spanish disclaimer substring outside allowlisted files
- Extended disclaimer blocks (e.g., consult a lawyer) keyed separately but versioned together

**Out (explicit):**
- i18n for other languages (Spanish-only product today)
- Legal review workflow automation

## Acceptance criteria

- [ ] All product surfaces required by BR-07 pull disclaimer text via registry helper (no raw duplicate string in app code)
- [ ] Lint rule includes allowlist file paths (registry + tests) and fails on new duplicates in `src/`
- [ ] Snapshot test ensures HTML report header/footer contain exact canonical substring from registry version tag
- [ ] Email/SMS template builders reference same keys as F7 implementation tickets will use

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| Registry version bump | v1 → v2 string change | snapshot tests fail until templates updated intentionally |
| Partial match | “asesoría” lowercase vs Unicode variant | normalization policy rejects non-canonical Unicode tricks (document NFKC choice) |
| Feature flag | new experimental page | must import registry or lint fails |
| Short vs long template | channel requires extended text | channel selects correct key without duplicating sentence manually |

## Test intent (Rule 9)

Encodes BR-07: **visibility and immutability-by-process** of the disclaimer — any “helpful” one-off paraphrase in UI must break the build.

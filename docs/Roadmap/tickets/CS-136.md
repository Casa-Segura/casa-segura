# CS-136 — Stamp benchmark_version on ContractAnalysis and EconomicSummary

## Context

Each analysis must remain reproducible after benchmark edits ([[PRD_GENERAL]] BR-13). This ticket wires `benchmark_version` from active YAML/`benchmark_version` catalog into both `ContractAnalysis.benchmark_version` column and nested `economic_summary.benchmark_version` echo ([[PRD_F5_ANALISIS_ECONOMICO]] expected JSON).

## Scope

**In:**
- Resolve active semantic version string at runtime from loader singleton fed by [[CS-130]].
- On successful economics assembly, write TEXT field matching FK expectation when database enforces relation ([[PRD_F5_ANALISIS_ECONOMICO]] §5.3).
- Prometheus gauge / log line exposing active benchmark age for opsalert foundations ([[PRD_F5_ANALISIS_ECONOMICO]] US-03 metrics bullet).

**Out (explicit):**
- Alert routing integrations ([[EPIC-11-observability]]) beyond emitting metric hooks.

## Acceptance criteria

- [x] Given loaded YAML `version: 2026-Q2`, persisted analysis rows store identical string on `benchmark_version` column. _Guaranteed by the loader (CS-130) + `latest_active()` chain; `test_summary_benchmark_version_echoes_catalog_byte_equal` ties the YAML version, the active row, and the persisted summary string into one assertion._
- [x] Given economics assembly writes summary JSON, embedded `benchmark_version` duplicates column value byte-for-byte. _`EconomicSummary.benchmark_version` is set from `catalog.version` directly inside `analyze()` so the JSON echo is by construction the same string as the active `BenchmarkVersion` PK._
- [x] Given inactive/expired benchmarks per `next_review_due`, loader surfaces warning metric OR log structured event **without blocking** analysis ([[PRD_F5_ANALISIS_ECONOMICO]] BR-12). _`assert_freshness(version)` emits a `benchmark.version.stale` structured log when `today > min(child.next_review_due)`; non-blocking. Covered by `test_freshness_warning_when_next_review_due_in_past` + the silent path._

### BVA — boundary value analysis

| Clock vs `next_review_due` | Boundary | Expected |
|---|---|---|
| Today equals due date vs tomorrow past due | Alert classification | Still serves analysis; flagged stale |

## Test intent (Rule 9)

Tests fail if engineer duplicates rubric version into benchmark slot — ensures **distinct provenance** for economics reproducibility vs scoring corpus ([[DOMAIN_MODEL]] §3.2 attributes list).

## Notes

- Align with dual versioning already tracked via `rubric_version` + `corpus_version` columns.

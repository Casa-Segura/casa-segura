# CS-112 — Extract and normalize project name for Project linkage

## Context

Analyses aggregate under [[DOMAIN_MODEL]] `Project` via `normalized_name`. This ticket implements canonical capture from the classification payload (`project_name_canonical`), applies normalization rules from [[PRD_F2_CLASIFICACION]] US-02, resolves collisions via upsert keyed by `normalized_name`, and handles non-extraction with `unknown_<short_hash>` per BR-06 — aligning user-visible disclaimers with [[PRD_GENERAL]] US-02.

## Scope

**In:**
- Read `project_name_canonical` from classification JSON ([[PRD_F2_CLASIFICACION]] §8.1).
- Implement normalization pipeline: lowercase; NFD accent stripping; strip non-alphanumeric except hyphen and space; collapse whitespace; strip generic tokens (`proyecto`, `residencial`, `condominio`, `urbanización`, `lotificación`, `complejo`, `parque`) at **start or end**; trim.
- Match [[CS-031]] slug semantics where overlapping (reuse shared helper if introduced there).
- Upsert `Project`: on conflict `normalized_name`, bump `total_analyses`, refresh `last_analyzed`; on insert set `canonical_name`, timestamps per [[DOMAIN_MODEL]] §3.1.
- Placeholder path: if missing name or normalized length `< 3`, create **new** Project row `normalized_name = unknown_<first_8_of_submission_hash>`, `metadata.placeholder = true`, without reuse across distinct submissions ([[PRD_F2_CLASIFICACION]] BR-06).

**Out (explicit):**
- External verification of project truth ([[PRD_GENERAL]] scope).
- OCR fixes ([[EPIC-02-ingestion-ocr]]).

## Acceptance criteria

- [x] Given `project_name_canonical = "Residencial Las Palmeras"`, persisted `normalized_name` equals `las palmeras` and matches PRD examples in [[PRD_F2_CLASIFICACION]] US-02.
- [x] Given two submissions differing only by case/diacritics, both resolve to the same `project_id` after normalization ([[PRD_F2_CLASIFICACION]] BR-05).
- [x] Given unextractable name or post-strip length `< 3`, `normalized_name` matches pattern `unknown_[a-f0-9]{8}` derived from `submission_hash`, `metadata.placeholder = true`, and **distinct** submissions never share placeholder Projects ([[PRD_F2_CLASIFICACION]] BR-06).
- [x] Given successful linkage, `ContractAnalysis.project_id` FK is populated prior to publishing downstream queues ([[FEATURES_MAP]] §4 F2 mapping). _`ProjectLinker` primitives + integration tests verified in PR-4; the actual `ContractAnalysis` row write (project_id + project_name_canonical) is performed by the F2 orchestrator in PR-6 of the EPIC-04 completion plan, against the column shipped by PR-0._

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| Normalized length | 2 chars vs 3 chars post-strip | `< 3` triggers placeholder |
| Generic token | Leading `Proyecto` vs embedded mid-string | Leading stripped per rule; verify mid-token retained |
| Hash slice | submission hash shorter than 8 (hypothetical bug) | Spec defines first 8 chars — pad or error deterministically per implementation decision documented in Notes |

## Test intent (Rule 9)

Normalization must stay faithful to **slug uniqueness for aggregation**, not cosmetic prettiness — changing strip lists must break tests tied to BR-05 collision avoidance ([[PRD_F2_CLASIFICACION]] BR-05).

## Notes

- Report copy obligation lives with [[EPIC-07-report-generation]]; this ticket exposes normalized + canonical fields on analysis payload.
- Coordinate duplicate normalization logic with [[CS-031]] to avoid drift.

## Status — 2026-05-16

Flipped `backlog` → `in_progress`. Extract → normalize → linkage chain shipped; remaining work is the orchestrator wiring + tests.

**Implemented:**
- `backend/classification/domain/project_name_extraction.py` — `ProjectNameExtraction` (pydantic v2, frozen, `extra="forbid"`). `is_placeholder` is a derived field; the post-init validator overrides any caller value using `is_placeholder_normalized_name` so the flag always matches the slug shape.
- `backend/classification/domain/project_link.py` — `ProjectLinkResult` (frozen, `extra="forbid"`). Returns `project_id: uuid.UUID`, `normalized_name`, `was_created`, `was_collision`.
- `backend/classification/application/project_name_prompts.py` — Spanish system prompt distinguishing project vs. seller/developer/party/address. JSON contract `{"project_name_raw": str | null, "confidence": float}`. Three BR-07-safe synthetic anchors: clear hit, no name found, ambiguous name.
- `backend/classification/application/project_name_extractor.py` — `ProjectNameExtractor` service. Single OpenRouter call (T=0.1, `response_format=json_object`) mirroring `ContractClassifier`'s plumbing. Pipeline: LLM → parse → `normalize_project_name` → fallback to `build_placeholder(extracted_text)` when normalized is empty. Placeholder = `unknown_<first-8-hex-of-sha256(extracted_text)>`; rationale documented in module docstring (stable per submission, distinct across submissions, decoupled from `ContractSubmission.submission_hash`). Optional `placeholder_seed=` override so the orchestrator can echo the canonical `submission_hash` when wiring CS-112 into the pipeline.
- `backend/classification/application/project_linker.py` — `ProjectLinker.link_or_create_project(extraction)` wrapped in `transaction.atomic()`. **Placeholder path:** always `Project.objects.create(...)` with `metadata={"placeholder": True}`. **Real-name path:** `select_for_update().filter(normalized_name=…).first()` → on hit refresh `last_analyzed` and return `was_collision=True`; on miss INSERT with `was_created=True`. Both paths catch `IntegrityError` on the unique constraint and re-fetch the winning row, so concurrent retries cannot create duplicates.
- ACs 1–3 ticked: AC1 is satisfied by `normalize_project_name("Residencial Las Palmeras") == "las palmeras"` per `platform_core.domain.project_name` (commit `02fac1f`, ADR-0003); AC2 is satisfied because the same normalizer folds NFKD accents + lowercases, so case/diacritic variants collide on `normalized_name` and `_upsert_named` routes them to the same `project_id`; AC3 is satisfied by `build_placeholder` (`unknown_[0-9a-f]{8}` regex shape) + `_create_placeholder` always inserting + the `metadata.placeholder=True` flag.

**Partial / Missing:**

## Status — 2026-05-17 (closeout — `in_progress → done`)

PR-4 of the [EPIC-04 completion plan](../EPIC-04-classification.md) closes the linker test coverage and fixes a latent bug in the unique-conflict handler.

**Shipped:**

- `backend/classification/application/project_linker.py`: the `except IntegrityError` blocks on both `_create_placeholder` and `_upsert_named` were broadened to also catch `django.core.exceptions.ValidationError`. Rationale: `Project.save()` runs `full_clean(exclude={"first_seen"})`, so a unique conflict on `normalized_name` surfaces as `ValidationError` (model-level pre-check) under sequential retries within a single submission, OR as `IntegrityError` under true concurrent inserts where validation passed because the racing row was not visible. Catching both keeps the recovery contract intact in either isolation mode.
- `backend/tests/test_project_linker_integration.py` (9 pytest-django tests against the real DB):
    - **BR-05** (`test_case_and_diacritics_collide`, `test_collision_path_refreshes_last_analyzed`): `"Residencial Las Palmeras"` and `"RESIDENCIAL LAS PÁLMERAS"` resolve to the same `project_id`; `last_analyzed` is bumped on the collision path.
    - **BR-06** (`test_placeholders_always_distinct`, `test_placeholder_idempotent_within_submission`, `test_placeholder_marks_metadata_flag`): distinct submission seeds produce distinct placeholder rows; the same seed within a submission lifecycle returns the winner; `metadata.placeholder = True` is set so PRD_F8 US-09's recompute job can exclude these rows.
    - **CS-031 AC4** (`test_unique_constraint_race_recovers`, `test_placeholder_race_recovers_to_winner`): the SELECT-then-INSERT race is reproduced deterministically by stubbing the `select_for_update().filter().first()` lookup to miss; the recovery handler re-fetches the winner. Placeholder race returns `was_collision=False` per BR-07.
    - **Rule 9** (`test_linker_delegates_normalization`): `ProjectLinker` persists exactly the `normalized` slug the extraction carries; any future re-normalization step would diverge and break this test, protecting against drift from `platform_core.domain.project_name.normalize_project_name`.

# CS-088 — Author ≥30 curated (finding ↔ expected article) eval pairs

## Context

Empirical grounding for RAG avoids shipping arbitrary thresholds. Formal epic DoD mandates **≥30** labeled pairs spanning the **six** rubric macro-categories aligned with headings in [[PRD_GENERAL]] (A–F) or Feature mapping categories used operationally ([[FEATURES_MAP]]). STATUS reconciliation (#4) endorses widening beyond legacy 10-case discipline.

## Scope

**In:**

- Curate **30–40** succinct Spanish `finding_text` snippets mimicking eventual LLM output phrasing sans PII placeholders.
- For each snippet, annotate `expected_law_id`, `expected_anchor`, optional acceptable alternates array (≤2 extras) acknowledging multi-article findings.
- Cover **each category ≥4 examples**, ensuring at least three stress tricky overlaps (leasing vs financiero vs compraventa).
- Store canonical dataset committed under `fixtures/rag_eval_cases.json` (newline JSON acceptable) referenced by harness ([[CS-087]]) — filenames adjust to repo norms.
- Maintainer guidelines document annual review expectation but do not automate legal monitoring.

**Out:**

- Automated translation to other languages.

## Acceptance criteria

- [ ] Dataset row count **`N ≥ 30`** enforced by linter script in CI.
- [ ] Category coverage matrix CSV/Markdown export generated automatically in harness showing counts per category meets ≥4 baseline.
- [ ] Each sample includes curator initials + date metadata field `last_reviewed`.
- [ ] Dual review sign-off tracked (Git HISTORY + reviewer field) acknowledging non-lawyers must partner with reviewer tagged **GPT-5.5 senior reviewer / counsel** before merge freezes dataset v1.

|---|---|---|

Dataset tests fail if corpus team shrinks below agreed coverage — protecting statistical validity of retrieval metrics.

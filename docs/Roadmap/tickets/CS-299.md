# CS-299 — Mobile QA pass at 360px on real Android (midrange / 4G)

## Context

[[PRD_GENERAL]] §6 requires HTML reports usable on **360px** widths; [[UI-UX Documents/UI-UX]] §6 explicitly calls out **360px** entry-level Android. [[EPIC-10-frontend]] DoD requires QA on a physical device (not emulators-only).

## Scope

**In:**
- Test matrix: Chrome/Android, **360×800** (or device-native ~360 CSS px), throttled **4G** profile for one full happy-path
- Flows: [[CS-290]] → [[CS-291]] → [[CS-293]] → [[CS-294]] (stub BE or staging), plus [[CS-295]] forced via fixture response
- Capture issues: scroll traps, clipped CTAs, keyboard occlusion on destination inputs, `aria-live` noise
- Sign-off note stored in ticket / PR (screenshots OK, no contract content)

**Out (explicit):**
- Automated device farm subscription
- iOS Safari full matrix (spot-check only unless product expands)

## Acceptance criteria

- [ ] Given device QA session, when executed, then checklist covers landing, upload+channel+disclaimer, loading rotation, result viewer, expired page
- [ ] Given **360px** width, when each screen is captured, then no unintended horizontal page scroll on primary containers (tables may scroll internally per [[CS-294]])
- [ ] Given 4G throttling, when upload completes under staging SLA, when observed, then UI remains responsive (spinner animates; no ANR-class lockups attributable to FE)
- [ ] Given TalkBack enabled, when spot-checking disclaimer gate and channel fields, when traversed, then labels and errors are readable (one critical path minimum)
- [ ] Given findings, when any P0/P1 discovered, then linked follow-up tickets filed before marking this ticket done

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| Viewport | **360px** vs **390px** | 360px is hard gate; 390px issues do not downgrade 360 failures |
| Orientation | portrait only | Landscape documented “best effort” for MVP |
| Channel | `web_link` vs email | QA includes at least one non-link channel form validation path |

## Test intent (Rule 9)

Real devices expose **tap size, font scaling, and GPU** issues emulators hide—critical for the product’s actual audience. Tests must fail if QA is emulator-only or if 360px width is not in the recorded evidence.

# CS-239 — Maintain Zavu template registry in code

## Context

Outbound WhatsApp must use **Meta-approved** template names/parameters only ([[PRD_F7_ENTREGA_MULTICANAL]] §4 BR-10). Registry encodes allowable shapes preventing ad-hoc copy drift.

## Scope

**In:**
- Constant module enumerating env-driven template name (`ZAVU_TEMPLATE_NAME_REPORT_DELIVERY`) + ordered parameter schema (score, band, bullets, URL, expiry, IDS)
- Pre-send validator ensuring composer output matches component cardinality expected by dashboard configuration
- Change log requirement: altering registry bumps `TEMPLATE_REGISTRY_VERSION` metric for alerting when prod/staging configs diverge

**Out (explicit):**
- Actually editing Meta/Zavu dashboards (operator manual)

## Acceptance criteria

- [ ] Validator raises blocking error when composer supplies 4 parameters but template expects 6 — prevents silent partial sends
- [ ] Unit test documents mapping field → template component index with comments referencing Zavu dashboard screenshot hash (attach in repo `docs/assets/` optional)
- [ ] Feature flag to disable WhatsApp channel if template approval pending (returns user-visible maintenance copy)

### BVA — boundary value analysis

| Parameter | Boundary | Expected |
|---|---|---|
| Dynamic bullet text | 400 char vs 600 char | Hard fail build if > Zavu component limit discovered in staging (document exact cap when known) |
| Language code | `es` vs `es_SV` | Registry pins allowed language tag matching approval |

## Test intent (Rule 9)

Template mismatch fails hours after deploy when first user triggers — schema tests fail immediately in CI when component arity drifts.

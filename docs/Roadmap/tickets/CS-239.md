# CS-239 — Maintain SMS message registry in code

## Context

Outbound SMS must use approved transactional message text only ([[PRD_F7_ENTREGA_MULTICANAL]] §4 BR-10). Registry encodes allowable shapes preventing ad-hoc copy drift.

## Scope

**In:**
- Constant module enumerating SMS template text and interpolation fields (score, band, URL, expiry, ID)
- Pre-send validator ensuring composer output fits segment budget and includes required disclaimer shorthand
- Change log requirement: altering registry bumps `SMS_TEMPLATE_REGISTRY_VERSION` metric for alerting when prod/staging configs diverge

**Out (explicit):**
- Actually editing provider console sender/brand registration (operator manual)

## Acceptance criteria

- [x] Validator raises blocking error when composer output omits required fields or disclaimer shorthand
- [x] Unit test documents mapping field → SMS body placeholder with expected sample output
- [x] Feature flag to disable SMS channel if provider/sender registration is not ready (returns user-visible maintenance copy)

### BVA — boundary value analysis

| Parameter | Boundary | Expected |
|---|---|---|
| Message length | one segment vs segment budget+1 | Hard fail build if template exceeds configured budget |
| Locale | `es` vs `es_SV` | Registry pins Spanish copy to Casa Segura voice |

## Test intent (Rule 9)

Template mismatch fails hours after deploy when first user triggers — schema tests fail immediately in CI when required placeholders drift.

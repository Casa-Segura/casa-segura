# CS-032 — Test fixture infrastructure (factory pattern + clean reset)

## Context

Every ORM entity needs reproducible factory helpers so migrations, constraints, and future services can be tested without copy-paste inserts ([[EPIC-01-persistence]] DoD; [[DOMAIN_MODEL]] catalog). This ticket introduces pytest factories / factory_boy (or equivalent) plus DB reset strategy per test.

## Scope

**In:**
- Deterministic test DB configuration using `DATABASE_URL` pointing at disposable database (docker service from `[[CS-020]]`)
- Session-scoped connection fixture (`django_db`, transactional pytest-django) and function-scoped rollback **or** truncate cascade strategy—pick one, document tradeoff
- Factories for: `Project`, `ContractAnalysis` (minimal legal combination), `ContractSubmission`, `OcrJob`, `DeliveryRequest`, `RubricVersion`, `Criterion` (lightweight stub row), `CorpusVersion`, `LegalDocument`, `LegalChunk` (random dim-384 vector generator), `EconomicBenchmark`/`BenchmarkVersion`
- Helper to generate valid `public_short_id` matching `CS-YYYY-XXXXXX` pattern from DOMAIN

**Out (explicit):**
- Full-domain seed content — [[CS-033]]–[[CS-034]]
- Service integration tests — feature epics

## Acceptance criteria

- [ ] Given `pytest` run, when fixture setup executes, when tests finish, then subsequent test run starts from clean schema (`python manage.py migrate` baseline or transaction rollback—document which)
- [ ] Given factory for `LegalChunk`, when created, when embedding vector length inspected, then always 384 floats
- [ ] Given factory violating FK order intentionally in negative test, when developer runs example, then error message guides correct creation order
- [ ] Given retention view tests from [[CS-030]] need overdue rows, when factory helper ages `expires_at` / `created_at`, when queried, then views reflect synthetic overdue counts
- [ ] Given CI from [[CS-004]] and [[CS-035]], when database job runs, when fixtures used, then runtime stays within practical budget (<2 min) via reused container

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| Vector generator | values unnormalized | Still accepted by pgvector column; optional L2 normalize toggle documented for realism |
| `score_total` factory default | 0 vs 10 | Both satisfy DB CHECK when paired with consistent `band` |

## Test intent (Rule 9)

Without factories, engineers bypass constraints in ad-hoc SQL and miss ORM mapping bugs. Factories encode valid defaults—tests fail when schema evolution breaks them.

## Notes

- Avoid shipping factories outside `tests/` tree.
- Consider `faker` seeds for reproducibility in parallel CI.

# CS-154 — Unverifiable criteria: worst-case scores with justification

## Context

When the contract or pipeline cannot verify a criterion, the engine applies **`worst_case_when_unverifiable`** from the criterion catalog (often score **4** per [[RUBRICA_CONTRATO]] examples like B2/B5), never an optimistic default ([[PRD_F4_MOTOR_RUBRICA]] BR-03). OCR gaps, missing clauses, and F5-marked absent fields must converge on one code path ([[PRD_F4_MOTOR_RUBRICA]] BR-15).

## Scope

**In:**
- Resolver applied before aggregation: if `unverifiable=True` OR upstream `FIELD_NOT_PRESENT`, replace LLM-proposed score with catalog worst-case
- Persist justification text + reason enum (`missing_clause`, `ocr_gap`, `f5_blocked`, `timeout`, `llm_failure_after_retry`)
- Increment analysis-level `unverifiable_count` when criterion marked unverifiable ([[DOMAIN_MODEL]] §3.2)
- Double-failure path: criterion evaluation exception after retry → mark unverifiable per PRD_F4 US-01

**Out (explicit):**
- Changing global default worst-case numeric policy product-wide — requires rubric PR change
- User-visible copy in report — [[EPIC-07-report-generation]]

## Acceptance criteria

- [ ] Given `unverifiable=True` and catalog `worst_case_when_unverifiable=4.0`, aggregated score uses **4.0** even if LLM returned `score=10`
- [ ] Given B2 rate only monthly with convertible equivalent, criterion follows [[RUBRICA_CONTRATO]] B2 rule (compute EAR) — **not** unverifiable unless conversion impossible
- [ ] Given per-criterion timeout exceeded twice, evaluation row shows `unverifiable=true`, worst-case score, justification referencing timeout ([[PRD_F4_MOTOR_RUBRICA]] US-01 30s)
- [ ] Given F5 marks financing field absent for dependent economic criterion, evaluator short-circuits without LLM and applies worst-case ([[PRD_F4_MOTOR_RUBRICA]] BR-15)
- [ ] Given fixture contract, `unverifiable_count` equals count of criteria with `unverifiable=true` post-resolution

### BVA — boundary value analysis

| Catalog worst-case | Boundary | Expected |
|---|---|---|
| 4.0 vs 0.0 | explicit per criterion | resolver uses catalog value exactly |
| LLM score | 10 with unverifiable | forced to worst-case |
| justifications | empty string | validation error |
| B5 ratio inputs missing | term unknown | score **4** worst intermediate per [[RUBRICA_CONTRATO]] B5 |

## Test intent (Rule 9)

Tests encode **conservative user protection**: removing worst-case substitution must flip aggregation downward vs upward and fail golden fixtures — silent "pass" on missing data is unacceptable ([[PRD_GENERAL]] BR-04).

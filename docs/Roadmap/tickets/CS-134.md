# CS-134 — Compute benchmark comparisons and USD overcost

## Context

Reports must answer “how much more than market under same financed amount” ([[PRD_F5_ANALISIS_ECONOMICO]] US-05). This ticket combines amortization recomputation using substitution rules (rate capped toward benchmark mid when contract exceeds bank max; asymmetric preservation of favorable down payments), emits `BenchmarkComparison` rows per metric, and computes `overcost_vs_benchmark_usd` traceably.

## Scope

**In:**
- Rate assessments using delta percentage-point bands from [[PRD_F5_ANALISIS_ECONOMICO]] US-04 (<0 favorable; [0,1) within_market; stepped buckets up to `well_above_market`).
- Segment-aware benchmark selection: developer-direct contracts prefer developer ranges per BR-10; FSV inside published band skips bank substitution per BR-11.
- Secondary comparisons for down payment, term, multiplier, monthly payment where metrics exist.
- `overcost` object with narrative explanation template fields + `what_changes_would_save[]`.

**Out (explicit):**
- Named bank product comparisons ([[PRD_F5_ANALISIS_ECONOMICO]] §2).

## Acceptance criteria

- [x] Given contract annual rate above `bank_mortgage_rate_max`, recomputed amortization substitutes benchmark rate per US-05 bullet list while holding financed amount + term constant; emits positive overcost when contract total exceeds benchmark scenario total. _Shipped in `compute_overcost`: substitutes `segment_band.mid_value`, re-amortizes via `compute_theoretical_monthly_payment` (reused from CS-133), and emits `Overcost` with USD-quantized `vs_benchmark_usd` + Spanish narrative. Covered by `test_above_market_emits_overcost_with_explanation`._
- [x] Given contract rate below benchmark mid, assessment resolves `below_market_favorable` and **never** synthesizes penalties ([[PRD_F5_ANALISIS_ECONOMICO]] BR-02 asymmetric rule). _Rule 9 anchor `test_below_market_never_synthesizes_overcost` pins this contract; `assess_delta` returns `below_market_favorable` for negative deltas; `compute_overcost` short-circuits to `None` when `contract_annual_pct <= segment_band.mid_value`._
- [x] Given missing monthly payment or financed amount, overcost calculation skips with explicit `derivation_gap` entry rather than extrapolating. _Returns `None` when `contract_total_cost_paid is None` or when `compute_theoretical_monthly_payment` rejects the inputs. Covered by `test_missing_total_cost_returns_none`. The "derivation_gap" surfacing per-row is owned by CS-137's renormalizer._
- [x] Each `BenchmarkComparison` includes `benchmark_key`, `benchmark_source` string echoed from YAML `source`, aligning with [[DOMAIN_MODEL]] §5.6 exemplar. _Both fields are required in the pydantic model; the comparator copies them from the `RateBand` dataclass that CS-135 will build from the active catalog. Per `ECONOMIC_SUMMARY_CONTRACT.md` (the cross-team contract that landed alongside this work), `benchmark_source` is explicitly required even though DOMAIN_MODEL §5.6's snippet omits it._

### BVA — boundary value analysis

| Delta pp | Boundary | Assessment label |
|---|---|---|
| −0.01 vs +0 | vs zero | `below_market_favorable` vs `within_market` |
| +0.99 vs +1.0 vs +1.01 | US-04 tiers | `within_market` vs `slightly_above_market` |
| +4.99 vs +5.0 | upper severe threshold | `above_market` vs `well_above_market` |
| Overcost sign | ≤0 vs >0 | `no_overcost` tone vs magnitude recording |

## Test intent (Rule 9)

Fixtures must encode **substitution asymmetry on down payment** — lowering benchmark down payment artificially must fail tests ([[PRD_F5_ANALISIS_ECONOMICO]] US-05).

# CS-111 — Implement leasing reclassification detector (Art. 2 LAF)

## Context

Purchase contracts disguised as leasing are the highest-impact fraud pattern in the Salvadoran market per [[RUBRICA_CONTRATO]] §3. After [[CS-110]] assigns an initial type, this ticket runs the §8.4 structured detector when applicable and applies strict indicator-count rules so `contract_type`, flags, and `reclassification_reason` match [[PRD_F2_CLASIFICACION]] US-03.

## Scope

**In:**
- Conditional invocation: only when initial accepted type ∈ `{CVC, CVP, APV}` ([[PRD_F2_CLASIFICACION]] BR-02).
- Prompt §8.4 with six indicators: mandatory term; predefined purchase option; ownership retained until option; taxes/fees to “buyer”; risks to “buyer”; payments labeled as canon vs price installments.
- Parse response `leasing_indicators`, `indicators_count`, `should_reclassify`, `reclassification_severity`.
- Persistence semantics: if `indicators_count ≥ 4`, set `contract_type = LEA`, `contract_type_declared` unchanged from prior step, `contract_type_reclassified = true`, `reclassification_reason` listing verbatim evidences ([[PRD_F2_CLASIFICACION]] US-03).
- Emit structured payload for F4 warning path when `indicators_count ∈ {2, 3}` without changing final declared purchase type.

**Out (explicit):**
- Turnkey yellow findings in F4 (hints only).
- Re-running detector for types outside `{CVC, CVP, APV}`.

## Acceptance criteria

- [ ] Given `contract_type_declared ∈ {ARV, ARC, IVU, FSV, LEA}` after [[CS-110]], the leasing detector step is skipped and no `reclassification_*` fields are mutated from classification defaults.
- [ ] Given `contract_type_declared ∈ {CVC, CVP, APV}`, the §8.4 LLM call executes and returns JSON validating against the shapes in [[PRD_F2_CLASIFICACION]] US-03 expected output.
- [ ] Given exactly four indicators `detected: true`, `contract_type` becomes `LEA`, `contract_type_reclassified = true`, and `reclassification_reason` concatenates or structures the six evidences such that the report can cite them verbatim ([[PRD_GENERAL]] US-02 bullet on explicit justification).
- [ ] Given `indicators_count ∈ {2, 3}`, `contract_type` remains the purchase-related type from classification, `contract_type_reclassified = false`, and a machine-readable warning artifact (e.g. `reclassification_indicators` JSONB + severity medium/low per §8.4) is stored for [[EPIC-06-rubric-engine]].
- [ ] Given `indicators_count ∈ {0, 1}`, no warning artifact is emitted for leasing suspicion.

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `indicators_count` | 3 vs 4 | 3 → no `LEA` reclassification; 4 → `LEA` |
| `indicators_count` | 2 vs 1 | 2 → warning path; 1 → silent |
| Applicable type | `CVP` vs `ARV` | `CVP` runs detector; `ARV` skips |

## Test intent (Rule 9)

Tests must fail if the threshold shifts from **four-of-six** to three-of-five or similar without updating contracts — the numeric cutoff is the legal-product hinge ([[PRD_F2_CLASIFICACION]] BR-03).

## Notes

- Open product tension on optimal threshold listed in [[PRD_F2_CLASIFICACION]] §10 Q1 — ticket assumes PRD-approved **4 of 6** until research overrides.
- Idempotency key suffix `f2:leasing_detection` per [[PRD_F2_CLASIFICACION]] BR-11.

## Status — 2026-05-16

Status flipped `backlog → in_progress`. The Art. 2 LAF detector is wired
end-to-end at the code level; live LLM exercise + persistence path are
deferred to CS-112 / CS-115.

**Shipped (code-level, no tests):**

- `backend/classification/domain/leasing_indicators.py` — `LeasingIndicators`
  pydantic v2 model with the six PRD §8.4 booleans (`mandatory_term`,
  `predefined_purchase_option`, `ownership_retained`, `taxes_to_buyer`,
  `risks_to_buyer`, `payments_as_rent`), `total_indicators_found` computed
  property, and `is_leasing(threshold=DEFAULT_RECLASSIFICATION_THRESHOLD)`
  helper. Module-level constants `LAF_INDICATOR_COUNT = 6` and
  `DEFAULT_RECLASSIFICATION_THRESHOLD = 4` are the single source of truth
  for the BR-03 legal-product hinge.
- `backend/classification/domain/reclassification.py` —
  `LeasingReclassificationResult` (frozen, `extra="forbid"`) with
  `original_type`, `recommended_type`, `should_reclassify`, `indicators`,
  `confidence`, `reasoning` and a `model_validator` enforcing
  `should_reclassify ⇔ recommended_type != original_type` plus
  "recommended_type may only be LEA on reclassification".
- `backend/classification/application/leasing_prompts.py` — Spanish §8.4
  system prompt citing Art. 2 LAF, the six indicators, the 4-of-6
  threshold, the JSON output contract, and three BR-07-safe synthetic
  few-shot anchors (clear LEA, clear CVP, 3/6 borderline). Exports the
  applicability set `APPLICABLE_INITIAL_TYPES = {CVC, CVP, APV}`
  (PRD BR-02).
- `backend/classification/application/leasing_detector.py` —
  `LeasingReclassificationDetector` service. Skips when `initial_type ∉
  APPLICABLE_INITIAL_TYPES` (returns the canonical "keep original"
  envelope). Otherwise issues one OpenRouter call with `temperature=0.1`,
  `response_format={"type": "json_object"}`, strips fences, parses both
  flat and PRD-§8.4-nested shapes, and **owns the threshold decision
  locally** rather than trusting the LLM's `should_reclassify`. Reuses
  CS-110's `ClassificationError` (`LLM_TRANSIENT_FAILURE` /
  `LLM_PARSE_FAILED` / `EMPTY_INPUT`).

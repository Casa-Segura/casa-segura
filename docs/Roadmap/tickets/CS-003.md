# CS-003 — Next.js scaffold with Tailwind, shadcn/ui, ESLint, Prettier

## Context

The product ships a mobile-first web surface ([[ARCHITECTURE]] §4). This ticket adds the `apps/web` shell so CI, pre-commit, and future frontend work have a typed, linted baseline. The scaffold stays thin: no product flows yet ([[EPIC-10-frontend]] owns pages beyond placeholders).

## Scope

**In:**
- `apps/web` with Next.js (App Router), TypeScript, Tailwind CSS
- shadcn/ui initialized with the repo’s design tokens path documented in README or package scripts
- ESLint + Prettier configured for the web app; `npm`/`pnpm`/`yarn` lockfile policy matches monorepo choice in [[CS-001]]
- Vitest (or project-standard unit runner) with at least one passing smoke test
- One placeholder page/route that proves `next dev` and production `next build` succeed

**Out (explicit):**
- Contract upload, report UI, or Zavu integration — [[EPIC-10-frontend]]
- API integration beyond an optional env-driven base URL constant — feature epics
- Auth or user sessions — out of product scope ([[PRD_GENERAL]] §2)

## Acceptance criteria

- [x] Given a clean checkout, when `pnpm install` (or chosen package manager) runs in `apps/web`, then dependency install completes without errors
- [ ] Given dev dependencies installed, when `next dev` runs from `apps/web`, then the placeholder page returns HTTP 200
- [ ] Given CI config from [[CS-004]], when the web job runs, then `lint`, `typecheck`, `test`, and `build` complete successfully for `apps/web`
- [ ] Given the disclaimer registry from [[CS-006]] / [[CS-010]] is not yet global, when a reviewer opens the placeholder page source, then there is no contradictory copy implying legal advice (minimal neutral placeholder text only)
- [ ] Given repository conventions from [[CS-005]], when pre-commit runs on a touched web file, then ESLint/Prettier hooks apply without conflicting with API hooks

## Test intent (Rule 9)

The web scaffold is the enforcement point for “mobile-first, typed frontend” assumptions in [[ARCHITECTURE]] §4. A failing `next build` or absent test runner would let EPIC-10 land code that cannot ship; the smoke test exists to catch that class of drift early.

## Notes

- Explicitly scoped under [[EPIC-00-foundation]] per roadmap direction (Next.js bootstrap precedes feature UI epics).
- shadcn/ui version pins should follow boring-current defaults; no bespoke design system in this ticket.

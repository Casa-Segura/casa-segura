# CS-003 — Next.js scaffold with Tailwind, shadcn/ui, ESLint, Prettier

## Context

The product ships a mobile-first web surface ([[ARCHITECTURE]] §4). This ticket scopes the **`frontend/`** Next.js shell (canonical layout alongside `backend/`) so CI, pre-commit, and feature frontends share a typed, linted baseline. Product routes live here too; disclaimers honour [[PRD_GENERAL]] BR-07 via `@/legal/disclaimer` imports.

## Scope

**In:**
- `frontend/` with Next.js (App Router), TypeScript, Tailwind CSS
- shadcn/ui initialized with the repo’s design tokens path documented in README or package scripts
- ESLint + Prettier configured for the web app; `npm`/`pnpm`/`yarn` lockfile policy matches monorepo choice in [[CS-001]]
- Vitest (or project-standard unit runner) with at least one passing smoke test
- Routes that prove `next dev` and production `next build` succeed (landing + contracted flows shipped beyond the original stub)

**Out (explicit):**
- Contract upload, report UI, or SMS/email delivery integration — [[EPIC-10-frontend]]
- API integration beyond an optional env-driven base URL constant — feature epics
- Auth or user sessions — out of product scope ([[PRD_GENERAL]] §2)

## Acceptance criteria

- [x] Given a clean checkout, when `npm install` runs in `frontend/`, then dependency install completes without errors (lockfile: `frontend/package-lock.json`)
- [x] Given dev dependencies installed, when `next dev` runs from `frontend/`, then `/` returns HTTP **200** (mobile-first landing; optional routes documented in frontend README / Vercel section)
- [x] Given CI config from [[CS-004]], when the **Frontend build** workflow job runs against `frontend/`, then **`npm run lint`**, **`npm test`** (Vitest), **`tsc --noEmit`**, and **`npm run build`** complete successfully
- [x] Given [[CS-006]] / [[CS-010]] disclaimer registry expectations, pages import disclaimer copy from **`@/legal/disclaimer`** (`DisclaimerFooter`) so visible text never contradicts “not legal advice” (BR‑07 literal enforced + user-facing clarification “No somos abogados” on `/`)
- [x] Given repository conventions from [[CS-005]], frontend TypeScript/markdown/markup is covered by the shared root **Prettier** hook and ESLint/`npm run lint` stays aligned so Python hooks (`ruff`) do not collide

## Test intent (Rule 9)

The web scaffold is the enforcement point for “mobile-first, typed frontend” assumptions in [[ARCHITECTURE]] §4. A failing `next build` or absent test runner would let EPIC-10 land code that cannot ship; the smoke test exists to catch that class of drift early.

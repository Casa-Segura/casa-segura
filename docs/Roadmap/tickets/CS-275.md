# CS-275 — Implement recompute_project_metrics hourly job

## Context

`Project.avg_score`, `score_distribution`, and `total_analyses` must stay correct when recomputes fail inline or drift ([[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] US-03, US-09). Hourly `recompute_project_metrics` recomputes from `contract_analysis` aggregates, batches work, and excludes placeholder projects from **global** recompute per US-09.

## Scope

**In:**
- Selector for projects needing recompute: `last_recomputed_at IS NULL OR last_recomputed_at < last_analyzed` (per US-09)
- SQL or ORM batch updates equivalent to US-09 snippet: AVG(`score_total`), band counts, COUNT(*)
- **Includes anonymized analyses** in avg (BR-08)
- Excludes `metadata.placeholder = true` projects from whatever “global” scope means in implementation notes (US-09); still allows per-project repair if those rows exist
- Metrics: projects processed, rows scanned, failures

**Out (explicit):**
- Trigger hook on every analysis completion — F8 write path (may exist separately)
- Creating placeholder semantics — F2/F8 tickets

## Acceptance criteria

- [x] Given project P with 3 analyses scores `{7.0, 8.0, 9.0}`, when recompute runs, then `avg_score = 8.0` (numeric tolerance per DB type)
- [x] Given mix of bands in P, when recompute runs, then `score_distribution.green/yellow/red` match exact counts of rows by `band`
- [x] Given a project just anonymized (score preserved), when recompute runs, then avg still includes that row ([[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] US-07 note + BR-08)
- [x] Given `metadata.placeholder = true`, when global sweep runs, then project is excluded from **global** batch (per US-09); document how manual single-project repair works for ops
- [x] Given job is idempotent, when running twice without intervening new analyses, then second run performs zero meaningful updates (detect via `rows_updated = 0` or version column)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `last_recomputed_at` | equals `last_analyzed` | Project not selected |
| `last_recomputed_at` | less than `last_analyzed` | Selected |
| `score_total` | anonymized vs full analyses | Both counted |
| `total_analyses` | 0 analyses edge | `avg_score` NULL or documented; distribution zeros |
| Batch sizing | more than one batch needed | job completes without timeout; progress metric increases |

## Test intent (Rule 9)

Downstream trust copy (“N contratos… promedio X.X”) depends on **honest aggregates**. Tests must fail if anonymized rows are dropped from the average (violates BR-08) or placeholder projects pollute public rollups.

- **`not_analyzable` band:** `score_distribution` includes an explicit `not_analyzable` count (alongside green/yellow/red) so totals reconcile with `COUNT(*)` and PRD DDL enum coverage.

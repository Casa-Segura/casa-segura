# CS-056 — Normalize not_analyzable error envelopes and reasons

## Context

Users need actionable rejection reasons when OCR or language gates fail. [[PRD_GENERAL]] US-01 defines `not_analyzable` outcomes; [[PRD_F1_INGESTA_Y_OCR]] §US-08 mandates Spanish detection over the first **2000** chars with **`es`** and probability **> 0.85** to continue without warning — at or below 0.85 the submission continues with a low-confidence warning log; non-Spanish top language is **`rejected_language`**. BR-09 restates threshold behavior.

## Scope

**In:**

- Consolidate validation/extraction/language failures into consistent API JSON with `error.code`, `error.message`, `user_facing=true` where applicable ([[PRD_F1_INGESTA_Y_OCR]] §7.2 pattern).
- Map conditions to statuses/codes aligned with PRD normalization table ([[PRD_F1_INGESTA_Y_OCR]] §7.4): `LANGUAGE_NOT_SUPPORTED`, `TEXT_TOO_SHORT`, `EXTRACTION_FAILED`, `TIMEOUT_EXCEEDED`, plus upload codes from [[CS-050]].
- Language detection integration (`langdetect`): evaluate on **first 2000 chars** post-extraction normalization.
  - Top language **`es`** with probability **> 0.85** → continue pipeline without warning.
  - Top language **`es`** with probability **≤ 0.85** → continue pipeline with structured `ocr.language.low_confidence` warning log.
  - Non-Spanish top lang → **`rejected_language`** → HTTP **422** `LANGUAGE_NOT_SUPPORTED`.
- Update `ContractSubmission.processing_status` enums per [[DOMAIN_MODEL]] §4.1 (`failed_extraction`, `rejected_language`, `rejected_size`, etc.).
- Add `TEXT_TOO_SHORT` reason to the enum so the [[CS-053]] 500-char gate can wire into the same HTTP 422 envelope.
- Guarantee responses never echo raw extracted text publicly.

**Out (explicit):**

- Full conversational-channel copy — out of MVP; include minimal JSON codes only here.

## Acceptance criteria

- [x] Given detected language **`es`** with confidence **0.850** vs **0.851**, when evaluated, then both continue; only **0.851** proceeds without a low-confidence warning (`test_ensure_spanish_at_0_851_no_warning`, `test_ensure_spanish_at_0_850_emits_warning`).
- [x] Given top language **`en`** probability **0.90**, when evaluated, then `processing_status=rejected_language` and HTTP **422** with `LANGUAGE_NOT_SUPPORTED` per §7.4 (`test_rejected_language_returns_422_language_not_supported`).
- [x] Given OCR strategies surface a `TEXT_TOO_SHORT` reason, when persisted, then user receives HTTP **422** with `TEXT_TOO_SHORT` per failure policy (`test_text_too_short_returns_422_text_too_short`). The 500-char fallback that triggers this code lands with [[CS-053]]; the API envelope is in place.
- [x] Given any terminal failure payload, when logged at INFO, then logs exclude extracted text blobs and only contain IDs + hashed snippets (existing structlog usage; `ContractSubmission.error_reason` is truncated to 1000 chars in `_mark_failed`).

### BVA — boundary value analysis

| Rule | Boundary | Expected |
|---|---|---|
| Spanish confidence | 0.849 / 0.850 / 0.851 | Top language `es` always continues; `0.849` and `0.850` log a `low_confidence` warning, `0.851` does not. Non-Spanish top language rejects with HTTP 422 |
| Detector input length | first 2000 chars boundary | `detect_langs` only sees the first 2000 chars even for 55k-char inputs (`test_detect_language_uses_first_2000_chars_only`) |
| Min length for detection | 19 / 20 chars | Below 20 chars → `LANGUAGE_UNDETECTABLE` short-circuit (`test_detect_language_undetectable_below_min_chars`) |
| LANGUAGE_NOT_SUPPORTED | Spanish false | Non-Spanish top → 422 reject |

## Test intent (Rule 9)

Failures must reflect **Spanish-only** contract policy and calibrated confidence — tests fail if someone removes the `0.85` discipline, widens the detection window past 2000 chars, or leaks OCR text via error payloads.

## Notes

- Comparator resolution: PRD's `>0.85` threshold controls **warning severity**, not whether Spanish-top-language text can continue. At exactly 0.850 we still continue, only with a low-confidence warning.
- Coordinate language gate placement after extraction completes but **before** queuing classification (F2).
- Wikilinks: [[EPIC-02-ingestion-ocr]], [[DOMAIN_MODEL]] §6.6 `ExtractionStrategy`, [[CS-053]] (TEXT_TOO_SHORT trigger), [[STATUS_RECONCILIATION]] (RAG/OCR survival notes irrelevant but OCR fallbacks cited).

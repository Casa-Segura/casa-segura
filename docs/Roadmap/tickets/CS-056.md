# CS-056 — Normalize not_analyzable error envelopes and reasons

## Context

Users need actionable rejection reasons when OCR or language gates fail. [[PRD_GENERAL]] US-01 defines `not_analyzable` outcomes; [[PRD_F1_INGESTA_Y_OCR]] §US-08 mandates Spanish detection over the first **2000** chars with **`es`** and probability **> 0.85** to continue — else **`rejected_language`**. BR-09 restates threshold behavior.

## Scope

**In:**

- Consolidate validation/extraction/language failures into consistent API JSON with `error.code`, `error.message`, `user_facing=true` where applicable ([[PRD_F1_INGESTA_Y_OCR]] §7.2 pattern).
- Map conditions to statuses/codes aligned with PRD normalization table ([[PRD_F1_INGESTA_Y_OCR]] §7.4): `LANGUAGE_NOT_SUPPORTED`, `TEXT_TOO_SHORT`, `EXTRACTION_FAILED`, `TIMEOUT_EXCEEDED`, plus upload codes from [[CS-050]].
- Language detection integration (`langdetect` or `lingua-py`): evaluate on **first 2000 chars** post-extraction normalization.
  - Top language **`es`** with confidence **> 0.85** → continue pipeline without warning.
  - Top language **`es`** with confidence **≤ 0.85** → continue pipeline with warning log, matching [[PRD_F1_INGESTA_Y_OCR]] §US-08 bullet 3 semantics.
  - Non-Spanish top lang → **`rejected_language`** with helpful Spanish UX copy.
- Update `ContractSubmission.processing_status` enums per [[DOMAIN_MODEL]] §4.1 (`failed_extraction`, `rejected_language`, `rejected_size`, etc.).
- Guarantee responses never echo raw extracted text publicly.

**Out (explicit):**

- Full Zavu conversational copy — tracked under delivery epic; include minimal JSON codes only here.

## Acceptance criteria

- [ ] Given detected language **`es`** with confidence **0.850** vs **0.851**, when evaluated, then both continue; only **0.851** proceeds without a low-confidence warning.
- [ ] Given top language **`en`** probability **0.90**, when evaluated, then `processing_status=rejected_language` and HTTP **422** with `LANGUAGE_NOT_SUPPORTED` per §7.4.
- [ ] Given OCR strategies exhausted with **CHAR_COUNT < BR-08 minimum after all retries**, then user receives `TEXT_TOO_SHORT` / `EXTRACTION_FAILED` per failure policy documented in orchestrator (**must match PRD**) and actionable resubmission hints.
- [ ] Given any terminal failure payload, when logged at INFO, then logs exclude extracted text blobs and only contain IDs + hashed snippets.

### BVA — boundary value analysis

| Rule | Boundary | Expected |
|---|---|---|
| Spanish confidence | 0.849 / 0.850 / 0.851 | Top language `es` always continues; `0.849` and `0.850` continue with warning, `0.851` continues without warning. Non-Spanish top language rejects. |
| Detector input length | exactly 2000 chars boundary | Uses first **2000** chars slice; verifies behavior when text shorter |
| LANGUAGE_NOT_SUPPORTED | Spanish false | Non-Spanish top → reject |

## Test intent (Rule 9)

Failures must reflect **Spanish-only** contract policy and calibrated confidence — tests should fail if someone removes `0.85` discipline or leaks OCR text via error payloads.

## Notes

- Comparator resolution: PRD's `>0.85` threshold controls warning severity, not whether Spanish-top-language text can continue.
- Coordinate language gate placement after extraction completes but **before** queuing classification (F2).

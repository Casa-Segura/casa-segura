# CS-232 — Persist hashed targets and KMS-encrypted payloads with post-delivery erasure

## Context

Privacy contract requires ephemeral cleartext: encrypt while delivery outstanding, purge ciphertext after **`delivered`** while retaining salted hash only for authorised resends until anonymization kicks in ([[PRD_F7_ENTREGA_MULTICANAL]] §3 US-07/08, BR-01/BR-02).

## Scope

**In:**
- Hash pipeline `salt_global + normalization + SHA-256` matching resend verifier ([[RUBRICA_CONTRATO]] §13.4 alignment)
- KMS encrypt/decrypt façade (`encrypt_target`, `decrypt_target`) parameterized via env block §6.4
- Persistence updates to BOTH `delivery_request.target_*` columns and mirrored `contract_analysis.delivery_target_hash` when required ([[PRD_F7_ENTREGA_MULTICANAL]] §5.3)
- Transactional purge setting `target_value_encrypted=NULL` immediately after successful SMTP/SMS acknowledgement path
- Logging rules consistent with BR-15 (no raw destinations; hash excluded from INFO logs unless redacted diagnostics policy exception documented)

**Out (explicit):**
- Inbound SMS/WhatsApp capture (conversational channels are out of MVP; web upload remains primary)
- Long-term KMS rotation runbooks (defer to ops playbook ticket)

## Acceptance criteria

- [ ] Integration test verifies ciphertext non-null prior to completion and NULL afterwards while `target_hash` remains stable for deterministic resend fixture
- [ ] Attempt to log decrypted string trips defensive guard (`ValueError`/lint) in CI where practical
- [ ] Given decrypt failure (`KMS_UNAVAILABLE`), dispatcher surfaces retriable error classification without persisting plaintext fallbacks

### BVA — boundary value analysis

| Clock | Boundary | Expected |
|---|---|---|
| Delivered transition | microseconds before SMTP 250 vs ack after | ciphertext cleared only on ack success |
| TTL | ciphertext older than KMS policy failsafe | housekeeping job wipes pending encryption blobs per DOMAIN retention note (`24h`) |

## Test intent (Rule 9)

Accidentally logging ciphertext undermines KMS investment — guard tests must detect logger calls with decrypted payload variables, mirroring SOC2 expectations even if hashing math stays correct.

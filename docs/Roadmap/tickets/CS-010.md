# CS-010 — Versioning ADR (rubric, corpus, API schema)

## Context

Reproducible analyses require immutable catalog versions ([[PRD_GENERAL]] BR-16) and explicit API compatibility discipline. This ticket captures an ADR explaining how `rubric_version`, `corpus_version`, `benchmark_version`, and API `schema_version` bump and how clients discover them ([[FEATURES_MAP]] §4, [[DOMAIN_MODEL]] §3).

## Scope

**In:**
- `docs/adr/ADR-00XX-versioning.md` (or repo-standard ADR folder) with: motivation, decision, consequences, rollback guidance
- Semver rules for `schema_version` returned on `/health` and error envelopes ([[CS-008]], [[CS-009]])
- Mapping table: where versions are stored at rest (`contract_analysis` columns) vs log fields ([[CS-007]])
- Process: feature PR must bump `schema_version` when JSON response contracts change; catalog bumps require new rows per PRD immutability (pointer to [[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] / EPIC-01 seeds)

**Out (explicit):**
- Actual seed rows — [[CS-033]], [[CS-034]]
- CI enforcement automation — optional follow-up

## Acceptance criteria

- [x] Given the ADR file, when a reviewer reads it, then they can answer: (1) when to bump API `schema_version`, (2) who may publish new rubric/corpus/benchmark versions, (3) how clients log incompatible versions
- [x] Given [[CS-008]] implementation, when `/health` JSON is compared to ADR, then the `schema_version` field semantics match the documented meaning
- [x] Given [[CS-009]] error envelope, when `schema_version` appears, then ADR documents whether errors must echo request or deployment version (explicit decision recorded)
- [x] Given immutability rules in PRD F8 / DOMAIN, when ADR references them, then it states that mutating published catalogs in-place is forbidden; only new version rows are allowed
- [ ] Given onboarding README, when a subsection links ADRs, then this ADR appears in the index list

### BVA — boundary value analysis

| Input | Boundary | Expected policy in ADR |
|---|---|---|
| `schema_version` change | PATCH vs MINOR vs MAJOR | Document mapping to client breakage (additive JSON field vs renamed field) |
| Log `rubric_version` unset | health check path | Allowed `null`; analysis paths must be non-null by EPIC-06/07 completion |

## Test intent (Rule 9)

Without a written ADR, engineers will silently couple FE/BE on implicit JSON or reuse version strings for unrelated concepts. The ADR is the test oracle: future PRs that contradict it should fail review.

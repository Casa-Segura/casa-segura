# CS-024 — Schema: ContractAnalysis entity

## Context

`ContractAnalysis` stores reproducible scoring outputs and delivery state without contract text ([[DOMAIN_MODEL]] §3.2; [[PRD_GENERAL]] BR-01). This ticket implements the `contract_analysis` table, FK to `project`, version references, JSONB blobs for embedded structures, and enums for `contract_type`, `band`, and `delivery_*` fields per PRD DDL + DOMAIN boundaries.

## Scope

**In:**
- Migration + ORM for `contract_analysis` including indexes: `project_id`, `public_short_id`, `submission_hash`, partial indexes for `link_expires_at`, `anonymized_at IS NULL`, `created_at`
- CHECK constraints: `score_total` between 0 and 10 inclusive; `band` includes `green|yellow|red|not_analyzable` per PRD DDL; delivery enums per DOMAIN §6.x (lowercase values as in PRD DDL)
- FK to `rubric_version`, `corpus_version`, `benchmark_version` tables (nullable until catalog seeds exist—document insert order with [[CS-027]]–[[CS-028]])
- Fields for anonymization (`anonymized_at`), link expiry, hashed delivery target

**Out (explicit):**
- Generating `public_short_id` — F2/F6 epics
- Anonymization mutation logic — [[EPIC-09-retention-privacy]]
- PDF/HTML persistence — forbidden ([[DOMAIN_MODEL]] §9)

## Acceptance criteria

- [x] Given applied migration, when inserting analysis with `score_total=7.5` and `band='yellow'`, when DB checks constraints, then insert succeeds
- [x] Given `score_total=10.1` insert attempt, when migration constraints active, then insert fails
- [x] Given `band='not_analyzable'`, when `score_total` NULL vs numeric per domain rules, then schema matches explicit decision recorded in migration comments (if PRD allows NULL score when not analyzable—justify vs DOMAIN NOT NULL constraint; align to winning PRD vs DOMAIN—**decision required**: if conflict, follow PRD + STATUS_RECONCILIATION; document outcome in migration)
- [x] Given FK to `project_id`, when invalid UUID, then insert fails
- [x] Given JSONB columns for `scores_by_category`, `criterion_evaluations`, `findings`, when empty defaults used, when ORM loads row, then defaults match non-null expectation from DOMAIN (use `[]` not NULL where DOMAIN says NOT NULL)

### BVA — boundary value analysis

| Input | Boundary | Expected |
|---|---|---|
| `score_total` | 0.0, 10.0, 4.9, 5.0, 7.9, 8.0 | Allowed if paired with consistent `band` at application layer; DB enforces numeric range only |
| `band` | illegal token | CHECK rejects |
| `delivery_status` transitions | `pending` → `expired` | Allowed values only; transition rules enforced in services ([[PRD_F8_PERSISTENCIA_PROYECTO_RETENCION]] US-06) |

## Test intent (Rule 9)

A missing CHECK on `score_total` or `band` lets impossible states persist, corrupting aggregates and reports. Tests must prove the database rejects out-of-range scores and illegal enum tokens.

## Notes

- **Open schema decision:** DOMAIN says `score_total` NOT NULL; PRD DDL shows CHECK but allows NULL unless NOT NULL specified—verify latest PRD DDL excerpt; implement NOT NULL if product forbids NULL scores except documented `not_analyzable` path. Record decision inline in ticket Notes during implementation.
- `submission_hash` retained after anonymization per DOMAIN lifecycle.

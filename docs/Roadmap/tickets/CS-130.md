# CS-130 — Define economic_benchmarks.yaml schema and seed values

## Context

Market comparisons must be reproducible and source-attributed ([[PRD_GENERAL]] BR-13). This ticket establishes the repo-owned `economic_benchmarks.yaml` matching [[PRD_F5_ANALISIS_ECONOMICO]] §6.4 (top-level `version`, `released_at`, `next_review_due`, `benchmarks` map) while aligning keys with rubric narratives in [[RUBRICA_CONTRATO]] §14 — noting illustrative-vs-production caveat in §5 intro — and prepares loader compatibility with [[DOMAIN_MODEL]] `EconomicBenchmark`.

## Scope

**In:**
- YAML schema contract (documented + validated at load): required benchmark entries including minimum keys from [[PRD_F5_ANALISIS_ECONOMICO]] US-03 table (`standard_down_payment_bank_purchase`, mortgage min/max/mid, FSV min/max, developer_direct min/max, `credit_term_max_reasonable`, `credit_term_ivu_max`, cost multiplier trio, monthly-payment ratio trio when wired).
- Each benchmark row includes `unit`, `applicable_contract_types`, `source`, `last_updated`, `next_review_due`, optional `source_url`, `notes`.
- Semantic version tag like `2026-Q2` per examples across [[PRD_F5_ANALISIS_ECONOMICO]] §6.4 and §6.2 `benchmark_version` table expectations.
- Startup validation: malformed YAML ⇒ fatal error with actionable message ([[PRD_F5_ANALISIS_ECONOMICO]] US-03).

**Out (explicit):**
- Legal verification that each numeric equals live regulatory feeds ([[RUBRICA_CONTRATO]] §17 open decision — marks seed as provisional until ABANSA/BCR sign-off).
- Runtime reload plumbing ([[PRD_F5_ANALISIS_ECONOMICO]] §6.3 `BENCHMARK_RELOAD_ON_SIGHUP`) — optional stub acceptable if ticket split later.

## Acceptance criteria

- [x] Repository file exists at configurable path defaulting per [[PRD_F5_ANALISIS_ECONOMICO]] §6.3 `BENCHMARK_FILE_PATH` with `version`, `released_at`, `next_review_due`, and populated `benchmarks` map covering all **Required benchmarks (minimum list)** rows in [[PRD_F5_ANALISIS_ECONOMICO]] US-03 (source gaps must be written as `source_status: pending_verification` in `notes`; prefer numeric seeds from §6.4 exemplar where present). _Shipped at `backend/fixtures/economic_benchmarks_2026q2.yaml` (18 rows). Test `test_load_yaml_parses_production_fixture` asserts the US-03 minimum-list keys are present._
- [x] Loader rejects: missing required fields, unknown `unit`, empty `applicable_contract_types`, or `next_review_due` before `last_updated`. _Shipped in `backend/economics/application/benchmark_loader.py::_validate_entry`; covered by 6 negative tests (`test_load_yaml_rejects_*`)._
- [x] `bank_mortgage_rate_mid` documents derivation rule ("Average of min and max") inline in YAML `notes` matching US-03. _See `economic_benchmarks_2026q2.yaml` `bank_mortgage_rate_mid.notes`._
- [x] Cost multiplier keys align rubric naming: `cost_multiplier_healthy_max`, `cost_multiplier_high_max`, `cost_multiplier_excessive_min` with values consistent with [[RUBRICA_CONTRATO]] §14 `total_cost_multiplier` block (`healthy_max` 1.5, `high_max` 2.0, `excessive_min` 2.5) — if [[RUBRICA_CONTRATO]] §5 B4 scale (1.8 band) diverges, document explicit mapping decision in Notes for product sign-off. _Three keys seeded with the F5 §6.4 values. The 1.8 mid-band stays an open product question owned by EPIC-06 B4 evaluator wiring (see Notes below); F5 overcost math (CS-134) only consumes healthy_max / excessive_min._
